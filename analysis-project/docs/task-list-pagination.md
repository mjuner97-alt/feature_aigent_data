# 任务列表分页与按需详情

长任务配置、报告流程配置、独立定时任务和执行中心已改为后端分页，默认 20 条，最大 100 条。新接口返回 `{items,page,pageSize,total}`，详情接口保持原样。

## 部署

1. `src/main/resources/db/migration/gauss/V20261017.1__report_process_list_node_count.sql`：新增并回填报告流程节点数。此脚本是新版报告流程列表及保存接口的必需前置条件。节点 JSON 需为历史服务保存的合法数组，非法旧数据会显式报错，不能跳过回填后把真实节点数当作零。

## 查询变化

- `/api/skill-flows/page`：服务端过滤和分页，只返回基础字段、节点数、去重后的有效依赖指标数及当前用户执行权限。当前页所有节点/指标只做一次标量批量查询，不读取节点提问、参数或大纲。
- `/api/report-processes/page`：只返回基础字段和持久化的 `node_count`。创建、修改和复制同时维护该值，不需要每次列表查询解析整个节点 JSON。
- `/api/skill-jobs/page`、`/api/skill-jobs/executions/page`：服务端过滤和分页，创建人姓名按当前页批量补齐；错误正文按点击读取。
- `/api/skill-flow-executions`：长任务和报告执行记录共用轻量列清单，移除原始提问、提问模板及摘要正文。先取当前页 ID，再批量聚合节点进度和执行尝试耗时；保留节点尚未创建时按流程定义统计数量的逻辑。
- 查询排序增加 ID 作为相同时间的稳定排序依据。过滤条件同时用于数据与总数查询。

配置列表不再获取所有记录后由浏览器 `slice` 分页；报告查看、编辑、复制操作先读取所选对象完整详情。任务页面只加载当前标签页，后台执行轮询只在对应标签页开启；流程编辑页不再为了前端重名提示预取所有流程详情，名称唯一性继续由服务端校验。

旧列表接口为已有选择器/集成保留兼容，管理页面使用新分页接口。正文、脚本参数、大纲仍由原详情接口提供。
