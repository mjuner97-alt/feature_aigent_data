# 统一样式裸片段（非围栏/非完整文档）无壳无皮肤修复方案

日期: 2026-11-13
状态: 已实施（2026-11-13，ScriptHtmlSanitizerTest 15 测试全过，全量回归待确认；内网 E2E 待验）
前作: `docs/202611/脚本表格样式上移hooks层统一方案.md`（§10 v3 / §11 v3.1）、
`docs/202611/统一样式#report重写双重前缀bug修复方案.md`

## 1. 现象（内网 2026-11-13 17:26，wenshu_chadui_all 第二次验证）

修复双重前缀后，同一脚本输出的 stdout 形态变了——表格不再走完整文档，
而是**裸片段**直出：

```
{"metricsChadui":["chadui"],"version_plan":["2026年12月份版本"]}
<style>
.guize { color:#999; ... }
.desc { font-weight:bold; ... }
</style>
<div class="desc"></div><div class="guize">插队统计规则：…</div>
<table class='dataframe table table-bordered table-striped'>…</table>
<!DOCTYPE html>…（插队明细下载.xlsx 链接文档）…
```

结果：表格无红头/白底/斑马纹（无皮肤），`.guize`/`.desc` 的 `<style>` 原样
透出（未作用域重写），表格也没有 unified-table 壳。

## 2. 根因：v3 净化只覆盖两条 HTML 路径，裸片段完全绕过

`ScriptHtmlSanitizer.sanitize = sanitizeBareDoc(sanitizeFences(stdout))`，
两个入口各有严格的前置条件：

| 路径 | 触发条件 | 本例 |
|---|---|---|
| `sanitizeFences` | ```html 围栏块 | stdout 无任何围栏 → 不触发 |
| `sanitizeBareDoc` | `<!DOCTYPE html>…</html>` 完整文档 | 表格区在文档**外**（唯一的 doc 是尾部下载链接文档，无表格）→ 不触发 |

脚本输出形态是三类而 v3 只治理两类：**围栏块 / 完整文档 / 裸片段**。
裸片段（json 信封 + `<style>` + div + 裸 `pandas.to_html` 表 + 尾部下载 doc）
在 chat 与长任务两个宿主都原样透出——包壳、皮肤、作用域重写全部缺席。

> 附注: 该脚本两次输出形态不同（前次完整文档、本次裸片段），说明脚本侧
> 输出形态不可依赖，sanitizer 必须把第三类也收进来才鲁棒。

## 3. 方案：新增裸片段 pass（sanitizeBareFragments）

执行序变为三段（前两段不动，全部幂等）：

```java
sanitizeFences(stdout)      // ```html 围栏块
sanitizeBareDoc(...)        // 第一个 <!DOCTYPE 完整文档
sanitizeBareFragments(...)  // 【新增】裸片段
```

### 3.1 裸片段区域界定

- **起点**: 文本中 `(?i)<(style|table|div)\b` 的首个匹配；
- **终点**: 其后第一个 ` ``` ` 围栏标记或 `(?i)<!doctype`（二者取先到者），
  无则到文本末尾；
- **处理门槛**: 区域内必须含 `<table`，否则整段原样返回——
  只有 `.guize`/`.desc` 这类无表片段不动（样式继续全局生效，个性化无损）；
- 区域可有多段，逐段扫描处理。

### 3.2 区域内处理（与围栏路径完全同一套变换，幂等）

```
stripScripts → scopeCss → ensureSkin(片段模式) → wrapFragment
```

- `scopeCss`: `.guize` → `.unified-table .guize`——区域被整体包壳后
  `.guize` div 落在壳内，选择器照常命中，**个性化不丢**；
- `ensureSkin`: 区域含表且无红头标记 → 注入 BASE_TABLE_CSS
  （pandas `table table-bordered table-striped` 只是 class 名、无自带 CSS → 走兜底）；
- `wrapFragment`: `id="report"` 归一 + 整个区域包
  `<div class="unified-table"><div class="table-wrap">` 壳（与围栏路径同款，
  检测 `class="unified-table"` 防双层壳）。

### 3.3 下载链接文档不受影响

尾部 `<!DOCTYPE html>`（仅含 `<a>` 下载链接，无表格）不满足区域起点
（无 style/table/div），且被终点规则排除在表格区域之外——保持原样
（对齐既有拍板：下载块不经过净化）。

### 3.4 与既有两路径的互操作（幂等性论证）

- 围栏内容已被包壳 → 裸片段 pass 的区域若扫到围栏内部，`wrapFragment`
  检测到 `class="unified-table"` 跳过包壳，`scopeCss` 对已 scope 选择器
  原样返回 → 输出不变；
- 完整文档区域: doc pass 已包壳（body 内容）→ 同上跳过；若文档无 body
  未包壳，裸片段 pass 兜底包壳（顺势修复该死角）；
- 区域终点用 ` ``` `/`<!doctype` 截断，保证不会把围栏标记/后续文档裹进壳内。

## 5. 影响面

- **只改** `ScriptHtmlSanitizer`（+1 私有方法/2 个 pattern）+ 测试；
  ScriptExecTool 接线点、HtmlReportRenderer（继续一行不动）、前端、脚本零改动；
- chat 与长任务同时受益（同一 choke point）；
