# 产品线 × 统计组下钻展开方案

> 2026/11/18 立项。需求：**产品线有具体值 + 统计组下钻维度（dimension=[统计组] / drillDown=[组维度]）同时出现**时，
> 不再把 productLine/dimension 原样传给脚本，而是查人员台账展开该「部门 × 产品线」下所有统计组，
> 以 `group`（groupName 维度参数）清单形式下发，并清空 productLine 与粒度参数。
>
> **拍板结果（2026/11/18，同日两次修订后定稿）：快照过滤加 / 多部门·多产品线·无部门全部支持（Q9 IN 并集）/ fail-open / 开关默认 false / 追问轮走方案 A。**
> **实施状态（2026/11/19）：已实施——Q9 + expandProductLineToGroups（4 处调用点）+ 开关装配 + 12 个新单测全绿，待本机 E2E 与内网验证后开生产开关。**

## 2. 现状机制盘点（为什么今天 dimension=[统计组] 能活着传出去）

| 机制 | 位置 | 与本需求的关系 |
|---|---|---|
| 下钻粒度冲突消解 `stripGranularityConflicts` | `DirectSkillExecutor.java:1513` | 规则2/3：productLine（`DRILL_CONFLICT_FINE_DIMS` 成员）有值 → 应删粒度参数；**但 D1 豁免：本轮 extraction 显式重提粒度键（「各组」命中 dimension 词表）→ 保留**。这就是 trace 里 productLine 与 dimension 并存的原因 |
| 「分布」默认下钻 `applyDistributionDrillDown` | `DirectSkillExecutor.java:1619` | 仅问句含「分布」才补默认粒度值；本需求问句不含「分布」，不参与。**但存在组合场景**（见 §5.4） |
| 台账仓储 `PersonLedgerRepository` | `v2/dimension/PersonLedgerRepository.java` | 已有 Q1~Q8 五类查询，全部走 `SNAPSHOT_FILTER`（max 统计月份）+ TTL 缓存 + 失败降级不抛错。本需求新增 Q9 沿用同一套范式 |
| 管线调用顺序 | 三处：multi-exec `:805-806`、单 plan `:1007-1009`、追问层 `:1239-1241` | 统一为 `buildParams → (快照合并) → strip → 分布下钻 → (缺参判定)`。新展开步骤插在**分布下钻之后**（理由见 §4.3） |
| 词表收敛保证 | `dimension_family_config` seed（`:39` `组维度→groupName`、`:52` `统计组→groupName`） | 粒度词命中后收敛为标准形态词，**trigger 只需匹配两个字面值**，不需要再查家族映射 |

## 3. 方案总览

```
问句「杭州五部普惠金融下各组的缺陷密度」
  └─ buildParams: productLine=[普惠金融], dimension=[统计组]
  └─ stripGranularityConflicts: D1 豁免 → dimension 保留（现状，不动）
  └─ applyDistributionDrillDown: 无「分布」→ 不动
  └─ expandProductLineToGroups (★新增, 本方案):
       trigger: dimension 值=统计组(或 drillDown 值=组维度)
                + productLine ≥1 值 + deptName 任意(0/1/多) + group 参数当前无值
       查台账 Q9 → 10 个统计组
       转换: 删 dimension/productLine 参数键, group=shapeValue(组清单)
  └─ 缺参判定 / 执行
```

## 4. 详细设计

### 4.1 台账查询 Q9（PersonLedgerRepository）

新增方法，完全复用 Q8 `deptsByDimension` 的范式（列白名单 + SNAPSHOT_FILTER + per-key TTL 缓存 + 失败负缓存）：

```java
/** Q9 部门×产品线 → 统计组全集 (2026/11/18 产品线下钻展开方案 §4.1):
 *  产品线有值 + 统计组粒度词同时出现时, DirectSkillExecutor 按此展开 group 清单。
 *  快照口径同 Q1-Q8 (max 统计月份); 固定排除 '离场'; 失败/查无 → 空列表
 *  (调用方保留原参数 fail-open, 负缓存防反复打库)。 */
public List<String> groupsByDeptAndProductLine(List<String> depts, List<String> productLines)
```

SQL（中文列名双引号，参数全 PreparedStatement 绑定；**部门过滤可选 + 部门/产品线均支持多值 IN**，拍板见 §5-②）：

```sql
-- 变体 1：部门有值（单值或多值）
SELECT DISTINCT "统计组" FROM developer_pl_person_info_t
WHERE "部门" IN (?, ...) AND "产品线" IN (?, ...)
  AND "统计组" IS NOT NULL AND "统计组" != '离场'
  AND "统计月份" = (SELECT MAX("统计月份") FROM developer_pl_person_info_t)

-- 变体 2：部门缺席（本轮未提部门且反填未注入）
SELECT DISTINCT "统计组" FROM developer_pl_person_info_t
WHERE "产品线" IN (?, ...)
  AND "统计组" IS NOT NULL AND "统计组" != '离场'
  AND "统计月份" = (SELECT MAX("统计月份") FROM developer_pl_person_info_t)
```

- `部门 IN (...) AND 产品线 IN (...)` 与「逐 (部门×产品线) 组合查询后并集」集合语义等价
  （不存在的组合在台账中自然无行），单条 SQL 即可，不必循环查询。
- 实现为单方法双常量（`Q9_WITH_DEPT` / `Q9_NO_DEPT`），`depts` 为空集合时走变体 2；
  IN 占位符按值个数动态拼接，值全部 PreparedStatement 绑定，不拼字符串。
- 缓存 key：排序后 `String.join("|", depts) + ":" + String.join("|", productLines)`，
  部门为空时前缀固定 `*:`；复用 `groupDeptCache` 同款 `CachedDepts` 结构与 TTL（默认 30min）。
- 失败：`log.warn` + 空列表负缓存（同 Q8），调用方保留原参数。
- **拍板 ①（2026/11/18 已定：加）**：需求 SQL 未写快照过滤。`SNAPSHOT_FILTER` 即台账快照口径
  `"统计月份" = (SELECT MAX("统计月份") FROM developer_pl_person_info_t)`（只取最新月份人员快照），
  本方案默认**加**，与 Q1-Q8 台账口径一致，避免历史月份脏值混入。

### 4.2 展开变换（DirectSkillExecutor）

新增私有方法，签名对齐 `applyDistributionDrillDown`：

```java
/** 产品线×统计组下钻展开 (2026-11-18 方案 §4.2): 产品线有具体值且粒度参数值为
 *  组级形态词 (dimension=统计组 / drillDown=组维度) 时, 查台账 Q9 把该
 *  部门×产品线下全部统计组展开进 group 参数, 并移除粒度参数与 productLine 参数。
 *  调用位置必须在 applyDistributionDrillDown 之后 (§4.3); 任何前置条件不满足 /
 *  台账失败 / 查无 → 原参数返回 (宁漏勿错, fail-open)。 */
private Map<String, Object> expandProductLineToGroups(Map<String, Object> params,
        Map<String, String> mapping, List<ParamSpec> schema,
        DimensionExtraction extraction, String question)
```

**触发条件（全部满足才转换）：**

1. 开关 `productLineGroupExpandEnabled` = true（§4.4）。
2. mapping 中存在粒度参数（dim ∈ {drillDown, dimension}）且其值（`valueList` 展开）包含组级形态词：
   - dimension 键：值 = `统计组`
   - drillDown 键：值 = `组维度`
   - 词表收敛（dimension_family_config seed）保证命中值已是标准形态，无需查家族映射。
3. productLine 维度在合并视图（params + extraction）上**≥1 个值**；deptName 维度**任意**（0/1/多值均可，
   2026/11/18 拍板 ② 修订：多部门/多产品线也展开，Q9 用 IN 过滤取并集）。
   与 Q8 部门反填的交互：deptName 参数必输时反填可能注入部门 —— 注入 0 值 → 变体 2；
   注入 1/多值 → 变体 1；反填未注入（查无/失败/非必输）→ 变体 2。
   deptName 必输且缺席时：**跳过展开**（补参轮 consumePending 补齐部门后重算覆盖 group，
   实施修订 2026/11/19：补参轮只填缺失键不重走全管线，须在 consumePending 补参完成处
   显式追加一次展开调用），缺参判定照常反问补部门。
4. mapping 中存在 dim=groupName 的参数（如 `group`），且该参数当前无值 ——
   用户显式点名了统计组时不覆盖（拍板点 ③：`普惠金融 + 信贷核心组` 并提属合法组合，脚本自身支持双过滤）。
5. schema 声明了该 group 参数（同 `applyDistributionDrillDown:1639-1641` 的 schema 白名单守卫，防死参数）。
6. 台账 Q9 返回非空。

**转换动作：**

```java
Map<String, Object> out = new LinkedHashMap<>(params);
// 移除全部粒度参数键 (drillDown + dimension 两个键都清, 防双键残留)
for (mapping 中 dim==drillDown/dimension 的键) out.remove(key);
// 移除 productLine 参数键
for (mapping 中 dim==productLine 的键) out.remove(key);
// group 清单, params_schema 保形 (array→List, 同 buildParams shapeValue 口径)
out.put(groupParam, shapeValue(groupParam, schema, groups));
log.info("DirectSkillExecutor: 产品线下钻展开 group={} 个 (dept={}, productLine={})", ...);
```

- 「productLine 应为空」落地为**移除参数键**（与 `stripGranularityConflicts` 删键口径一致），脚本侧走缺省分支；不传空数组（避免脚本把 `[]` 当成「无产品线人员」的歧义）。

### 4.3 调用位置：三处，均在 `applyDistributionDrillDown` 之后

| 路径 | 现有顺序 | 插入点 |
|---|---|---|
| multi-exec `planAll` | `:805 strip` → `:806 分布下钻` | `:806` 之后 |
| 单 skill plan() | `:1007 strip` → `:1009 分布下钻` | `:1009` 之后 |
| 追问层 planFollowupDirect | `:1239 strip` → `:1241 分布下钻` | `:1241` 之后 |
| 补参轮 consumePending（实施追加） | 补参完成分支 | 填齐缺失键后、返回执行计划前（required 传 null） |

**必须在分布下钻之后的原因（组合语义）：**

- 问句「杭州五部普惠金融**各组**分布」：strip 后 dimension=[统计组]（D1 豁免存活）→ 分布下钻见粒度参数有值跳过 → 展开 → group 清单，粒度停在组级。✔
- 若展开在分布下钻**之前**：展开删掉粒度参数后，分布下钻会以「链上最深有值=groupName」补默认 `人员` 维度 → 组级+人级双重下钻，语义错误。✘
- 问句「杭州五部普惠金融缺陷**分布**」（无「各组」）：分布下钻按 `DRILL_DEFAULT_BY_DIMENSION[productLine]=人员` 补粒度 → 非组级词 → 展开不触发，维持 10/09 拍板现状。✔

时间锚点歧义反问路径（`:1223 preParams`）不插入：pending 参数在补参轮会重新走 merged 全管线，展开届时再触发，避免反问文案与展开后的参数不一致。

## 6. 追问轮交互（已知风险与对策）

追问层 `mergeSnapshotParams(:1050)` 在 `inheritKeys=null` 时**全量继承**上轮 params（细粒度 group 也在内）。

风险场景：

```
R1: 杭州五部普惠金融下各组的缺陷密度   → group=[普惠金融10组], productLine 已删
R2: 那房贷的呢                          → extraction.productLine=[房贷]
    buildParams: productLine=[房贷]; group 继承 R1 的 10 组 (普惠金融的!) → 脏组合
    且 R2 无粒度词 → 展开不触发 → 脏参数直出
```

**方案 A（已拍板，2026/11/18）**：展开触发条件增加次级分支 —— 本轮 extraction 重提 productLine 且 group 参数值来自快照继承（本轮 extraction 未提 groupName）且无本轮组级词时，**同样执行展开并覆盖 group**。即「产品线重提 = 重算组清单」，与 R1 语义对齐（R2 展开为房贷的组）。

方案 B（保守，不处理，E2E 观察）已否决：R1 命中展开是本需求的常规路径，R2 必然高频，实现成本约 10 行（复用同一方法，trigger 加一条 OR 分支），不值得留脏组合风险。

## 7. 测试计划

### 7.1 单测（DirectSkillExecutorTest + PersonLedgerRepositoryTest）

1. **Q9 SQL/缓存**：正常返回去重清单；失败→空列表+负缓存；TTL 内二次调用不打库。
2. **主案例**：trace 1 形态 → group 展开且 productLine/dimension 键删除。
3. drillDown 形态（`drillDown=[组维度]`）同样触发。
4. 无组级词 → 原参数。
5. 台账查无/失败 → 原参数（fail-open）。
6. group 显式有值 → 不覆盖。
7. 双部门 / 双产品线 → IN 并集展开（组清单为组合并集去重）。
8. 开关关 → 不触发。
9. 「各组分布」组合 → 只组级展开、无人员维度追加。
10. 追问轮：R1 展开后 R2 重提产品线 → 重算覆盖（方案 A）。
11. **无部门**：仅产品线+组级词 → 变体 2 全量展开；Q8 反填注入部门 → 变体 1；deptName 必输且缺席 → 展开后仍走缺参反问，补参轮重算覆盖。
12. Q9 缓存 key：多值排序拼接、部门空哨兵 `*:`，TTL 内二次调用不打库。
