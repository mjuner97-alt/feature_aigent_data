# 问题包含「分布」→ 按当前问的维度默认下钻一级方案

> 日期：2026-11-09

> 关联：docs/202611/追问轮维度继承直接执行方案.md（v3，家族消解 + 下钻粒度冲突消解）、
> docs/202610/直接执行优先于旁路词重排序方案.md、dimension_family_config（D1 拍板）

## 1. 需求与目标

问题文本中包含「分布」时，按当前问题问到的维度**默认下钻一级**：

- 下钻链：**部门 → 应用/组/产品线 → 人**（杭研上级组织不用管，默认下钻到部门）。
- 示例：「杭州三部内部的问题分布情况，可以按应用或小组列」应产出：

```json
{
    "dept": ["杭州开发三部"],
    "drillDown": ["应用维度"]
}
```

目标：无 LLM 参与，纯确定性规则，在直接执行参数组装阶段自动补默认 `drillDown`，用户**显式提及**下钻粒度词时优先按用户说的（不覆盖）。

## 3. 方案设计

### 3.1 触发条件（全部满足才自动补默认下钻值）

1. **轨道**：直接执行新问轨 `plan()` 或追问轨 `planFollowupDirect()` 走到参数组装（旁路让位/回退 LLM 的路径天然不触发）；
2. **触发词**：问题文本包含「分布」（简单 contains，不做分词；「分布式」误伤见 §8）；
3. **skill 支持**：param_mapping 中存在**粒度参数**——dim=drillDown **或** dim=dimension（STAT_DIMENSION_KEY）。两个参数在脚本侧语义同轴（下钻粒度/统计维度），**一个脚本一般仅使用其中之一**（拍板确认），自动补值只针对该 skill 实际配置的那个参数，另一个不补；
4. **无显式值**：组装后该粒度参数（drillDown 或 dimension）无值——问题显式提了粒度词（按应用/按小组/产品线）时，动态键词表 contains-scan 已提取，**用户显式优先，不覆盖**；
5. **人有值则不补**：链底是人（perName/perNo/perRole），人已点名时无更下一级，不补；组/应用/产品线有值时**照补**其下一级（人）——P2 拍板「取最深」的直接推论（「信贷核心组的问题分布」→ 按人分布）。

### 3.2 下钻链与默认值

与代码闭集 DRILL_CONFLICT_FINE_DIMS 对齐，「当前问的维度」取本轮**有值**维度家族中链上**最深**的一级（P2 拍板）：

| 当前问的维度（family） | drillDown 参数默认值 | dimension 参数默认值 |
|---|---|---|
| 部门（deptName） | `应用维度` | `应用` |
| 应用/统计组/产品线（appName/groupName/productLine） | `个人维度` | `人员` |
| 人（perName/perNo/perRole） | 不下钻（链已到底） | 不下钻（链已到底） |

- 默认值取该参数**所属词表的标准值**：drillDown 用「X维度」形态词（DimensionFamilyConfigRepository seed），dimension（STAT_DIMENSION_KEY）用「部门/统计组/应用/产品线/人员」形态词（双词表收敛 seed 同表）；
- **杭研维度不在本方案处理范围**（P4 拍板：不需要考虑，脚本默认逻辑已下钻到部门维度）；
- 部门下钻默认**单值** `["应用维度"]`（P1 拍板，与需求示例一致）：用户真想要组/产品线时会显式说（词表命中路径已覆盖，触发条件 4 不覆盖显式值）。

### 3.3 「当前问的维度」判定

- 值来源：本轮 extraction 终态（含 我X enrich/人名扫描/组→部门反填之后的干净值），追问轨用 **merged 合并视图**（本轮替换 + 快照继承）——「分布呢？」追问轮继承到部门值 → 同样默认下钻应用维度，语义自洽；
- 多级同时有值（如「杭州三部信贷核心组的问题分布」）→ 取链上最深一级：组有值 → 下钻`个人维度`。拍板点 P2；
- 全部无值（「问题分布情况」无任何维度锚点）→ 不补（缺维度锚点时本就另反问/回 LLM，不做假设）。

### 3.4 实现位置与顺序

新增一个私有方法，两条轨道各插一行：

```java
/** 「分布」触发默认下钻一级 (2026-11-09 方案 §3): 问题含「分布」且该 skill 配置了粒度参数
 *  (drillDown/dimension 二选一) 且该参数无值时, 按链上最深有值维度 (P2 拍板) 补默认
 *  粒度值 —— dept→应用, 组/应用/产品线→人; 人有值=链底不补; 零维度锚点不补。 */
private Map<String, Object> applyDistributionDrillDown(Map<String, Object> params,
        Map<String, String> mapping, DimensionExtraction extraction, String question)
```

插入点（**必须在 stripGranularityConflicts 之后**，实施时修正）：

- 新问轨：`stripGranularityConflicts(...)`（:687）之后一行；
- 追问轨：`merged = stripGranularityConflicts(...)`（:917）之后一行。

**为什么在 strip 之后**（实施时发现 §3.1-⑤ 原稿与 P2 拍板矛盾，已修正）：

- 2026/11/06 strip 规则2/3：细粒度家族（组/应用/产品线/人）任一有值 → 粒度参数清空。若填在 strip 前，P2 场景（组有值→下钻人）补的 `个人维度` 会被 strip 立刻删掉，功能无法生效；
- 填在 strip 后由本方法自带守卫：人有值（链底）不补、粒度参数 strip 后仍有值（显式词表命中/合法继承）不覆盖、零维度锚点不补；
- 组/应用/产品线有值时补默认人维度，是「分布」语义下对 strip 规则2/3 的**有意例外**：strip 的动机是「用户已重锚到更细粒度，继承的旧粒度参数失效」；而「分布」触发的默认下钻恰是要按当前焦点的下一级展开，两者不冲突；
- 自动补的值不写入 extraction.extraDimensions → 不产生 D1 豁免副作用，下一轮追问层消解口径不受污染。

### 3.5 与既有机制的关系（不改的部分）

| 既有机制 | 关系 |
|---|---|
| 检索旁路词「分布」（分析类） | **不动**。层级轨 top-1 优先于旁路词（10/27 重排序），本需求生效路径即层级轨直接执行；存量轨/非层级轨带「分布」照旧旁路走 LLM |
| 动态键词表 contains-scan（用户显式提粒度词） | **优先级更高**，3.1-④ 不覆盖 |
| stripGranularityConflicts / dimension_family_config 消解 | **在其下游兜底**，口径同轴（§3.4） |
| 追问层维度信号判定 hasDimensionSignal | **不把「分布」加进 followupSignalKeys 动态键白名单**（那是维度键形态，分布不是维度键）；但分布触发词本身构成追问信号（2026-11-09 E2E bug ① 追加修复，原「现状约束」口径已推翻，见 §10）——「分布情况呢？」纯继承轮由此进入追问轨 |

## 5. 拍板点清单（2026-11-09 全部拍板）

| # | 拍板点 | 结论 |
|---|---|---|
| P1 | 部门下钻默认值：单值 vs 全家桶 `["应用维度","组维度","产品线维度"]` | **单值** `["应用维度"]`（与需求示例一致；组/产品线显式说走词表路径） |
| P2 | 多级同时有值取哪级下钻 | **链上最深一级**。示例：「杭州三部信贷核心组的问题分布」dept 与 groupName 同时有值 → 取组 → 下钻`个人维度`；取最浅会得 [应用维度]，但问句焦点在「组」，按应用展开答非所问 |
| P3 | 追问轮（planFollowupDirect）是否同样生效 | **生效**（同一方法两处调用，merged 语义自洽）。原拍板「分布呢？无其他维度信号时进不了追问轨属现状约束，不扩白名单」——**已被 2026-11-09 内网 E2E bug ① 推翻**：该约束把核心追问场景整个堵死，追加修复改为分布触发词本身构成追问信号（见 §10 追加修复） |
| P4 | 杭研维度是否纳入自动下钻 | **不考虑**——脚本默认逻辑已下钻到部门维度，本方案不为杭研做任何特判 |
| P5 | 「分布」触发词 contains 匹配，「分布式」等误伤 | **接受**。示例：「系统的分布式架构改造进展」不含分布统计意图但 contains 命中「分布」——若该问句恰走直接执行轨且 skill 带粒度参数、有部门值，会多补一个默认 drillDown；后果仅是脚本多按应用展开一层，不报错，不加排除词 |
| P6 | 配置开关 | **加** `harness.a2a.skill-direct-exec.distribution-drill.enabled`（默认 true；沿用 followup-signal-keys 纯后端配置模式，便于内网灰度回退） |

## 7. 明确不做

- 不改检索旁路词表（「分布」保持旁路词身份，让位规则照旧）；
- 不把「分布」加入 followupSignalKeys 维度信号白名单（§3.5）；

### 关键实现决策（与方案的差异点）

1. **插入点改为 strip 之后**（§3.4 已同步修正）：§3.1-⑤ 原稿「细粒度家族均无值才补」与 P2 拍板（组有值→下钻人）矛盾——填在 strip 前会被规则2/3 立即删掉。改为 strip 后由方法自带守卫（人有值链底不补/粒度参数已有值不覆盖/零锚点不补），组/应用/产品线有值时补人维度是对 strip 语义的有意例外；
2. **params_schema 保形**：默认值经既有 `shapeValue` 装配（array→List，单值→String），与 buildParams 口径一致——单测抓出初版恒传 List 与 schema 形状不符；
3. **零锚点 NPE 防御**：`Map.of(...).get(null)` 会抛 NPE，deepest==null 显式提前返回（零锚点单测覆盖）。

**现象**：R1「杭二 完成率」直接执行 q2_1_dual_time_demo 成功 → R2「分布情况呢？」走了 LLM，快照继承与默认下钻都没发生。

**根因**（两层）：

1. **代码**：追问轨入口闸门 `hasDimensionSignal` 要求本轮有维度信号（显式维度/动态键/指代词/人名/台账真值），「分布情况呢？」零信号 → 追问轨不接 → 回退 LLM。修复：分布触发词本身构成追问信号（`question.contains(DISTRIBUTION_TRIGGER)`）——纯继承追问语义 = 对上轮口径要分布视图；不入 followupSignalKeys（那是动态键白名单，分布不是维度键）；
2. **skill 配置**：q2_1_dual_time_demo 的 param_mapping 没配 drillDown 参数、脚本不收该参数——追问轨接住了也补不进去（触发条件③）。修复：脚本 + SKILL.md 增加 drillDown 可选参数（仅回显不过滤，进「维度入参回显」行）；**param_mapping 需在管理页补 `{"drillDown":"drillDown"}`**（配置动作，见下）。

**顺带修正**：`applyDistributionDrillDown` 补 params_schema 白名单守卫（同 buildParams :1416 口径——mapping 配了粒度键但 schema 未声明时不补，防「补了被 scriptExec 防注入拒绝」）。

**测试**：新增 `followupDistributionQuestionInheritsAndFillsDefaultDrill`（R1 直执行记快照 → R2「分布情况呢？」→ 继承 dept/version + 补 drill=[应用维度]），164/164 过；全量 871/871 过。

**内网需做的配置动作**：q2_1_dual_time_demo 的 param_mapping 增加 drillDown 参数（管理页 skill 配置），脚本经 workspace 热加载/重启生效。
