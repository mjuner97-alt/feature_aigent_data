# B① 真值扫描跨轨子串误加修复方案（F-DTX ⊂ F-DTX-OPS 型）

> 状态：**已实施（2026-11-11，单测 886/886 过，内网 E2E 待验）**。
> 现象（内网实测）：问句「**F-DTX-OPS**，卡口测试进度」，提取产物
> `{"app":["F-DTX-OPS","F-DTX"]}` —— `F-DTX` 是**误解析**出来的第二个应用值
> （F-DTX 在台账 `应用` 列存在，F-DTX-OPS 是基地应用不在台账）。
> 脚本收双值做 IN 过滤会把 F-DTX 的数据混进 F-DTX-OPS 的结果。

## 0. 根因（B① 扫描与正则轨互相不知情）

链路（DirectSkillExecutor.applyLedgerTruthScan，:1905-1910 附近）：

1. **正则轨先跑**（DimensionStateManager）：`EXPLICIT_APP = FS?-[A-Za-z][A-Za-z-]*`
   贪婪匹配整段 "F-DTX-OPS" → `extraction.appName=[F-DTX-OPS]`；
2. **B③ 校验**：F-DTX-OPS 不在台账，但命中 2026-11-10 的 F-xxx 形态豁免 → 放行（行为正确）；
3. **B① 正向扫描**（PersonalDimensionResolver.scanTruthValues:247）：台账真值域含
   `F-DTX` → 在问题原文 indexOf → 命中 "F-DTX-**OPS**" 的前 5 个字符 → 追加 `F-DTX`；
4. 合并 → `app=["F-DTX-OPS","F-DTX"]`。

**盲区本质**：`scanTruthValues` 的"最长优先 + boolean[] span 消费"只在**扫描值之间**
防重叠，不知道正则/alias 轨已经提取过更长的值——子串命中没有对照既有提取值消解。
这是 2026-10-27 B① 上线就存在的既有缺陷，此前未暴露是因为 F-DTX-OPS 这类基地应用
会被旧 B③ 剔掉（留下来的恰好只有误加的 F-DTX）；11/10 豁免让基地应用正确保留后，
误加值才在产物里显形。

## 1. 方案：扫描值对既有提取值做"子串让位"消解（单向）

### 1.1 原则

- **显式提取值（正则/alias 轨）永远信任，不被消解掉**；
- **扫描值（B①）是子串推断产物，若是同键既有值的真子串则不加**——
  "F-DTX" ⊂ "F-DTX-OPS" → 丢弃扫描值；
- 单向消解（只过滤 scanned，不动 validated）：合法双提场景必须保住——
  "F-DTX和F-DTX-OPS的进度" 两值都被正则显式提取，谁也不是"推断值"，全保留。

### 1.2 改动（单文件 DirectSkillExecutor，合并处 :1905-1910）

```java
List<String> scanned = resolver.scanTruthValues(question, truthSet);
int addedBefore = validated.size();
for (String v : scanned) {
    // 2026-11-11 拍板: B① 扫描值是同键既有提取值的真子串 → 不加
    // (「F-DTX-OPS」文句中, 台账值 F-DTX 子串命中被 F-DTX-OPS 吸收)
    if (validated.stream().anyMatch(u -> isProperSubstringCI(v, u))) {
        continue;
    }
    if (!validated.contains(v)) {
        validated.add(v);
    }
}
scanHit.put(key, validated.size() > addedBefore);
```

辅助（大小写不敏感：F- 码正则轨归一大写，台账值大小写不保证）：

```java
private static boolean isProperSubstringCI(String shorter, String longer) {
    return shorter != null && longer != null && longer.length() > shorter.length()
            && longer.toLowerCase(Locale.ROOT).contains(shorter.toLowerCase(Locale.ROOT));
}
```

配套：`scanHit` 口径改为"**扫描命中且未被子串消解的值非空**"——
「已在结果里」的扫描值仍算命中（`followupGroupReanchorStripsInheritedDrillDown`
回归实证：R3 追问轮的维度信号源依赖 groupHit，扫描命中但值已存在时必须算命中，
初版"实际净增非空"口径误伤该信号路径，已修正）；纯子串噪声被吸收不算命中。

### 1.3 覆盖面与连锁

- 修复对三个键同源生效：组的「台账值 ⊂ 正则组名」同型误加一并消解
  （如台账有「个贷组」、问句含「个贷汽车场景建设组」→ 不再双收）；
- 扫描值之间的子串/重叠**现状已正确**（scanTruthValues 最长优先 + span 消费，
  F-DTX 与 F-DTX-OPS 同在台账时只会收长者），不动；
- PersonLedgerRepository / scanTruthValues 本体 / B③ / 豁免 / 互斥 / Q8 反填：零改动。

### 1.4 已知边界（有意不做）

- **反方向（扫描值 ⊃ 既有值）不消解**：alias 收了短标准名、台账有更长超串时
  （如既有「资金交易组」+ 扫描「FMBM资金交易组」）两值并存——现状即如此，
  且"显式值被推断值挤掉"违反 1.1 原则，真出现再加超串裁决；
- **位置感知不做了**：扫描值在句中另有独立出现位置、同时又撞既有值子串的极端形态
  （正则没收到独立位置）会漏收——需要把正则 span 透传进扫描，改动面不成比例；
  该形态下主应用结果仍正确，可接受；
- 大小写相同内容的去重维持现状 equals 精确匹配，不扩 CI。
