# Skill 直接执行追问轮：仅提维度即直接执行方案（v3）

> 日期：2026-11-05
> 状态：**已拍板**（2026-11-05 用户拍板 D1-D7 全部通过，可进入实施）
> 关联：`docs/202611/skill-direct-exec-followup-plan.md`（v2 追问走 LLM 链路，已实施）、`docs/202610/domain_tags命中优先于直接执行重排序方案.md`（现行漏斗）、`docs/202610/人员台账维度方案.md`、`docs/202610/time-dimension-plan.md`
> v2 口径回顾：裸追问（「9月的呢」）selector 无佐证不出候选 → 回退 LLM，靠 `<last_direct_exec>` hint 块 + 目录补给让 LLM 复用参数。弱模型场景下 LLM 理解追问+改参数+调 script_exec 的成功率与延迟都不理想。
> v3 目标：**追问轮只提及维度（时间/部门/组/应用/人/下钻粒度/最值）时，也走 skill 直接执行**，保持秒回体感；其余追问形态仍回退 LLM（v2 hint 块兜底不动）。

## 1. 问题与目标

T1「杭州开发二部7月版本 Q2-1 达标率多少」→ 直接执行秒回（快照已记，见 v2 §3.1）。
T2「9月的呢」→ selector 无佐证（无层级词/keywords 命中）→ `plan()` 返回 null（DirectSkillExecutor.java:476-477）→ 回退 LLM。

**目标（v3 口径）**：T2 这类「维度替换型追问」不再回退 LLM——在 plan() 内识别追问、复用快照 skill、本轮维度替换 + 未提及维度继承，直接出 params 执行。

**与 v1 撤销教训的边界**（关键）：v1 被否是因为试图覆盖**全部追问形态**（换对比对象/换指标口径/否定前问…），规则覆盖不全。v3 只做规则能确定覆盖的一个高频子集——**「本轮提到的是维度值，指标与口径沿用上一轮」**，判定依据复用现有维度提取管线（非新造规则），提取不出维度信号就回退 LLM，宁可漏不可错。

```

1. 补参轮 pending 消费 (缺参/时间歧义/人名重名)                  ← 不变

     (含 §3.5 快照兜底; 「三部达标率呢」命中『达标率』层级词仍在这层)
4. 旁路词命中 → (先判追问, 4.5 未命中才置空)                     ← 判定顺序不变
4.5 ★ 追问判定 (C1~C4) 命中 → 复用快照 skill 直接执行            ← 本次新增
     (拍板 2026-11-05: 按原链路优先级走——先看能否有 skill, 再旁路词,
      都未接住才判追问; 旁路词命中轮同样先过追问判定)
5. LLM+目录 (含 v2 hint 块 + 快照 skill 并入)                   ← 不变, 4.5 未命中形态的兜底
6. LLM 走工具层                                                 ← 不变
```

要点：
- 3 与 4.5 互斥：selector 命中走 3（原链路+§3.5 兜底已覆盖「关键词命中型追问」），selector 空才进 4.5。**4.5 是 §3.5 的超集**（§3.5 只补缺，4.5 还做替换）。
- **4.5 位于原链路 skill/旁路词判定之后**（拍板：先 skill → 再旁路词 → 都落空才判追问）。对旁路层的影响只有一处：旁路词命中后不再立即置空进工具层，而是先过追问判定——判定命中（如「近几周分析一下」有维度信号）→ 直接执行；未命中 → 维持现状置空。C4b 排除词表据此收窄为安全网（新任务问法大多已被 skill 命中/旁路词拦截，见 §4.1）。
- 4.5 未命中的追问轮（换指标口径/否定前问/判定条件不满足）原样掉进 5/6，v2 的 hint 块 + 目录补给照常生效——**v3 是增量，不替换 v2**。

## 4. 方案设计

### 4.1 难点一：追问判定（确定性规则，零 LLM）

新私有方法 `planFollowupDirect(question, userId, previousState, conversationId)`，在 plan() **selector 空分支与旁路词分支之后**（原 :476-477 / :493-498 两处 return null 前）调用。**全部前置条件**：

```
C0. 开关开 + conversationId 非空
C1. 快照存在: lastExec(userId, conversationId) != null (TTL 30min 内, 会话隔离, 复用 v2)
C2. 原链路未接住 (走到这里天然成立): selector 候选为空, 且旁路词判定已过
    —— 拍板口径: 先看能否有 skill (domain/层级/keywords), 再旁路词, 都落空才判追问
C3. 维度信号命中: 本轮 extraction 非空 —— 13 个固定键任一非空
    OR extraDimensions 任一非空 (orgName/drillDown/timeRange/topMode...)
    OR 指代词命中 (这个/那个 + 任意维度词, REF_* 正则族)
C4. 负向排除 (防误劫持):
    a. 问题显式点名其它 skill 名 (contains, 与 selector explicit 同判定) → 不追问
    b. 排除词表命中 (新任务动词, 安全网): 帮我写|写个|生成|整理|周报|报告|解释|为什么|怎么办…
       (常量词表起步, 后续可挪 dimension_key_config 配置化) → 不追问
       职责说明: 新任务问法大多已被第 2 层 (domain) / 第 3 层 (selector) / 第 4 层
       (旁路词) 拦截, C4b 只兜「提取出维度信号但语义是新任务」的长尾
       (例: 「把二部的数据整理成周报」——时间+部门有值过 C3, 靠 C4b 拦下), 词表小起步即可
    c. 问题长度 > 60 字 → 不追问 (追问通常短; 超长问题大概率是新问题, 保守回退)
```

- C3 是核心信号：**「用户在本轮说的是维度」**。这套提取就是现网直接执行轮每天在跑的管线（alias/台账真值/时间正则/动态键词表），不新造规则——v1 教训的直接回应。
- C3 覆盖「随便聊」「帮我写周报」（extraction 空 → 回退 LLM）；C4a 覆盖「换个 skill 问」；「缺陷密度呢」若缺陷密度是另一 skill 的 keywords → selector 命中走第 3 层（轮不到 4.5）；同 skill 多指标则直执行本就不带指标参数，无碍。
- 判定错误的代价边界：最坏 = 按上轮 skill+继承参数执行出一份「可能不对题」的结果。见 §8 风险 1。

### 4.2 难点二：维度继承与替换

**原则：本轮提取管线的输出覆盖快照 params，本轮未提取的键继承快照值。** 提取管线原样复用（台账真值/人员扫描/组→部门反填/重锚抑制一个不少）：

```java
private DirectExecutionPlan planFollowupDirect(...) {
    LastDirectExec last = lastExec(userId, conversationId);
    if (last == null) return null;
    SkillRoutingMetadata top = active.stream()... last.skillName();   // 快照 skill 为候选
    if (top == null || !top.active() || top.scriptId() == null) return null;
    if (!canUse(top.skillName(), userId)) return null;                // 权限与原链路同规
    // C4a/C4b/C4c 排除词判定
    // ① 本轮提取: 与 plan() 完全同序的管线复用
    DimensionState preview = dimensionStateManager.previewState(question, previousState);
    DimensionExtraction extraction = extract(preview, List.of()/*无 matchedKeywords*/, topName,
            extractExtraDimensions(question));
    if (!hasDimensionSignal(extraction, question)) return null;       // C3
    extraction = applyLedgerTruthScan(extraction, question).extraction();
    PersonScanOutcome personScan = applyPersonalDimensions(extraction, question, userId);
    extraction = personScan.extraction();
    extraction = backfillDeptFromLedger(extraction, mapping, schema, required);
    extraction = applyReanchorSuppression(extraction, question, personScan, truthScan);
    // ② 时间歧义/人名重名反问: 与原链路同构 (复用同一段, 抽公共方法或内联同逻辑)
    // ③ merge: 快照为基底, 本轮有值即替换
    Map<String, Object> params = new LinkedHashMap<>(last.params());  // 继承基底
    Map<String, Object> round = buildParams(mapping, schema, extraction);
    for (String key : round.keySet()) {
        params.put(key, round.get(key));                              // 替换 (本轮提及优先)
    }
    for (String dimKey : suppressedDimKeys) {                         // 重锚抑制清空的维度键
        params.remove(paramKeyFor(mapping, dimKey));                  // 从基底删除 (D3 拍板,
    }                                                                 // 防「三部的车贷组」错账)
    // ④ 必填缺失 → 现有反问链路 (pending/missingKeys), 与原链路一致
    // ⑤ 成功 → recordLastExec (刷新快照, 链式追问T3/T4各自成立) → 返回执行计划
}
```

merge 语义逐场景核验（关键正确性论证）：

| 追问 | 本轮提取 | merge 结果 | 依据 |
|---|---|---|---|
| 「9月的呢」 | versionPlan=[9月版本]（或 timeRange 锚点） | versionPlan **替换**，deptName 继承二部 | 固定键覆盖 |
| 「三部呢」 | deptName=[杭州开发三部]（alias+台账真值） | deptName 替换，其余继承 | 场景2 |
| 「车贷组呢」 | groupName=[车贷组] + Q8 组→部门反填 | groupName 替换 + deptName 反填替换 | 场景3，复用 :552 |
| 「近几周呢」 | timeRange=AMBIGUOUS:WEEKS → **先反问方向**（与原链路同构） | 反问轮不 merge，补参后走 pending 消费 | 复用 :561-582 |
| 「近几个版本的呢」 | versionPlan=[LAST:3V] | versionPlan 替换 | LAST:{n}V 已支持 |
| 「这个部门那个组的达标率最高的是哪个」 | 指代消解（previewState）→ deptName/groupName 有值；topMode=[最高]（新动态键） | deptName/groupName/topMode 替换 | 场景5 |
| 「各个组呢」 | drillDown=[各组]（词表已有） | drillDown→映射参数（如 groupBy）替换/新增；未配映射则该键在 mapping 外被 buildParams 忽略 → 维持继承值执行或回退 | 场景1 |
| 「9月的呢」但上轮脚本报错 | 快照存在（D2 拍板：plan 即记） | params 继承 + 本轮替换 → 重试友好 | 同 v2 §3.1 语义 |

与 §3.5 兜底（:608-625）的关系：§3.5 语义 =「merge 中 round 为空的键继承 base」的特例。落地时把 §4.2 的 merge 抽成公共原语 `mergeSnapshotParams(base, round, suppressedKeys)`（D7 拍板），原 :608-625 改为调用同一原语（行为不变：round 没有该键就不 put，suppressedKeys 传空集），两处共享测试。

顺序约束（必须保持，与 plan() 现状一致）：
- 重锚抑制在 merge 之前——「三部呢」替换部门后，上轮的组/应用细粒度值**不能**带过来（重锚抑制正好清空它们，然后继承的是清空后的 extraction → buildParams 不产出该键 → base 中该键需要**删除**而非保留）。⚠️ 这是 merge 唯一的非常规点：**重锚抑制清空的键，继承时也要从 base 删除**（否则「三部呢」会把上轮「二部X组」的 groupName 继承过来，变成「三部的X组」，错账）。实现：merge 前按 extraction 重锚抑制结果计算 `suppressedKeys`，`params.remove(mapping 反查键)`。
- 时间歧义锚点/人名重名反问在 merge 之前——能反问就反问，不带错参数执行（拍板先例：反问优于查空集）。

### 4.4 明确不做（维持 v2 口径）

- 换指标口径、否定前问（「不要按部门」）、跨 skill 对比追问 → 回退 LLM；
- 不改 DimensionStateManager（G2 本体仍不修，v2 D1 拍板沿用）；
- 不改两条 Chat 链路 stream()——追问直接执行轮复用 runDirectExecution 渲染（stdout 直发），链路已有 recordResult 一行无需再动；
- 快照结构不变（params 已含动态键实值，merge 天然覆盖 drillDown/orgName）。
