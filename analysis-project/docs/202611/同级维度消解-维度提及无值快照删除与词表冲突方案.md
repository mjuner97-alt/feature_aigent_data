## 1. 问题与 E2E 复现

### 1.1 复现序列（2026/11/06 内网 E2E）

| 轮次 | 问题 | 实际 params | 期望 |
|---|---|---|---|
| 1 | 「信贷核心组的 完成率」 | `groupName=[信贷核心组]`, `version=[10月,11月在建]` | ✅ 正确 |
| 2 | 「各组的呢？」 | `groupName=[信贷核心组]`, `version=[继承]`, `drillDown=[组维度]` | ❌ **groupName 应被消解** |

「各组的呢」语义 = 按**统计组维度**下钻看各组 → 快照继承的 `groupName=信贷核心组` 过滤值与 drillDown 同级冲突（脚本收到「过滤到信贷核心组 + 按组下钻」→ 下钻结果恒为单组），违反 11/05 拍板规则②「涉及 xx 维度，对应 xx 维度值应为空」。

trace 关键证据：本轮 extraction 中 `groupName=[]`（空），但 merge 后 params 仍带 `groupName=[信贷核心组]` —— 说明值不是被本轮管线清掉的，而是**根本没进本轮 extraction**，删除机制全程没看见它。

### 1.2 部门维度词表冲突（附带发现的配置问题）

`dimension_key_config` 两个动态键的词表存在交叉：

- **drillDown (id=24)**：`各部门→杭研维度`、`各个部门→杭研维度`，另有 **scope 词混入**：`杭研→杭研维度`、`杭州研发部/研发部/基地→杭研维度`
- **dimension (id=23)**：`各部门/各个部门→部门`、`杭研→部门`

两个后果：

1. **「杭研」被 drillDown 抢走**：11/05 E2E trace（「杭研 1、2、3三个季度的研发周期的 完成率」）中 extraction 出现 `drillDown=[杭研维度]` 而 `orgName` 为空 → 11/05 修复的规则①（orgName×部门消解）在这条链路完全不生效。杭研是**上级组织 scope 词**不是下钻词，混在下钻词表里语义就错了。
2. **「各部门」双词表同时命中且值名不一致**：drillDown 给 `杭研维度`，dimension 给 `部门` —— 同一个口语词在两套词表里指向同一根轴（部门轴）但值名不同。

## 2. 根因分析

### 2.1 D3 diff 机制的盲区（主 bug）

追问层 merge 的删除依据是 `suppressedFineGrainedParams(preSuppression, extraction, mapping)`（DirectSkillExecutor.java:1031）——对比**本轮提取管线前后**的维度值差异，before 非空且 after 空才判定为「被消解」。它只能感知管线内的清空（L2 重锚抑制 / org×部门消解），感知不了值在管线之前就消失的形态。

「各组的呢」的完整链路：

```
「各组的呢？」
  → analyzeQuestionRuleBased 判级 = PEER（peer 词「的组/各组」命中）
  → previewState = inheritDimensions(previous, analysis)
      PEER case（DimensionStateManager.java:1650）: 只继承 timeDimension + departments，
      peerDimension（组值）由「LLM 回答后提取」——本轮直接丢弃
  → extract(preview, ...) → extraction.groupName = []（preSuppression 捕获时已是空）
  → applyReanchorSuppression：drillDown 触发，但组值本来就没有 → 无可清，无 diff
  → D3 diff：before=[] && after=[] → clearedDims 空 → 快照 groupName 参数不删
  → mergeSnapshotParams(快照, 本轮, ∅) → groupName=[信贷核心组] 原样继承
```

即三种「本轮无组值」形态中，D3 只覆盖了一种：

| 形态 | preSuppression 有组值? | D3 能删? |
|---|---|---|
| ① 本轮提取到组值后被 L2 清空（含值重锚） | 有 | ✅ |
| ② org×部门消解清空 deptName | 有 | ✅ |
| ③ **本轮提维度不提值（preview 继承阶段即丢）** | **无** | ❌ ← 本 bug |

### 2.2 为什么快照是唯一残留源

extraction 层的组值被 preview 继承规则丢掉是**既有正确行为**（10/22 定稿的继承口径，防「杭州三部10月版各组→stat_group 查空集」历史坑），不能改。但快照（`LastDirectExec.params`，来自上一轮实际执行参数）不受 preview 继承规则管，merge 时原样继承——残留只发生在快照这一层，所以修复也应只落在 **merge 删除集**这一层，不动继承、不动 plan() 主链路。

## 3. 修复方案 A：维度提及无值 → 家族级快照参数删除

### 3.1 核心规则

> **本轮（追问轮）通过动态键信号显式提及某维度家族（drillDown 值或 dimension 值），且消解管线后本轮 extraction 中该家族无任何值 → merge 时从快照基底删除该家族的全部参数。**

与既有机制的关系：

- 11/05 规则②③的「值重提保留」语义不变：本轮显式重新提及值（如「信贷核心组各组呢」→ 组值重新提取）→ extraction 家族非空 → **不删**，保留重锚。
- D3 diff 删除继续保留（覆盖形态①②，本方案补形态③），两者取并集，互不冲突。
- 仍然**只动追问层 merge 删除集**（`suppressedParamKeys` 追加），不动 previewState、不动 L2、不动 plan()。

### 3.2 统一家族映射表（双词表收敛，D1 拍板：前端配置表）

两套词表的值统一映射到同一批 dim 家族（解决 1.2-2 的值名不一致——代码层收敛，词表不必二删一）。
**存储（D1 拍板）**：新建 `dimension_family_config` 表（value 唯一 / family / enabled /
updated_at，gauss ensureTable 幂等建表），前端「维度键字典」页新增配置区块，业务人员自维护；
**family 下拉限定固定集**：`groupName / appName / productLine / perName / perNo / perRole /
deptName`（家族集合是代码闭集，对应 extraction 字段，不能发明新家族）。空表预置初始行：

| value（词表标准值） | family | 来源词表 |
|---|---|---|
| 组维度 | groupName | drillDown (id=24) |
| 应用维度 | appName | drillDown |
| 产品线维度 | productLine | drillDown |

| 人维度 | perName,perNo,perRole | drillDown |

### 3.3 判定算法与插入点

新私有方法，在 `planFollowupDirect` 中 `suppressedFineGrainedParams` 之后调用，结果并入 `suppressedParamKeys`：

```java
/** 同级维度消解 (2026/11/06 方案 §3): 本轮动态键提及某维度家族且消解后无值
 *  (含 preview 继承阶段即丢的形态③, D3 diff 盲区) → 快照该家族参数删除。
 *  值重提保留: extraction 家族非空 (显式重提/L2 保留) → 不删;
 *  部门家族例外用问题派生口径 (D2 拍板, preview 无条件继承 departments 终态失真)。 */
private Set<String> dimensionMentionedValuelessDims(DimensionExtraction extraction,
                                                    String question) {
    Map<String, List<String>> familyMap = loadFamilyConfig();   // dimension_family_config, fail-safe 空表
    Set<String> mentionedDims = new LinkedHashSet<>();
    for (String signalKey : List.of(DRILL_DOWN_KEY, STAT_DIMENSION_KEY)) {   // 仅两动态键 (D5 同源)
        for (String value : extraction.extraDimensions().getOrDefault(signalKey, List.of())) {
            List<String> family = familyMap.get(value);
            if (family != null) {
                mentionedDims.addAll(family);
            }
        }
    }
    if (mentionedDims.isEmpty()) {
        return Set.of();
    }
    Set<String> valueless = new LinkedHashSet<>();
    for (String dim : mentionedDims) {
        boolean hasValue = "deptName".equals(dim)
                ? questionMentionsDeptExplicitly(question)   // D2: 问题派生口径 (重新引入)
                : !fineGrainedValues(extraction, dim).isEmpty();
        if (!hasValue) {
            valueless.add(dim);
        }
    }
    return valueless;
}
```

要点：

- **信号源限定 drillDown + dimension 两键**（D1 拍板前提「同级维度消解根据这两个动态键判定」）：不从全部 extraDimensions 扫值，防自定义传参键撞值名。
- **家族映射读 `dimension_family_config` 表**（D1 拍板）：fail-safe——表空/读失败/值查不到 → 不删（宁漏勿错）。
- **值判定**：细粒度家族用 `fineGrainedValues(extraction, dim)`（复用现有 helper）；「值重提保留」覆盖 L2 保留形态——L2 清空后值空 → 删；显式重提值非空 → 不删。部门家族用 `questionMentionsDeptExplicitly`（D2 拍板，随本方案重新引入）。
- **mapping 反查复用 D3 同款循环**：只删该 skill param_mapping 内的参数，mapping 外参数不受影响。
- **D6 拍板不跳过缺参反问**：家族消解删除后若必填缺失照常反问，下钻脚本 schema 非必填由业务自查。

## 4. 词表冲突治理（orgName 移除后重新评估）

> orgName 维度已从代码移除（2026/11/06），写作本文档时的冲突①（杭研抢 orgName 信号）已消失。
> 以下为重新评估后的现状与遗留选择。

### 4.1 scope 词（杭研/杭州研发部/研发部/基地→杭研维度）留在 drillDown 的影响

orgName 移除后，这 4 条 scope 别名不再「抢」任何专用键信号，但产生了**新语义**：「杭研」命中
drillDown → 值 `杭研维度` → 按 §3.2 映射进 **deptName 家族**。后果：

- 「杭研的呢」追问：杭研维度 → dept 家族提及 → 快照部门参数被消解删除 + drillDown=杭研维度
  传给脚本（脚本按部门维度下钻）。这**恰好实现了原 orgName 口径的消解效果**（部门过滤清空），
  只是路径从专用键换成了 drillDown 家族映射；
- 副作用：「杭研 完成率」这类**只想 scope 不想下钻**的问法也会把 `drillDown=杭研维度` 传给脚本，
  脚本会按部门分组输出 —— 若脚本不希望被 scope 词触发下钻，仍应删这 4 条别名；
- 代码无法区分值来自 scope 别名还是下钻别名（`extractExtraDimensions` 只收集标准值不记录别名
  来源），别名级语义只能在词表层分清 —— 该结论不变。

**→ 归入拍板点 D4（更新版）：scope 别名删（纯 scope 语义，脚本不受下钻词污染）vs 留（杭研问法
自动获得部门消解效果）。**

### 4.2 各部门双词表值名不一致 → 代码双词表映射解决，无需删词条（结论不变）

「各部门」同时命中 drillDown（→杭研维度）与 dimension（→部门）：

- drillDown 值是**脚本下钻契约**（脚本 switch-case 认 `杭研维度/组维度/...`），dimension 值是
  **纯信号**（param_mapping 无参数映射到 dimension 键）——两者职责不同、不互斥，双命中无害；
- §3.2 统一家族映射表把 `杭研维度` 和 `部门` 都映射到 `deptName` 家族——下游消解行为完全一致，
  值名差异被代码层吸收。

**结论：不需要让业务人员删「各部门」任何一个词条**。

### 4.3 附带确认项（不改代码，仅确认）

- `dimension` 键 id=23 内部有重复词条 `处理人→人员`（出现两次）——无害，可顺手清理。
- `dimension` 词表含口语宽词（`的人→人员`/`的组→统计组`/`的应用→应用` 等）：这些词若使追问轮
  进入直执行（需 dimension 入 C3 白名单，见拍板点 D5），消解行为是「人员维度提及 → 快照人值
  删除」——语义正确，但意味着这些口语词的追问不再回 LLM，**宽词入白名单的影响面需拍板确认**。

## 9. 下钻粒度冲突消解（2026/11/06 E2E 第三轮拍板，同日落地）

### 9.1 问题（下钻链反向冲突）

下钻链：部门 → 应用/统计组/产品线 → 人。E2E 三轮序列暴露合并视图反向冲突：

1. R1「杭二 7月 完成率」→ 快照 dept/version
2. R2「每个人的呢」→ group_by=个人维度 直执行，**入快照**
3. R3「信贷核心组 的呢」→ 组值重锚，但 params 同时带
   `drillDown=个人维度`（R2 快照继承）+ `groupName=信贷核心组` —— 粒度键与细粒度值冲突。

§8 的家族消解只管「维度提及无值」方向（正向），管不住「细粒度有值 × 继承粒度参数」
（反向）：R3 本轮未提及任何粒度词，家族消解信号为空，不触发。

### 9.2 规则（用户拍板）

- 规则①：部门有值 → drillDown/dimension 可以有 应用/统计组/产品线、人维度；
- 规则②：应用/统计组/产品线有值 → drillDown/dimension 需为空；
- 规则③：人维度有值 → drillDown/dimension 需为空。

### 9.3 拍板点

- **D1 ✅ 显式重提豁免**：本轮 extraction 显式重提的粒度键保留
  （「信贷核心组每个人的呢」组值+粒度共存合法）；只清继承/残留的粒度参数。
- **D2 ✅ 两端一致**：plan() 与追问层同调 `stripGranularityConflicts`。plan() 的粒度键
  恒为本轮显式提及 → 豁免恒成立（实际 no-op），保留是为口径对称 + §3.5 快照兜底防御。

### 9.4 实施（DirectSkillExecutor）

- `stripGranularityConflicts(params, mapping, extraction)`：
  1. 收集 mapping 反查为 drillDown/dimension 且有值的粒度参数；
  2. D1 豁免：extraction.extraDimensions 该键本轮非空 → 保留；
  3. 规则②③：`DRILL_CONFLICT_FINE_DIMS`（groupName/appName/productLine/perName/perNo/perRole，
     dept 不在列——规则①部门值不禁粒度下钻）任一在**合并视图**有值
     （extraction 本轮值 ∪ params 映射参数）→ 非豁免粒度参数全删；
  4. 规则①补充（同家族冲突）：细粒度无值时，粒度值经 dimension_family_config 反查家族，
     家族对应参数有值 → 删该粒度参数（覆盖 部门值×部门维度）；
     粒度值不在家族映射内 → fail-safe 不删（宁漏勿错）。
- 插入点：追问层 ambiguous-anchor 路径（preParams）+ merged 路径 + plan()
  （§3.5 快照兜底后、missingKeys 前）。被删粒度参数经 recordLastExec 不再回流快照。
- 需求项/项目编号非下钻链家族，不纳入。
