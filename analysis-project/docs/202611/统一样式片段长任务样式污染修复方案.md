# 统一样式片段在长任务中的样式污染修复方案

日期: 2026-11-09
状态: 已实施（2026-11-09，本机验证过；服务器已同步 _html_table.py；长任务 E2E 待内网验证）
前作: `docs/202610/DataFrame通用HTML表格导出方案.md`、`docs/202611/个性化HTML表格兼容统一样式方案.md`

## 1. 现象

- **单脚本前端展示**（直接问数，fragment 进 ```html 围栏 → Markdown.vue 沙箱 iframe）：样式正确；
- **串进长任务**（Skill Job 汇总报告）：脚本用 `print(render_html_custom(show_df, fragment=True))`
  输出后，**存量长任务里其他节点/Markdown 的表格样式被改变**（文字颜色/字体/hover/斑马纹/
  容器 padding 等漂移），且脚本自己的表格出现双重留白。

## 2. 根因（两个撞名叠加）

### 2.1 id 撞名：`#report`

`_html_table.py` 的统一 CSS 全部挂在 `#report` 作用域，输出正面包 `<div id="report">`
（§8 v2 修订选 `#report` 是为了对齐 HtmlReportRenderer 的"容器级作用域"设计）。

但长任务汇总文档自己的容器恰好就是 `<div id="report" class="report">`
（`HtmlReportRenderer.assembleHtml`:1071）。片段串进长任务后形成 **嵌套重复 id**，
REPORT_CSS 的容器级规则同时命中内外两层：

```css
#report { padding: var(--report-content-padding) !important; overflow-x: hidden;
          position: relative; height: var(--report-content-height); ... }
```

→ 脚本的内层 `#report` div 被再套一层 padding/overflow，双重留白。

### 2.2 `<style>` 全局提升：片段样式变成全报告样式

长任务渲染链路会把片段里的 `<style>` 提为全局：

- **markdown 路径** `render()`：`STYLE_BLOCK` 抽出注入 head（HtmlReportRenderer.java:777-782），
  ```html 围栏内容原样进 body（`HTML_CODE_BLOCK`）；
- **混排路径** `renderMixedContent()`：markdown 段不做提升，`<style>` 原样留在 body ——
  但 `<style>` 在 body 中同样全局生效。

提升后的 `#report table/th/td/tr...` 选择器命中长任务容器本身 → **整份报告所有表格**
（存量 markdown 表、其他节点输出表）被脚本 CSS 以 `!important` 二次覆盖；
`#report { color:#333; font-family }` 还会改掉全报告的文字颜色与字体。

单脚本展示不出问题，是因为沙箱 iframe 里只有这一张表 —— "撞名"和"全局提升"两个条件
都不成立。这是典型的"片段设计时假设的宿主 ≠ 实际宿主"问题。

## 3. 修复方案：命名空间 `#report` → 独有 class `unified-table`（Python 单点改）

### 3.1 改动内容（只动 `_html_table.py`，零 Java、零调用方改动）

1. **CSS 选择器**：全部 `#report ` 前缀 → `.unified-table ` 前缀（含 box-sizing 两行、
   语义类 `tr.summary-row` / `td.rowhead` / `.red` / `.section-title-sm`）；
2. **输出面包裹**：`_assemble` 里 `<div id="report">` → `<div class="unified-table">`
   （完整文档/片段两档同改，共用同一 CSS 常量）；
3. **CSS 头部加标记注释**：`/* unified-table: 片段样式可被长任务 head 提升,
   独有 class 保证只命中自带 wrapper, 不污染宿主其他表格 */`；
4. 模块 docstring 同步更新作用域说明。

### 3.2 为什么选独有 class 而不是别的

| 方案 | 结论 |
|---|---|
| **A. 独有 class `unified-table`（选定）** | Python 单点改；片段被提升到 head 后只命中自带 wrapper，存量表格零影响；v-html 误注入同样不命中页面元素（保留 §8 的零泄漏性质）；不用改 Java |
| B. Java 侧识别并丢弃片段 `<style>` | 要动 HtmlReportRenderer + 靠标记检测，脆弱；且长任务里脚本表格将完全依赖 REPORT_CSS，chat iframe 里又没人给它样式，两套宿主行为分叉 |
| C. 长任务不用 fragment 改完整文档 | 完整文档在长任务混排里走独立 srcdoc iframe 确实隔离，但脚本被迫二选一输出形态，且存量调用已经铺开 fragment |

### 3.3 双宿主下的样式仲裁（预期行为，写明避免误判回归）

- **chat 沙箱 iframe**：无 `#report`，`.unified-table` 全权生效 —— 统一外观不变；
- **长任务汇总文档**：脚本表格同时被 REPORT_CSS（`#report ...`，特异性更高）和
  提升的 `.unified-table ...` 作用。两边 !important 竞争时 **REPORT_CSS 胜出**
  —— 差异项（margin 4px vs 10px、td color #000 vs #333、padding 变量）以长任务
  REPORT_CSS 为准。**这是预期**：长任务外观由 HtmlReportRenderer 单一真相源决定，
  脚本自带 CSS 退化为"chat 场景专用皮肤"。值早已对齐 REPORT_CSS，视觉一致性不受影响；
- **v-html 误注入**：页面里没有 `.unified-table` 元素 → 零泄漏（同 §8.3 原设计意图）。

## 4. 影响面

- `_html_table.py`：`render_html_table` / `render_html_custom` 内部实现改，函数签名不变；
- `q2_1_metrics_by_dept_version.py`（render_html_table 调用）、
  `q2_1_metrics_by_dept_version_eh.py`、`555153205/_q2_1_display.py`
  （只产语义类表体，无 `#report` 引用）—— **零改动**（已 grep 确认）；
- 前端 Markdown.vue、HtmlReportRenderer.java —— 零改动。

## 5. 验证清单

1. **本机单测**：`render_html_table`/`render_html_custom` 两档输出
   - 不含 `#report`、不含 `id="report"`；含 `.unified-table` 前缀与 wrapper；
   - 完整文档仍以 `<!DOCTYPE html>` 开头；fragment 以 `<style>` 开头；
   - 含 `rgb(192, 0, 0)`、语义类规则、`!important`；
2. **HTML 结构**：同一文档混排「通用表 + 个性化表（summary-row/rowhead/red）」，
   浏览器打开两表均红头白底、汇总行加粗灰底不被斑马纹盖；
3. **长任务模拟**：手工拼一份 REPORT_CSS 结构文档（`<div id="report" class="report">`
   容器 + 存量 markdown 表 + 脚本片段），确认存量表样式与注入前 diff 为零、
   脚本表无双重 padding、嵌套 div 不再叫 `id="report"`；
4. **chat 回归**：q2_1 直接问数，围栏渲染红头白底不回退；
5. **内网 E2E**：跑一次含该脚本的长任务，逐节点对比修复前后截图。
