# 「25年度」转版本计划锚点修复方案

> 2026/11/20 · 背景：双时间 demo 问句「杭二 25年度的完成率」期望 version = 2025 年全部 12 个月版本，
> 实际落了默认在建版本。规则一句话定稿：**「X年度」必须带年份才触发，触发即按该年展开 12 个月版本**。

## 1. 问题与复现

问题原文：

```
杭二 25年度的完成率
```

dimension_extract 面板输出（节选）：

```json
"extraction": { "versionPlan": [], "deptName": ["杭州开发二部"],
  "extraDimensions": { "noVersion": ["杭二 25年度的完成率"], "vestYear": ["全年杭二 25年度的完成率"] } },
"params": { "version": ["2026年11月份版本", "2026年12月份版本"], "dept": ["杭州开发二部"] }
```

期望：`params.version = ["2025年1月份版本", …, "2025年12月份版本"]`。

## 2. 根因

年度级时间变体走两条既有轨，`(\d{2}|\d{4})年度` 两条都没覆盖：

| 轨 | 覆盖变体 | 位置 |
|---|---|---|
| 词表轨（versionPlan 内置 seed） | 全年/今年以来/今年→YEAR_V、上半年/下半年→HALF_V:1/2（`25年上半年→HALF_V:1@2025` 靠 YEAR_PREFIX_TAIL 紧邻年份前缀升级） | `DimensionKeyConfigRepository.java:124-145` + `DimensionStateManager.java:1417-1427` |
| 正则轨 | 近N个版本→LAST:nV | `DimensionStateManager.java:1157-1160` |

`25年度` 落不进 versionPlan → `buildParams` 走 R3 默认在建版本（THIS_V 展开 → 2026年11+12月份版本）；
「年度」一词同时被 DB 动态键 vestYear/noVersion 的词表收走（extraDimensions 噪声）。

而 `YEAR_V@yyyy` 的执行期展开**已存在且语义正是需求**：`VersionPlanAnchorResolver.java:246-249`
→ `monthVersions(year, 1, 12)` 纯格式化产 12 个月版名，历史年份（2025）无需版本日历行。

## 3. 拍板（2026/11/20）

| # | 口径 |
|---|---|
| ① | **年度必须带年份才触发**：`25年度/2025年度→YEAR_V@2025`；裸「年度/本年度」不触发（落既有 R3 默认在建版本口径） |
| ② | **vestYear/noVersion 动态维度键保留不动**：仍按现状收值（resolved 面板噪声，不进 params）；「25年度」同时走 versionPlan→YEAR_V@2025 |

## 4. 方案（已实施，2026/11/20）

### 4.1 `DimensionStateManager` 新增年度正则轨

与「近N个版本→LAST:nV」同组同写法：

```java
// "25年度/2025年度" → YEAR_V@yyyy 锚点（年度必须带年份才触发，裸"年度"不进此轨）
private static final Pattern ANNUAL_YEAR = Pattern.compile("(\\d{4}|\\d{2})年度");
```

`extractExplicitDimensions` LAST_N 块后：

```java
Matcher annualMatcher = ANNUAL_YEAR.matcher(q);
while (annualMatcher.find()) {
    versions.add("YEAR_V@" + yearOf(annualMatcher, currentYear));
}
```

- 复用 `yearOf`（:1032）2 位年归一（`25`→2025），与 11/17「27年1季度→2027」修复同口径；
- 锚点形态 `YEAR_V@2025` 已被 `ANCHOR_PATTERN`（`VersionPlanAnchorResolver.java:53`）接受，展开路径零新增；
- 不与既有模式冲突：「年度」后缀与 `月份版本/季度` 互斥；日期 span（`12月26日`）不含「年度」字样。

### 4.2 `VersionPlanAnchorResolver` ResponseCache 绕过补条目

`ANCHOR_PHRASE_REGEX`（:70）追加 `|\d{2}年度|\d{4}年度`。

原因：锚点短语问题的缓存绕过靠 `containsAnchorPhrase`（:132）——词表 alias 行自动覆盖，但**正则轨产物
不在词表里**，不补则「杭二25年度完成率」与「杭二完成率」缓存指纹撞车脏读（近N个版本/延后正则当初同此补法）。

## 5. 影响面核对（既往改动零回归）

| 既往改动 | 关系 |
|---|---|
| 版本/季度互不换算（R1-R5，buildParams 败者抑制） | 不动。「25年度」产 versionPlan 值 → R1 版本胜，季度抑制照旧 |
| LAST:nV 退化默认修复（F1/F3B） | 不动 lastInBuildAnchor；默认 THIS_V 路径仅在无时间时触发，行为不变 |
| 2 位年缩写 YEAR_PREFIX（921 测试） | 复用 yearOf 归一，口径一致 |
| R6 需求项无时间不补默认 | 「25年度」是显式时间，正常传版本 |
| timeRange §12 / 近N月换轨 | 「年度」不进 timeRange 正则，无交集 |
| 动态键轨 §9（vestYear/noVersion） | 拍板②保留不动，DB 配置零改动 |
| 指纹（auto-synth） | 锚点原词本就不进指纹（DimensionStateManager:1180 注释），无变化 |

已知边界（记录不处理）：`25年度` 与 `全年/今年` 同句混排 → `YEAR_V@2025`+`YEAR_V` 双锚点各自展开取并集
（2025+2026 共 24 值）。罕见混排，与既有锚点多值语义一致，不做抑制。

## 6. 测试要点

单测（3 处）：

1. `DimensionStateManagerRuleTest`：`杭二 25年度的完成率`→versionPlan 含 `YEAR_V@2025` 且 TimeDimension=VERSION；
   `2025年度`→同；裸 `杭二年度的完成率`/`杭二本年度完成率`→无版本锚点；`杭二25年上半年数据` 回归仍过
2. `VersionPlanAnchorResolverTest`：`YEAR_V@2025` 展开 = `2025年1月份版本`…`2025年12月份版本` 12 值
3. `DirectSkillExecutorTest`：双时间 skill 输入「杭二 25年度的完成率」→ params.version 为 2025 年 12 值、
   quarter/qStart/qEnd 不传（R1 抑制生效）

E2E（内网，**须换新 conversationId**）：

- 问「杭二 25年度的完成率」→ dimension_extract `params.version` = 2025年1~12月份版本（12 值），dept=杭州开发二部；
- vestYear/noVersion 仍在 resolved 面板但不影响 params；
- 裸「杭二年度的完成率」→ 仍默认在建版本（回归）。
