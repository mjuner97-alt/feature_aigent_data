# 应用英文形态值豁免台账真值校验方案（统计组/产品线校验不变）

> 状态：**已实施（2026-11-10，单测 871/871 过，内网 E2E 待验）**。v2 收窄：由"appName 整体退出 B①/B③/互斥"
> 改为"**仅 F-xxx/纯英文形态的应用值豁免 B③ 真值域对照**"，其余垃圾值剔除逻辑不变。
> 背景：部分**基地的应用不在台账表 `developer_pl_person_info_t` 的 `应用` 列里**，
> 维度值台账真值校验方案（docs/202610/维度值台账真值校验方案.md，2026-10-27 实施）的
> B③ 终局校验把这些**用户问题里正确的应用名当垃圾值剔除了**（log: `Ledger truth-check
> dropped key=appName ... 不在台账/词表/alias 真值域`）。
> 需求拍板：**应用（appName）根据 developer_pl_person_info_t 校验的逻辑去除；
> 统计组（groupName）、产品线（productLine）的校验不变。**

## 0. 现状梳理（应用维度在真值校验机制里的参与点）

机制回顾（真值校验方案 §4，落点 `DirectSkillExecutor.applyLedgerTruthScan`，
DirectSkillExecutor.java:1879-1949，plan 主链路 :598 与追问链路 :827 两处调用）：

| 环节 | 应用（appName）的参与 | 问题 |
|---|---|---|
| 真值域组装 `truthSetFor` | 台账 Q7 `应用` distinct ∪ dimension_key_config 同义词 ∪ alias 标准名 | **基地应用不在台账 → 不在真值域** |
| B① 正向扫描 | 真值域值在问题原文 contains 扫描，命中即提取 | 域外应用扫不出（与本次误杀无关，不动） |
| B③ 终局校验 | 正则/同义词轨提取的 appName 逐值对照真值域，**域外丢弃 + warn** | **本需求根因：正确应用名被剔除** |
| 三键互斥裁决 | productLine > groupName > appName，多键同时非空时非胜者整键清空 | 与真值域无关的撞车裁决，不动（残余风险见 §2-④） |

**关键事实（豁免范围的依据）**：应用提取只有英文形态——
`EXPLICIT_APP = FS?-[A-Za-z][A-Za-z-]*`（F-GCS / FS-GBCP-EPL，DimensionStateManager.java:381），
裸码轨 `BARE_APP` 把省略前缀的英文段归一补 F-（`gcmcs`→`F-GCMCS`，:387-388）。
即**正则轨产出的 appName 值 100% 是 `F-xxx` 形态**；alias 轨产出标准名（天然在真值域）、
B① 扫描值（天然在真值域）都不会被 B③ 剔。B③ 对 appName 的实际剔除对象
= 正则轨的 F- 形态值 ⊄ 台账 —— 正是基地应用误杀。

应用的其它台账参与点（**全部保留不动**）：

- **Q8 维度值→部门反填**（`backfillDeptFromLedger` :1961，`deptsByDimension("应用", v)`）：
  fail-open 只加部门不删值，应用查不到部门就不反填，无剔除行为；
- **DimensionSpanScanner S2 span 屏蔽**（:127）与 **SkillDimensionCollisionService**
  （:130）读台账真值三列：只影响 skill 关键词路由的撞车屏蔽/审计提示，不删维度值；
- 我X enrich（"我的应用"→ Q1 台账 `应用` 列）：R1 注入路径，不是校验。

## 1. 方案：appName 键 B③ 增加 F-xxx/纯英文形态豁免

### 1.1 核心改动（单点）

`DirectSkillExecutor.applyLedgerTruthScan` 的 B③ 校验循环（:1896-1904）加豁免分支：

```java
/** 应用码英文形态（F-xxx / FS-xxx；裸码已被 BARE_APP 归一补 F- 前缀，大写）。
 *  2026-11-10 拍板：此形态豁免 B③ 真值域对照 —— 基地应用不在台账 developer_pl_person_info_t，
 *  域对照会误杀正确值；非英文形态的应用值（如有）仍走校验拦垃圾。 */
private static final Pattern APP_CODE_SHAPE = Pattern.compile("^FS?-[A-Za-z][A-Za-z-]*$");
```

```java
List<String> validated = new ArrayList<>();
for (String v : current) {
    if ("appName".equals(key) && APP_CODE_SHAPE.matcher(v).matches()) {
        validated.add(v);                      // 豁免：英文形态应用码不对照真值域
    } else if (truthSet.contains(v)) {
        validated.add(v);
    } else {
        log.warn("DirectSkillExecutor: Ledger truth-check dropped key={} value={} "
                + "(不在台账/词表/alias 真值域, 如为合法值请补词表)", key, v);
    }
}
```

### 1.2 豁免的实际覆盖面（为什么这样等于"应用不再被真值域误杀"）

| appName 值的来源 | 形态 | B③ 现状 | 豁免后 |
|---|---|---|---|
| 正则轨 EXPLICIT_APP / BARE_APP | 恒为 `F-xxx` 大写 | 域外剔（**基地应用误杀根因**） | **全量豁免，不再剔** |
| alias 同义词轨 | 标准名（管理员配置） | 在域（alias 标准名并入）不剔 | 不变 |
| B① 正向扫描 | 域内值 | 在域不剔 | 不变（B① 扫描保留，台账内应用整名提取能力不丢） |

- 豁免**只挂在 appName 键**：groupName/productLine 即便出现英文形态值（如组名内嵌
  英文段落整体成值）仍照常对照真值域，符合"统计组、产品线的校验不变"；
- B① 扫描、互斥裁决、Q8 反填、`truthSetFor` 组装、`LedgerTruthScan.appHit` 全部不动
  ——appHit 仍活跃（B① 应用扫描保留），重锚抑制 `appMentioned`（:2093）与追问轨
  `hasDimensionSignal`（:1032）两个消费点**零影响**（v1"整体退出"方案的两个连锁点消失）；
- `PersonLedgerRepository`（TRUTH_COLUMNS/Q5-Q7/缓存/降级）与词表：零改动。

### 1.3 明确不做

- 不给"基地应用"建旁路白名单（治标，名单腐化）；F- 形态豁免是按**形态**而非按**名单**，
  新基地应用零配置生效；
- 不做"应用真值域 = 词表 ∪ alias（去台账）"的折中：域外正确值照样被剔，问题不消；
- 不动互斥裁决（v1 方案的"appName 退出互斥"一并放弃——互斥是撞车裁决不是真值域
  校验，收窄后保持 10/27 行为，残余风险见 §2-④）；
- 统计组/产品线的 B①/B③/互斥/Q8 反填一律不动。

## 2. 行为变化与风险

| # | 变化 | 评估 |
|---|---|---|
| ① | 基地应用（F-xxx）不再被 B③ 剔除（**需求目标**） | 正收益，零配置 |
| ② | **假应用码回归**：正则轨误提的 F- 形态垃圾值（如 "FPA4季度"→F-FPA，台账没有 → 原被 B③ 拦）现在豁免透传 → 脚本查空集 | **本方案唯一实质风险，已拍板接受**（查空集优于误杀正确值）；技术词（sql/csv/api 等）仍由 BARE_APP_STOP 拦截不回归 |
| ③ | 台账内应用的 B① 整名扫描、Q8 反填、span 屏蔽全部保持 | 无回归 |
| ④ | 残余：互斥裁决保留——合法 F-xxx 与更长的组/产品线值同现时，appName 仍可能被裁决清空 | 非 10/27 行为变更（互斥本来如此），非真值域问题；若内网出现"组+应用合法双过滤被清"的实际 case 再评估对 appName 的裁决豁免 |
| ⑤ | 非英文形态应用值（现状不存在，未来中文应用词表若引入）仍走 B③ 校验 | 保护保留，机制不报废 |

## 4. 测试要点（内网 E2E）

1. **主场景**：问句带基地应用码（台账 `应用` 列无此值，如 `F-XXX`）→ appName 直传
   脚本，无 `Ledger truth-check dropped key=appName` warn，脚本按应用过滤出数；
2. **回归场景**：组/产品线垃圾值仍被 B③ 拦（"房贷两个组"型 → 缺参反问）；组 B①
   整名扫描仍生效（"杭州二部FMBM资金交易组"型）；台账内应用 B① 扫描/Q8 反填不回归；
3. **已知接受的退化**：假应用码（F-FPA 型）不再被拦 → 脚本查空集（拍板③接受）；
4. **Q8 反填**：台账内应用纯维度问句仍反填部门；台账外基地应用问句不反填不报错
   （fail-open 查空）。
