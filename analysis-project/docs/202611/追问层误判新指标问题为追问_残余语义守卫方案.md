# 追问层误判新指标问题为追问 —— 残余语义守卫（C5）方案

> 2026/11/23 立项。现象来自内网 trace（同一会话两连问）。方案待拍板后实施。

## 1. 现象

同一会话：

| 轮 | 用户输入 | 实际行为 |
|---|---|---|
| 1 | 杭州三部特种业务组12月版本质检问题明细 | 直接执行 `wenshu_detailed_design_zhijian`，params = version_plan=2026年12月份版本, dev_dept=杭州开发三部, stat_group=特种业务组 ✅ |
| 2 | 杭州三部各组的外源驱动比 | 被判为**追问轮**，继承快照 skill `wenshu_detailed_design_zhijian`，params = version_plan=继承2026年12月份版本, dev_dept=杭州开发三部, drillDown=组维度 ❌ —— 问的是外源驱动比，答的是质检问题（问东答西） |

Q2 dimension_extract 关键片段：

```json
"extraction": {
  "versionPlan": [], "deptName": ["杭州开发三部"], "metrics": [],
  "extraDimensions": {
    "dimension": ["统计组"], "drillDown": ["组维度"],
    "noVersion": ["杭州三部各组的外源驱动比"]
  }
}
```

## 2. 根因

### 2.1 追问层判定缺「内容新颖性」守卫（主根因）

分流顺序（`DirectSkillExecutor.planAll`，DirectSkillExecutor.java:583-595）：
selector 空 → `planFollowupDirect`（追问层）。Q2 的「外源驱动比」不在任何 skill 词条里，
selector 空，进入追问层。

`planFollowupDirect`（DirectSkillExecutor.java:1101-1313）现有守卫全是**排除型**
（识别「明确不是追问」），没有一条守卫识别「本轮出现了快照口径之外的新语义」：

| 守卫 | 内容 | Q2 结果 |
|---|---|---|
| C1 (:1109) | 快照存在（TTL 30min） | ✅ Q1 刚执行过 |
| C4c (:1114) | 问题长度 ≤60 | ✅ 13 字 |
| D1 (:1118) | domain 命中 → 让位 LLM | ✅「外源驱动」不在任何 domain_tags |
| C4a (:1123) | 显式点名其它 skill → 不是追问 | ✅ 未点名 |
| C4b (:1131) | 排除词（帮我写/生成/对比/为什么…） | ✅ 无命中 |
| 对比句式 (:1136) | `(和\|与\|跟\|同).{0,10}(比\|对比\|比较)\|对比\|比较\|相比` | ✅ 单字「比」不匹配 |
| C3 (:1181) | hasDimensionSignal = 本轮提到维度 | ✅ **命中（见 2.3）** |

C3 只回答「本轮有没有维度信号」，从不回答「本轮有没有超出快照口径的新内容」。
于是「维度值 + 未知新名词」形态的新问题（杭州三部 + 各组 + 外源驱动比）必然被吸进追问层。

### 2.2 追问层 metrics 恒空，指标守卫在该层不可用

追问层的提取强制 `extract(preview, List.of(), last.skillName(), …)`（:1157）——
metrics 形参恒传空列表，`extraction.metrics()` 在追问层**永远为空**。Q2 面板上
`"metrics": []` 即由此来（「外源驱动比」本身也不在指标词表）。因此任何
「提取到新指标 → 判新问题」的守卫在追问层拿不到输入，必须换判定原料。

### 2.3 放大因素：「各组」动态键词表命中强化 C3 信号

Q2 的「各组」命中动态键词表（drillDown → 组维度，可能同时命中 dimension → 统计组），
叠加「杭州三部」显式部门别名，C3 双信号命中，追问判定更加笃定。词表命中本身没错，
错在 C3 把「提到组」等同于「在追问组」。

### 2.4 noVersion = 整句：已知噪声，本方案不动

`extraDimensions.noVersion = [整句]` 是 noVersion 动态键（dimension_key_config 业务自配，
含整句捕获型条目）的已知面板噪声：

- 年度转版本计划锚点修复方案 §2/拍板②：vestYear/noVersion 动态键保留不动，不进 params；
- 人名上下文消歧方案 §1.5（2026/11/23 拍板：暂时不管）。

本方案零改动，仅复述留档。Q2 params 未出现 noVersion，无实害。

## 3. 根因对策选型

| 选项 | 思路 | 结论 |
|---|---|---|
| A. metrics 守卫 | 提取到新指标词且不属于快照 skill → 判新问题 | ❌ 不可行：2.2 追问层 metrics 恒空；且未知名词（外源驱动比）本就提不出来 |
| B. 指标后缀正则 | 「X比/X率/X占比」句式判新问题 | ❌ 词袋脆断，「驱动比/环比/同比/占比」误杀面大 |
| C. **残余语义守卫（C5）** | 问题剥离「已知成分」后仍有显著残余名词 → 新问题回退 LLM | ✅ 采用。与既有「宁可漏不可错」原则同向：误判新问题为追问 = 错口径执行（最重）；漏判追问 → LLM 带 hint 块仍能正确处理追问 |

## 4. 拍板点

| # | 问题 | 建议 |
|---|---|---|
| ① | 守卫编号与位置 | C5，插在对比句式判定（:1138）之后、快照 skill 元数据查询（:1140）之前 —— fail-fast，不跑 extract 管线 |
| ② | 回退方向 | return null 回退 LLM（带快照 hint 块），不回反问 |
| ③ | 残余显著阈值 | 剥离后连续汉字段长度 ≥2 才算显著（单字「比/率/呢」忽略） |
| ④ | 开关 | 独立开关 `harness.a2a.skill-direct-exec.followup-residue-guard`，**默认 true**（理由：本守卫只把边界 case 从「错口径执行」推向「LLM 兜底」，方向安全；与 multiExec 默认 false 的灰度逻辑不同性质，见拍板⑤讨论） |
| ⑤ | 已知词域是否纳入目录标签（tool_route_metadata metricTags/topicTags） | 先不纳入（最小实现），仅 skill 词条 ∪ 真值域 ∪ 动态键词域；若内网误杀案例出现再扩。metrics 双词源并集方案（11/18 拍板未实施）落地后可顺带接入 |
| ⑥ | 停用词表维护 | 常量内嵌（同 FOLLOWUP_EXCLUDE_WORDS 形态），暂不做配置化 |

## 5. 方案（C5 残余语义守卫）

### 5.1 判定定义

> **纯维度追问** = 问题剥离「已知成分」后，无显著残余。
> 剥离后残余含 ≥2 连续汉字且不在已知词域 → 本轮是**新问题** → C5 拦截，回退 LLM。

Q2 套验：「杭州三部各组的外源驱动比」→ 剥掉「杭州三部」（台账/部门词域）、
「各组」（drillDown 词表命中词）、「的」（虚词）→ 残余「外源驱动比」（5 汉字，
不在已知词域）→ **拦截 ✅**。

真追问套验（全部放行）：
- 「特种业务组呢」→ 剥掉组名 → 残余空 → 放行
- 「明细呢」→ 「明细」是 mingxi 动态键命中词 → 放行
- 「各个组呢」→ 「各个」停用词 +「组」单字 → 放行
- 「杨阳的缺陷密度呢」→ 杨阳（人名台账）+「缺陷密度」（快照 skill 词条）→ 放行
- 「分布情况呢」→ DISTRIBUTION_TRIGGER 命中 → 放行
- 「每个人的呢」→ 「每个人」停用词 → 放行

### 5.2 剥离集合（已知成分）

按长度降序做子串剔除（防「杭州开发三部」被「三部」先剥碎）：

| 来源 | 内容 | 获取方式 |
|---|---|---|
| 动态键命中 | extractExtraDimensions 的 alias 命中**原文** + 标准值 | 新增私有方法 `extractExtraDimensionsWithHits(question)` 双产物（值 map + 命中词 set），`extractExtraDimensions` 复用之，对外签名不变 |
| 维度值 | 本轮规则分析显式维度值（dept/group/app/productLine/需求项/项目编号）+ 同义词条目（alias 原文→标准名，含 Q2 的「杭州三部」） | `dimensionStateManager.analyzeQuestionRuleBased(question)` 的解析结果 + AliasResolver 词表；台账真值扫描命中片段（truthScan 词域） |
| 人名 | 台账扫描命中的人名/角色 | personScan（C5 阶段尚未跑台账 —— 见 5.4 顺序说明，用人名词表 contains 扫描轻量替代，或后移 C5 到台账扫描之后） |
| 时间词 | 版本/季度/年月/近N月等 | 复用 TimeRangeExtractor 锚点 + DimensionStateManager 既有时间正则族（MONTH/YEAR/QUARTER 等常量，不新写） |
| 指代/分布 | FOLLOWUP_REF_PATTERN、DISTRIBUTION_TRIGGER | 既有常量直接复用 |
| 虚词停用词表 | 的/呢/吗/啊/请/帮我/看看/查/查一下/一下/各个/各/所有/全部/分别/各自/每个人/按人/人均/情况/数据/再/还/也/照/按/统计/汇总/输出/列/出来 | 新常量 `FOLLOWUP_RESIDUE_STOPWORDS` |

剥离后再剔除标点/空白/数字/拉丁字符，剩余连续汉字段即残余。

### 5.3 已知词域（残余白名单）

残余汉字段逐段查以下集合，任一命中即不算显著：

1. **全部 active skill 词条**：`SkillRoutingMetadata` 的 keywords + level1/2/3Keywords
   （防御性纳入：若「外源驱动比」已配到某 skill 词条而 selector 层级轨 AND 漏选，
   C5 不应拦它 —— 交给 LLM 反而更差）；
2. **真值域**：台账 distinct（Q5-Q7）∪ dimension_key_config 同义词 value ∪ alias 标准名
   （复用台账真值扫描既有词域构建，DirectSkillExecutor.java:2503 注释口径同源）；
3. 动态键全部 alias 原文与标准值（5.2 已剥，双保险）。

命中判定用 contains（词域条目 contains 于残余段，或残余段 contains 条目），
与既有词表轨扫描口径一致。

### 5.4 实施位置与顺序

```
planFollowupDirect:
  C1 快照 → C4c 长度 → D1 domain → C4a 点名 → C4b 排除词 → 对比句式
  → [新增] C5 残余语义守卫（拍板①）
  → 快照 skill 元数据/权限/mapping 查询 → extract 管线 → C3 维度信号 → …
```

- C5 不依赖 extract 管线产物，只依赖 question + 词表/词域查询，可安全前置（fail-fast，
  省掉 2.2 提取管线与 script_registry 查询开销）；
- 人名剥离在 C5 阶段用「台账人名词表 contains 扫描」轻量替代（不跑完整 personScan），
  完整 personScan 仍在 C3 之后的管线里跑，语义不变。

### 5.5 回退行为（拍板②）

C5 命中 → `return null` → planAll 返回空列表 → 走 LLM。LLM 侧已有快照 hint 块 +
目录并入（v2 拍板口径，DirectSkillExecutor.java:449 注释），能：
- 若「外源驱动比」属某 LLM 可路由的领域 skill → 正常路由执行；
- 若无归属 → 基于上一轮质检结果摘要 + 本轮问题给出得体回复（而非静默错口径执行）。

### 5.6 配置（拍板④）

```yaml
harness:
  a2a:
    skill-direct-exec:
      followup-residue-guard: true   # 默认 true
```

`V2SkillConfig` 注入（与 followupDirectEnabled 同形态）。关闭 = 行为完全回退现状。

## 6. 与既有机制关系

| 机制 | 关系 |
|---|---|
| C3 hasDimensionSignal | 不动。C5 是它的前置反守卫：C5 管「有没有新内容」，C3 管「有没有维度信号」，二者交集才是追问 |
| D1 domain 让位 | 不动。domain 命中在 C5 之前已让位 |
| FOLLOWUP_EXCLUDE_WORDS / 对比句式 | 不动，C5 是其互补面（排除词抓「新任务动词」，C5 抓「新名词」） |
| 追问层继承/消解链（重锚抑制/时间家族/同级消解/分布下钻/产品线展开） | 不动，均在 C5 之后 |
| metrics 双词源并集（11/18 拍板未实施） | 无耦合；落地后可按拍板⑤扩已知词域 |
| noVersion/vestYear 动态键 | 拍板②保留不动（2.4） |
| 多 skill 直接执行 | 无交集（追问层位于 planAll selector 空分支，多执行在 selector 非空分支） |

## 7. 风险与误杀分析

| 场景 | 行为 | 代价 |
|---|---|---|
| 真追问里带词域外新词（「严重问题的呢」且「严重问题」未配词条） | 回退 LLM | LLM 有 hint，答得对但慢 —— 可接受（宁可漏不可错） |
| 新问题全由已知词构成（「特种业务组的明细」跨 skill 语义） | 仍进追问层 | 现状本来如此，无回归 |
| 业务后续给「外源驱动比」配了词条 | selector 命中走正常直接执行，C5 不触发 | 期望行为 |
| 词域查询失败（DB 抖动） | 词域按空集处理 → 残余守卫大概率拦截 → 回退 LLM | fail-safe 方向正确 |

## 8. 测试要点

单测（DirectSkillExecutorTest）：

1. **本 case 回归**：Q1 直接执行后问「杭州三部各组的外源驱动比」→ planFollowupDirect 返回 null（走 LLM）；
2. **纯追问回归**（全部仍进追问层）：「特种业务组呢」「明细呢」「各个组呢」「杨阳的缺陷密度呢」「分布情况呢」「每个人的呢」「那二部的呢」；
3. **已知词域豁免**：「外源驱动比」加入某 active skill 词条后 → C5 放行（该词不再算残余）；
4. **剥离鲁棒**：「杭州开发三部」全名/「三部」简称两种形态都能剥净；
5. **既有守卫回归**：C4c 超长 / D1 domain / C4a 点名 / C4b 排除词 / 对比句式 行为不变；
6. **开关关闭**：followup-residue-guard=false → Q2 形态回到现状（进追问层）；
7. noVersion 面板噪声不受影响（不进 params）。

## 9. E2E（内网，须换新 conversationId）

1. 同会话两连问（本 case 原样）：Q1 质检明细 → Q2 外源驱动比 → 第 2 轮不再秒回质检口径，
   走 LLM 给出正确响应（或明确告知暂无该指标口径）；
2. 追问回归：Q1 后接「特种业务组呢」「明细呢」「分布情况呢」→ 仍秒回追问层直接执行；
3. 面板观察：第 2 轮 dimension_extract 不再出现继承的 version_plan/drillDown 参数组装。
