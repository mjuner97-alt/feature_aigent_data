# 直接执行优先于检索旁路词：路由漏斗重排序方案

> 日期：2026-10-27
> 状态：已实施（2026-10-27，744 单测全过，E2E 待内网）
> 关联：`docs/202610/skill-direct-exec-plan.md`（直接执行工程化）、`docs/202610/skill-retrieval-logic.md` §8（检索旁路词，拍板①两处同拦）、`docs/202610/skill-direct-exec-followup-plan.md`（追问轮/快照）
> ⚠️ **漏斗已被再次修订（2026-10-28）**：`docs/202610/domain_tags命中优先于直接执行重排序方案.md` 在本漏斗之上新增最高层「domain_tags 命中 → LLM 运行领域 skill」，本方案第 2~4 层整体下移一层；本方案的机制改动（topFromLevelTrack、旁路检查后移）全部保留复用。

## 1. 背景与冲突案例

§8 旁路词上线时的拍板①是「**两处同拦**」：旁路词命中 → `SkillVectorIndexVisibilityFilter` 目录置空 + `DirectSkillExecutor.plan()` 短路放弃。当时直接执行与 LLM 检索是同级的下游，旁路拦在它们前面没有矛盾。

直接执行工程化铺开后出现了新的冲突类别：**同一个词既是旁路词、又是某个直接执行 skill 的层级关键词**。

实例：skill 配了 `L1=未闭环`、`L2=A号`、`script_id=...`；旁路词表「质量板块」组里有 `A号`（当初为质量板块切原子工具而配）。用户问：

> **三部10月未闭环的A号数据**

- 旁路词 `A号` 命中 → `bypassed(question)=true` → `plan()` 入口直接 return null；
- 直接执行被旁路**枪毙**，目录又被旁路**置空** → LLM 只能走工具层；
- 管理员为这个 skill 精心配的层级关键词（L1+L2 AND 命中，明确表达了「这个问法归我」）完全失效。

根因：旁路词是**按词**的全局开关，层级关键词是**按 skill** 的归属声明，两者撞车时现在的优先级是旁路赢——与「直接执行工程化（绕过 LLM）」的定位（确定性秒回路径，最高优先）相反。

## 2. 目标漏斗（本次拍板的排序口径）

一轮用户问题的分发顺序调整为：

```
0. 歧义反问短路 (clarifyPrompt)                          ← 现状不变, 在一切之前
1. 补参轮 pending 消费 (缺参/时间歧义/人名重名)             ← 现状不变, plan() 内已最优先
2. ★ Skill 直接执行工程化 (绕过 LLM):
     L1/L2/L3 层级轨 AND 命中 + top-1 配了 script_id
     + 参数齐 → Java 直接调脚本                            ← 本次调整: 升到旁路词之前
3. 检索旁路词命中 → skill 检索置空 → LLM 直接走工具层        ← 层级轨未接住时才生效
4. 正常 skill 检索 (显式点名 > 层级轨 > 存量轨) → LLM+目录
5. 无候选 → LLM 走工具层                                   ← 现状不变
```

关键语义：**层级轨命中 = skill 用层级关键词声明了「触及这些词的问题归我」**，这种显式归属声明优先于按词的全局旁路开关。存量轨（领域标签+叶层 keywords，无层级配置）不享受此优先级——问法带旁路词时照旧被旁路，保住 §8 的原始动机（偏分析问法不误入围 skill）。

## 3. 方案选型

### 3.1 方案 A（推荐）：旁路检查在 plan() 内后移 + 层级轨让位

`DirectSkillExecutor.plan()` 里把旁路检查从 selector **之前**移到**之后**：旁路词命中时，仅当 top-1 不是层级轨（存量轨/空候选）才放弃短路；层级轨 top-1 照常走直接执行判定链。

- LLM 目录路径（filter）**零改动**：旁路词命中仍整体置空。
- 影响面被严格限制在「直接执行能不能跑」这一件事上，正是冲突现场。

### 3.2 方案 B（否决）：bypassed() 语义改造——层级 AND 命中即不旁路

`SkillBypassKeywordService.bypassed()` 内部加一层「任一 active 层级 skill AND 命中 → 不旁路」判定，两个消费点自动继承。

否决理由：

1. **改变 LLM 目录路径行为**：带「分析」等旁路词的问题，只要碰巧 AND 命中任何一个**没配 script_id** 的层级 skill，目录就不再置空，问题从「确定性走工具」变成「走 LLM 检索」——内网 LLM 不可靠，这是 §8 当初要防的退化，等于架空旁路词的原始动机；
2. 违反目标漏斗：漏斗里层级命中只在**第 2 层（直接执行）**压过旁路；第 4 层（LLM 检索）仍排在旁路之后。方案 B 把层级命中抬到了第 4 层也压过旁路，超出授权范围；
3. `bypassed()` 是纯词表判定，塞进 selector 的 AND/保底注入逻辑会让「旁路」这个概念的语义混入检索细节，两套逻辑耦合后边改边崩（§6 已知坑纪律：归一化/匹配逻辑两处同步改的负担会更重）。

### 3.3 拍板记录（2026-10-27 全部拍板）

| # | 决策点 | 结论 |
|---|---|---|
| ① | 方案选型 | **A**（plan() 内重排，filter 不动） |
| ② | 层级轨命中 + 缺必填参数 + 旁路词 → 反问还是走工具？ | **反问补参**（needsAsk 是直接执行工程的零 LLM 环节，随第 2 层一起优先）。典型场景：skill L1=未闭环/L2=A号/部门必填，问「未闭环的A号情况」（未说部门）→ 不查脚本不走工具，直接反问「还需要补充：部门」，用户回复后补参轮（pending 消费在旁路检查之前）继续零 LLM 直接执行 |
| ③ | 层级轨命中 + top-1 未配 script_id + 旁路词 | **维持走工具**（直接执行未接住 → 落回第 3 层旁路，不给 LLM 目录；与方案 A 一致） |
| ④ | 旁路词×直接执行 skill 层级词撞车审计 | 本期**不做**（优先级已裁决冲突，撞车从 bug 降级为「管理员应知晓的事实」，审计纯提示性质不影响行为；可选后续见 §8） |

## 4. 代码改动

### 4.1 `SkillCandidateSelection` 尾部追加 `topFromLevelTrack`

`v2/skills/SkillCandidateSelection.java`：record 尾部追加 `boolean topFromLevelTrack`（top-1 是否来自层级轨），沿用本仓既定的尾部追加 + 旧构造器重载兼容策略：

```java
public record SkillCandidateSelection(
        List<String> skillNames,
        boolean explicitNameMatched,
        boolean confident,
        boolean fallbackExpanded,
        List<String> matchedKeywords,
        boolean topFromLevelTrack) {          // ★ 新增, 尾部

    // 现有 4 参 / 5 参重载保留, 各补一个 topFromLevelTrack=false 的委托
    public SkillCandidateSelection(List<String> skillNames, boolean explicitNameMatched,
                                   boolean confident, boolean fallbackExpanded) {
        this(skillNames, explicitNameMatched, confident, fallbackExpanded, List.of(), false);
    }
    public SkillCandidateSelection(List<String> skillNames, boolean explicitNameMatched,
                                   boolean confident, boolean fallbackExpanded,
                                   List<String> matchedKeywords) {
        this(skillNames, explicitNameMatched, confident, fallbackExpanded, matchedKeywords, false);
    }
}
```

存量调用点（空结果构造等）走旧重载零改动。

### 4.2 `SkillCandidateSelector.selectInternal` 填充标志

`v2/skills/SkillCandidateSelector.java`：

- `ScoredSkill` 加 `boolean levelTrack` 字段（层级轨候选=true，显式点名/存量轨=false）；
- 排序不变（depth 1-3 的层级轨本来就排在 depth 0 存量轨前），`finish()` 里直接取榜首的标志：

```java
boolean topFromLevelTrack = !scored.isEmpty() && scored.get(0).levelTrack();
return new SkillCandidateSelection(selected, ..., topMatched, topFromLevelTrack);
```

- 三个空结果 return 点用旧构造器（false），行为不变。

不改任何匹配/排序语义——只把「榜首来自哪条轨」这一既有事实透出。

### 4.3 `DirectSkillExecutor.plan()`：旁路检查后移 + 让位条件

`v2/skills/DirectSkillExecutor.java` L466-472 现状：

```java
// 检索旁路 (§8 拍板①): 与 SkillVectorIndexVisibilityFilter 同一判定, 必须两处同时拦截。
if (bypassKeywordServiceProvider != null) {
    SkillBypassKeywordService bypass = bypassKeywordServiceProvider.getIfAvailable();
    if (bypass != null && bypass.bypassed(question)) {
        return null;
    }
}
List<SkillRoutingMetadata> active = metadataRepository.findActive();
...
SkillCandidateSelection selection = candidateSelector.selectFromMetadata(active, question);
if (selection.skillNames().isEmpty()) return null;
```

改为（顺序对调 + 让位条件）：

```java
List<SkillRoutingMetadata> active = metadataRepository.findActive();
if (active.isEmpty()) return null;
SkillCandidateSelection selection = candidateSelector.selectFromMetadata(active, question);
if (selection.skillNames().isEmpty()) return null;
// 检索旁路 (2026/10/27 重排序): 旁路词命中时仅当 top-1 非层级轨才放弃短路;
// 层级轨 top-1 (L1/L2/L3 AND 命中) = 直接执行工程化命中, 优先于旁路词 (漏斗第 2 层 > 第 3 层)。
// 存量轨 (领域标签+叶层) 不让位 —— 问法带旁路词时照旧旁路, 保住 §8 原始动机。
if (bypassKeywordServiceProvider != null) {
    SkillBypassKeywordService bypass = bypassKeywordServiceProvider.getIfAvailable();
    if (bypass != null && bypass.bypassed(question) && !selection.topFromLevelTrack()) {
        return null;
    }
}
```

注意点：

1. **只动顺序和条件，不动后续判定链**——top-1 无 scriptId / mapping 空 / 权限 fail-closed / 缺参等既有回退分支全部保持。层级轨让位后如果 top-1 没配 script_id，照样在既有检查处 return null（拍板③：落回旁路 → 工具）；
2. **两条 Chat 链路零改动**：`V2ChatStreamServiceImpl` L461 与 `ChatStreamServiceImpl` L499 的 `plan()` 调用点不动，重排完全收在 plan() 内部；
3. **补参轮天然不受影响**：`consumePending` 在 plan() 最前面、旁路检查之前（现状如此），本次重排不改变它；
4. `bypassed()` 本身**语义零改动**（词表命中 + 显式点名让位，§8 拍板④⑦原样）——仍然是单一判定源，两个消费点调同一方法，「两处同拦」修订为「两处消费同一判定、消费语义分层」（目录侧无条件旁路，直接执行侧层级轨让位）。

### 4.4 注释/文档同步

- `SkillBypassKeywordService` 类注释：消费语义更新为「目录侧无条件旁路；直接执行侧层级轨让位（见本方案）」；
- `SkillVectorIndexVisibilityFilter` L134 注释补一句「2026/10/27 起直接执行侧旁路让位层级轨，目录侧维持无条件置空」；

| 组件 | 理由 |

## 8. 风险与取舍

| # | 风险/取舍 | 处置 |
|---|---|---|
| 1 | 「分析/趋势」类问法只要层级 AND 命中就直接执行，用户想听的「分析」可能拿到的是裸数据表 | 有意取舍（拍板：直接执行最优先）；skill 配层级词即声明归属，管理员可对个别 skill 删层级词退出该优先级；真要旁路个别词可把旁路词配 lookaround 或停用 |
| 2 | needsAsk 在旁路轮也生效（案例 7） | 拍板②确认；不认可则把让位条件收紧为「topFromLevelTrack 且计划可执行」——实现上需把旁路检查挪到 buildParams 之后，不建议（反问是零 LLM 环节，体验优于丢给工具） |
| 3 | 层级轨 top-1 配置错误（mapping 空/权限不够）+ 旁路词 → 静默走工具 | 与现状一致（旁路本就置空目录）；配置期校验已存在（param_mapping 保存期校验 + StartupAudit） |
| 4 | `topFromLevelTrack` 依赖 depth 排序不变式（层级轨 depth≥1 恒排存量轨 depth=0 前） | 不变式由 §9 双轨合并排序保证并有单测覆盖；显式点名 depth=4 单列，不受影响 |
| 5 | 撞车词审计缺失（哪个旁路词同时是层级词，管理员无感知） | 可选后续：SkillRoutingStartupAudit 或旁路词 reload 时扫「旁路词字面 ∈ 某 active+script_id skill 的 L1/L2/L3」打 warn 日志 + 配置页提示；本期不做（拍板④） |
