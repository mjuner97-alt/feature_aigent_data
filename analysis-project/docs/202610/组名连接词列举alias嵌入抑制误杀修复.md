# 组名连接词列举 alias 嵌入抑制误杀修复

> 2026-11-02 | 内网 E2E 实证 | 影响维度：TEAM（小组）多值列举

## 1. 现象

同义词配置（`dimension_alias` 表，TEAM 维度）：

| alias | standard_name |
|---|---|
| 车贷 | 个贷汽车场景建设组 |
| 房贷 | 个贷住房场景建设组 |

两种问法表现不一致：

| 问法 | groupName 提取结果 |
|---|---|
| 三部车贷组**、**房贷组的风险 | 个贷汽车场景建设组、个贷住房场景建设组 ✅ |
| 三部车贷组**和**房贷组的风险 | 只剩个贷住房场景建设组 ❌（车贷命中被丢） |

顿号列举正常，「和/与/逗号」列举只识别出其中一个组；零连接词紧邻写法
（「车贷组房贷组」）同病，见 §5.1。

## 2. 根因

`EXPLICIT_TEAM` 正则 `([一-龥A-Za-z0-9]{2,}组)` 的字符类 `[一-龥A-Za-z0-9]`
**不含列举连接词**，导致两种写法切出的组名 token 不同：

- **顿号版**：`、` 不在字符类内，天然切成「三部车贷组」「房贷组」两个 token，
  两个 alias 命中都不满足嵌入条件，双双保留。
- **「和」版**：`和` 在字符类内，整段被贪婪吞成**一个** token
  「三部车贷组和房贷组」，随后走嵌入抑制判定（`embeddedInTeamSpan`）：

  - 「车贷」命中后缀还有「组和房贷组」（5 字，满足 `span[1]-end > 1`）
    ⇒ 判定为嵌在组名 token 内部，标准名「个贷汽车场景建设组」与 token 互不包含
    ⇒ **抑制丢弃**；
  - 「房贷」命中后面只剩「组」（间距 = 1，不满足 `> 1`）⇒ 不算嵌入，保留。

  结果：头部命中被误杀，只剩尾部命中。

嵌入抑制的本意是处理「个贷数据开发组」里的「个贷」（产品线别名碰巧是组名子串，
应让组正则接管），但列举场景下 token 实际是多个组的拼接，误触发了该抑制。

## 3. 修复方案

`DimensionStateManager` 两处改动：

1. **`embeddedInTeamSpan`**：数量粒度豁免之后、互不包含判定之前，新增
   列举连接词拆分——token 含连接词时调 `enumerationSubSpan` 拆出 alias
   命中所处的**子 token**，改用子 token 做嵌入判定：

   - 子 token 内命中后缀只剩「组」（`subSpan[1] - end <= 1`）⇒ 与顿号写法
     同口径，不算嵌入，保留（`continue` 到下一个 team span）；
   - 子 token 内仍满足嵌入条件 ⇒ 继续原有的互不包含判定与抑制。

2. **新增 `enumerationSubSpan(q, span, start, end)`**：扫描 token 内的
   连接词字符（`、，,和与`，与共享后缀列举正则 `SHARED_SUFFIX_VERSION`
   的列举符同套），取命中前最后一个连接词之后、命中后第一个连接词之前
   的分段；无连接词返回 null（维持整段判定，行为不变）。

### 不受影响的既有机制（回归确认）

| 机制 | 用例 | 结果 |
| --- | --- | --- |
| 真嵌入抑制 | 「个贷数据开发组」的「个贷」（无连接词） | 仍抑制，组正则接管 ✅ |
| 数量粒度豁免 | 「车贷、房贷两个组的风险」 | 双值保留 ✅ |
| 互不包含错绑防护 | 「分行业务组」的「分行」 | 仍抑制 ✅ |
| 标准名互相包含保留 | 「杭州开发三部同业客户组」的「同业」 | 仍保留 ✅ |

## 4. 测试

`DimensionStateManagerEmbeddedAliasTest` 新增两例：

- `andJoinedGroupEnumerationKeepsBothAliases`：
  - 「三部车贷组和房贷组的风险」→ 双值（正序）；
  - 「三部房贷组和车贷组的风险」→ 双值（反序，修复前头部命中同样被误杀）。
- `juxtaposedGroupNamesWithoutConnectorKeepsBothAliases`（§5.1）：
  - 「三部车贷组房贷组的风险」→ 双值（零连接词，裸 alias）；
  - 「车贷组房贷组的风险」→ 保留「个贷汽车场景建设组」（alias 自带「组」尾，
    内置词表形态，修复前被整段抑制 + 兜底正则产出垃圾组名「车贷组房贷组」）；
  - 「个贷数据开发组的缺陷密度」回归不变。

dimension 包全量 275 个测试通过。

## 5. 已知相邻边界

### 5.1 零连接词紧邻列举（已实施，2026-11-02 同日补齐）

同根问题的极限形态——连接词完全没有：

> 「三部车贷组房贷组的风险」——人一眼看出是两个组，因为有两个「组」字。

`EXPLICIT_TEAM` 同样整段吞成一个 token，首个 alias「车贷」后缀带「组房贷组」
（5 字 > 1）⇒ 触发嵌入抑制误杀，表现与「和」版一致。「车贷组 房贷组」
（空格分隔）因空格不在字符类内，天然切两段，不受影响。

**修复判据（沿用「组」字计数）**：token 内含 ≥2 个「组」字 ⇒ 是列举而非
单个组名，按「组」字边界拆子 token 再做嵌入判定。已并入 `enumerationSubSpan`：
连接词与「组」字两类边界同扫，取最紧子段（partStart 取最大、partEnd 取最小）；
alias 自带「组」尾（内置词表「车贷组」形态）时命中段恰好止于子段边界
（后缀为空）同样保留——注意空后缀合法，守卫是 `partEnd < end` 而非 `<=`。

**风险**：极罕见的真组名内嵌「组」字（如「XX组织保障组」）会被拆错，
但需同时满足「组名内嵌组字 + alias 恰好命中该内嵌段」才出错，概率很低；
子 token 仍留后缀（> 1）时互不包含判定仍兜底；单「组」token 不拆，
真嵌入抑制不受影响。

**拍板（2026-11-02）**：扩 `enumerationSubSpan` 把抑制误杀补齐（影响面
仅嵌入抑制判定，与本次修复同一回归）；**组 span 生成层拆分另行立项**（§5.2）。

### 5.2 组名正则兜底垃圾组名（另行立项）

若某组**完全没配 alias**，alias 全空时组名正则兜底路径会把
「车贷组和房贷组」整段抓成一个垃圾组名 token（正则贪婪，同根问题）。
本次问法因 alias 命中不走兜底路径，未受影响；治理需在 `EXPLICIT_TEAM`
匹配层（teamSpans 生成处）做拆分——但组 span 还喂给屏蔽
（maskSpanList）、层级判定等多条路径，牵连面大，需单独回归，不在本
次最小修复范围内。
