> docs/202610/直接执行优先于旁路词重排序方案.md（漏斗重排序）、

## 1. 背景与问题

skill 检索（`skill_routing_metadata` 四层词条 + 旁路词）与维度提取（`dimension_alias`
口语别名 + 标准名 + 组名 token）是**两套互不感知的词表，跑在同一段问题文本上**。
检索词条命中判定是纯文本包含（`SkillTermMatcher.matches` = 正则 `find()` / 字面
contains），**不知道命中位置是不是一个维度实体指称的一部分**。

### 1.1 实证 case（2026/10/28）：杭州四部风险组

skill 配置：`wenshu_risk_item_detail_multi_para_py`，L1=`["风险"]`、叶层 keywords=`["风险"]`
（唯一主题词）、script_id 已配 → 层级轨直接执行候选。

```
TEAM 风险组 → 全球市场风险管理应用
TEAM 风险组 → 风险资产业务组
```

| 问法 | 实际行为 | 应有行为 |
|---|---|---|
| 杭州四部**风险组**10月版测试问题归属哪个开发经理 | `风险` 命中「风险**组**」内部 → skill 入围 → 层级轨直接执行 → `product_line=全球市场风险管理应用` 过滤 → **确定性错答**（还有歧义反问把用户引到错误标准名） | `风险` 是实体「风险组」的一部分，非主题信号 → skill 不入围 → LLM 工具层走人维度（对照 case 2 实测正确） |
| 杭州四部10月版测试问题归属哪个开发经理（无风险组） | 无命中 → LLM 工具层 ✓ | 同左 |

**关键对比**：问「风险项的达标率」时 `风险` 独立出现（不在任何实体 span 内），
路由到风险 skill 是**正确**的。term 级碰撞词表判不了这两种情形——
`风险` 本身不是 alias 词表成员（`风险组` 才是）；若把「keyword 是实体名子串」也判为
碰撞词，两个问法一起被杀，误杀合法问法。**这就是本次重写的动因：判定必须落到位置级。**

### 1.2 误命中来源的统一

用户视角的两个来源，本质是同一件事：

1. **标准名**中含关键词：`风险` ⊂ `风险资产业务组` / `全球市场风险管理应用`；
2. **口语词**中含关键词：`风险` ⊂ `风险组` / `财政` ⊂ `代理财政业务开发组`。

两者都是「关键词命中位置落在**维度实体指称 span** 内部」。维度值无论口语还是标准名，
在句子里都承担**圈数据范围**的角色（在什么范围内查），不是**表达主题意图**（要什么）。
把它误当主题信号，就会错误触发 skill 路由——直接执行升位后（重排序方案，层级轨 >
旁路词），后果是**绕过 LLM 直接跑脚本**的确定性错答。

### 1.3 底层逻辑（本方案的第一性原理）

> 用户问题里有两类信息：**要什么**（指标/主题 → skill 检索的合法依据）和
> **在什么范围内**（维度实体 → 维度提取的依据）。
>
> **同一个词，出现在维度实体指称（span）内部 = 实体名的一部分 = 假主题信号；
> 出现在 span 外 = 独立主题词 = 真信号。**

推论：

- 检索词条命中要按**位置**分级，不能按**词**分级；
- span 集覆盖口语 + 标准名 + 组名 token 后，两个误命中来源被同一机制统一消解；
- 维度提取侧**不动**（机制A 嵌入抑制、§13.4 span 剥离、BARE_APP 让位已验证），
  本方案只给检索侧补上它缺失的 span 感知。

## 2. 现状机制回顾

### 2.1 检索侧（skill-retrieval-logic.md §9 + 重排序方案）

| 环节 | 行为 | 对本 bug 的敏感度 |
|---|---|---|
| 显式点名 | `containsName`（skill 名 contains）| 低（skill 名是长串） |
| 层级轨 | AND：每个配置层都须有命中；**升位后直接执行** | **最大受害面**：假信号命中 → AND 满足 → 直接跑脚本 |
| 存量轨 | 叶层 1 词命中即入围（2000/词 cap 4000） | 假信号 → 误入围 LLM 目录 |
| 排序/截断 | depth → globalRank → partial 两档 | 假信号污染位次与截断档 |
| 旁路词 | plan() 内条件旁路（`bypassed && !topFromLevelTrack`）；filter 无条件 | 碰撞词进旁路表 → 非层级轨轮次整轮置空（维持 §8 原始动机，行为不豁免，仅审计提示，见 P5） |

### 2.2 维度侧现成机制（本方案只读复用，不改）

- `dimension_alias`：alias（口语）→ standardName，TEAM/PRODUCT_LINE/APPLICATION/…；
- 台账真值字典：`PersonLedgerRepository.dimensionTruthDictionary(统计组/产品线/应用)`；
- span 机制先例：机制A `suppressEmbeddedAliasHits`/`embeddedInTeamSpan`（alias 命中
  span × 组名 token 互不包含判定）、§13.4 span 屏蔽剥离、`dateShieldSpans`（时间屏蔽）；
- `EXPLICIT_TEAM = [一-龥A-Za-z0-9]{2,}组`（DimensionStateManager L446）——
  「风险组」即使不配 alias 也会被抓成组名 token。

## 3. 方案总览

| 方案 | 内容 | 本文处置 |
|---|---|---|
| **C. 维度实体 span 屏蔽（核心）** | 检索词条命中按位置分级：命中 ∈ 维度实体 span → 不计分 | **转正，§4** |

## 4. 核心机制：维度实体 span 屏蔽（方案C）

### 4.1 判定规则

```
对每个检索词条 term 的每次命中 hit：
  hit 位置 ∩ 维度实体 span 集 = ∅  → 真命中（照常计分/参与 AND/位次）
  hit 位置 ∩ 维度实体 span 集 ≠ ∅  → 假命中（等同该词未命中）
```

- **混合命中自然成立**：「风险组的缺陷」——`风险` 被「风险组」span 屏蔽，`缺陷`
  在 span 外真命中 → 配了 `缺陷` 词条的 skill 照常入围；只有全部命中都被屏蔽的
  skill 才出局（等价原方案B 的"全部碰撞才出局"，只是判定粒度从词升级到位置）；
- **正则词条**：`find()` 返回 Matcher 后取 `start()/end()` 判 span 交集即可，
  正则词条同样适用（比原方案B 的 SKIP 更强）；
- **显式点名不受屏蔽影响**（containsName skillName 在守卫之前，恒置顶不变）。

### 4.2 维度实体 span 集的构成

| # | span 来源 | 例 | 说明 |
|---|---|---|---|
| S1 | alias 口语命中 span | `风险组`/`车贷`/`同业` | AliasResolver 词表扫描 |
| S2 | 标准名命中 span | `风险资产业务组`/`全球市场风险管理应用` | alias standardName 列 + 台账真值字典三列 distinct 值；**是否纳入拍板 P1** |
| S3 | EXPLICIT_TEAM 组名 token span | `[一-龥A-Za-z0-9]{2,}组` | 未配 alias 的组名也能屏蔽（`风险组` 案例的兜底层） |
| S4 | 时间 span（既有） | `10月版本`/`3季度` | dateShieldSpans 已有，统一并入扫描器（词条撞时间词的场景，如裸 Q1 已单独处理过，此处统一收口） |

span 扫描器做成**独立共享组件**（`DimensionSpanScanner`，暂名）：输入 normalized
question，输出 span 列表；单一真相源同时供——

1. `SkillCandidateSelector`（检索屏蔽，本方案新增消费点）；
2. `DimensionStateManager`（机制A/嵌入抑制迁移到同一扫描器上，**可选二期**，本期
   不迁移避免回归面过大，先双轨并存）。

### 4.3 时序与注入

selector 在 `DirectSkillExecutor.plan()` 与 LLM 目录路径（filter/主 agent）中都先于
维度提取跑，span 扫描只依赖 alias/真值快照（Supplier，TTL 30s，同 AliasResolver
风格），**不依赖维度提取结果**，无跨阶段时序问题。

```
question ──► DimensionSpanScanner ──► spans
                  │
                  ▼
SkillCandidateSelector.selectInternal(question, spans)
  └─ collectMatched: 每次命中判 span 交集, span 内不计分
```

### 4.4 复用原方案B 的基础设施

- 碰撞/词表快照 Supplier + TTL 30s + 读失败 fail-open（空 span 集 = 屏蔽自动关闭，
  行为回退现状）；
- 开关 `skill.collision-guard.enabled`（默认 true）；
- 归一化纪律（§6 已知坑）：question 与词条、span 词表统一走
  `SkillTermMatcher.normalize`，span 坐标在 normalized 文本上计算。

### 4.5 与直接执行重排序的漏斗自洽（2026/10/27 重排序方案零改动）

span 屏蔽打掉层级轨候选 → AND 不满足 → `topFromLevelTrack` 翻转 false →
旁路词按重排序语义自然接管 → 落工具层。守卫在 selector 内、让位条件读守卫**之后**
的 selector 结果，两者天然串行。「杭州四部风险组…」案例走通后即：
层级轨出局 → 无旁路词 → plan null → LLM 工具层（与 case 2 汇合）。

## 5. 配置期审计（方案A，term 级近似）

span 级判定需要问题文本，配置期没有问题，审计用 term 级近似做**提示**：

- `SkillDimensionCollisionService`：对每个词条 term，静态计算它出现在哪些实体名内
  （alias 口语列 ∪ standardName 列 ∪ 台账真值三列）：
  - **HIGH**：term 完全等于某口语词；
  - **MED**：term 是某实体名的子串（如 `风险` ⊂ `风险组`/`风险资产业务组`）；
  - **SKIP**：term 不可静态分析（纯正则元字符）——运行期由 span 屏蔽兜住。
- 产出：① PUT /api/skill-routing 保存响应附 `dimensionCollisions`；② 启动审计日志
  （SkillRoutingStartupAudit 挂点，只告警不阻断，对齐重排序方案拍板④ 定调）；
  ③ 旁路词 × 维度口语撞车同表提示（P5 降级后的落点）；
- fail-open：词表读失败 → 跳过审计，不阻塞保存/启动。

## 6. 拍板点

| # | 问题 | 建议 |
|---|---|---|
| P1 | span 集是否含**标准名**（S2）？含则更彻底，但「主题词只出现在实体名里」的单词条 skill 会被屏蔽（如主题词恰好是 `风险管理` 而问题说 `风险管理应用`） | **含标准名**（混合命中规则救大部分；单词条 skill 被屏蔽本就是 §1.1 要修的 bug） |
| P2 | 混合命中规则：span 内不计分、span 外照常计分，全被屏蔽才出局 | **确认**（C 的固有语义） |
| P3 | S3 组名 token（`XX组` 正则）是否进 span 集？ | **进**（`风险组` 不配 alias 也有兜底；token 宽匹配的误屏蔽面小——组名指称本来就是范围限定） |
| P4 | DimensionStateManager 嵌入抑制是否迁移到同一扫描器（二期）？ | 本期不迁移，双轨并存，回归面最小 |
| P5 | 旁路词撞实体名是否豁免旁路？ | 否（不豁免，仅审计提示） |
| P6 | 配置端是否硬禁保存？ | 否，仅告警 + 响应 warning |
| P7 | `风险组` 歧义反问 / TEAM 配了应用语义标准名 / 部门限定消歧（「杭州四部风险组」用已提部门过滤 alias 候选后唯一化） | **另立方案**，不混入本文（见 §8） |

## 7. 改动清单（拍板后实施）

1. **新增** `DimensionSpanScanner`（v2/dimension 或 v2/skills）：S1-S4 span 扫描，
   Supplier 快照（alias 口语+标准名 + 真值字典三列）TTL 30s + fail-open；
   `List<int[]> scan(String normalizedQuestion)`。
2. **SkillTermMatcher**：新增返回命中位置的匹配方法（现有 `matches` 语义不动，
   供旁路词等旧消费点继续用）。
3. **SkillCandidateSelector**：构造器加 spanScanner（可空 = 关闭）；
   `collectMatched`/`matchedTerms` 每次命中判 span 交集；日志补屏蔽原因。
4. **SkillDimensionCollisionService + 审计**：§5 三级划分；保存响应 warning 字段；
   启动审计日志；旁路词撞车同表提示。
5. **V2SkillConfig 装配**：spanScanner bean 注入 selector（两条链路同源）。
6. 前端 skill 配置页徽标（可拆二期）。

## 8. 相邻问题（本 case 暴露，另立方案）

1. **`风险组` 双标准名歧义反问**：即使 span 屏蔽让本题落回 LLM 路径，反问仍会发生，
   且选项本身有误（`全球市场风险管理应用` 是应用/产品线语义却配在 TEAM 下；PL 下也有

## 9. 测试要点

- **SpanScanner 单测**：S1/S2/S3/S4 各来源 span 正确性；重叠 span 合并；normalized
  坐标一致性；快照失败 → 空 span 集（fail-open）。
- **Selector 单测**：
  1. 「杭州四部风险组…」+ skill 唯一词条 `风险` → 全屏蔽出局（§1.1 case 复现）；
  2. 「风险项的达标率」+ 词条 `风险` → 真命中入围（不误杀）；
  3. 「风险组的缺陷」+ 词条 `缺陷` → 混合场景 span 外计分入围；
  4. 层级轨 L1 真 + L2 span 内假 → AND 不满足出局；全真 → 入围；
  5. 显式点名 + span 屏蔽 → 恒置顶不屏蔽；
  6. 正则词条命中位置判 span；
  7. spanScanner=null → 行为与现状逐分支一致（存量 744+ 用例全过即回归）。
- **审计/保存单测**：HIGH/MED/SKIP 划分；warning 字段；旁路词提示。
- **E2E（内网）**：§1.1 两问法对照回归 + 「风险组的缺陷」混合问法；重排序方案 §7
  E2E 清单不回归。

## 10. 兼容性与回滚

- span 集为空（alias 表空/读失败/开关关）= 屏蔽天然关闭，等价现状；
- 不改 SQL 表结构、不改维度提取任何行为、不改 `bypassed()` 语义、不改重排序漏斗；
- 回滚 = 关 `skill.collision-guard.enabled`。
