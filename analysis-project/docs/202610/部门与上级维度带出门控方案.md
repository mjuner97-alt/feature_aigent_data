# 部门与上级维度带出门控方案（仅提下级维度不带出上级 · 我值连带恢复）

> 状态：已实施（2026-10-30，直执 + LLM 双轨落地，单测 800/800；E2E 待内网）。
> 需求原文（业务 2026-10-30）：
> 1. 用户问题**仅**提及 产品线/应用/统计组（没说部门），且脚本参数定义中部门维度参数为**非必输**时，不带出部门；
> 2. 用户问题**仅**提及 人维度（没说部门、也没说产品线/应用/统计组上级维度），且脚本参数定义中部门、产品线/应用/统计组上级维度参数为**非必输**时，不带出部门、产品线/应用/统计组上级维度；
> 3. 我值相关的产品线/应用/统计组不变，**继续带出部门维度**；我值默认带出部门维度（产品线/应用/统计组三者同级、仅能出现一个，未指定则都不带出）。
>
> 口径拍板（2026-10-30 与需求方确认）：
> - **拍板 A（需求 3 语义）**：恢复我X**全量连带部门**——我的应用/我的产品线也连带注入台账部门
>   （回到 2026-10-26 R1 按需注入之前的 anyHit 连带语义，仅部门这一项恢复；peer 自身值仍 per-type）；
>   裸「我」**新增**默认带出台账部门；peer 三键未指定一律不注入（现状已如此，固化）。
> - **拍板 B（需求 2 范围，2026-10-30 复核撤销）**：~~「不带出」含跨轮继承抑制~~
>   **需求 2 暂不做，维持现状**——本期不新增任何仅提人轮次的继承抑制/反填禁止条款
>   （详见 §2.2）。
> - **拍板 C（需求 1 反向）**：问句仅提及组/应用/产品线、且脚本部门参数为**必输**时，
>   维持 2026-10-27 台账 Q8 反填拍板（避免缺部门反问）。
>
> 主场景：skill 直接执行参数解析（`DirectSkillExecutor.plan`，同人员台账方案 §0 校准）。
> 上游文档：`人员台账维度方案.md`（Q8 反填 §8、我X enrich §3.3）、
> `我X按需注入与作用域重锚方案.md`（R1 per-type / L2 重锚抑制）、
> `岗位角色内置维度方案.md`、`Skill直接执行缺参反问方案.md`。

## 2. 方案

### 2.1 需求 1：Q8 反填按部门参数 requiredness 门控

**改动 1（前置）**：schema/required 加载（现 ：539-549）**前移**到 extract 之后、
`applyLedgerTruthScan` 之前（truthScan/personal/backfill 均不依赖 schema，前移无副作用；
一次加载全链路共用，⑦ 段原位置删除）。

**改动 2**：`backfillDeptFromLedger(extraction)` → `backfillDeptFromLedger(extraction, mapping, required)`，
入口新增门控：

```
deptBound   = mapping 中存在 value == "deptName" 的绑定
deptRequired= deptBound 且其参数名 ∈ required（任一绑定必输即算必输）
仅当 deptBound && deptRequired → 执行台账 Q8 反填；否则原样返回（跳过，省一次台账查询）
```

| 场景 | 行为 |
|---|---|
| 部门参数必输 + 仅提 peer | 维持反填（拍板 C，脚本不退化为缺部门口径） |
| 部门参数非必输 + 仅提 peer | **不反填**，deptName 保持空 → buildParams 不传 → 脚本按缺部门口径自决 |
| mapping 未绑 deptName | 不反填（产物无处落地，顺带省查询） |
| schema 查不到/解析失败（无 schema） | 现状"mapping 原样传"无法判定必输 → **维持反填**（fail-open，同 10/27 行为，拍板①） |
| 台账查不到/查询失败 | 不变：fail-open 不反填；若部门必输则走既有缺参反问 |

需求 2（暂缓）与本节正交：仅提人时无 peer 命中，Q8 本就不触发。

### 2.2 需求 2：仅提人不带出部门/上级维度 —— **暂不实施（2026-10-30 复核）**

**维持现状，本期不做任何改动。** 原设计（在 `applyReanchorSuppression` 新增"仅提人"
触发分支、清空跨轮继承的 deptName/peer、快照兜底补缺同步豁免）整体摘出，留档如下，
后续业务再提时可直接按此实施：

- 判定：本轮人名扫描命中（含重名未确认）且 无我X命中/显式部门/peer 提及/drillDown/指代；
- 动作：deptName + peer 三键清空（仅清跨轮继承残留），perName/perNo/perRole 保留；
- 联动：非必输参数不传；必输走既有缺参反问；**快照兜底补缺须对 dept/peer 跳过**
  （否则 ：612 会把上轮值补回绕过抑制）；补参轮经 suppressForReplyRound 自动同口径。

不做的现状语义（保留）：人名→部门本无反填机制；追问轮（"张三的缺陷数呢"）跨轮继承
的部门/peer 照旧带给参数（非必输也传），必输缺失时快照兜底补回上轮值。

### 2.3 需求 3：我X 恢复全量连带部门 + 裸我默认带部门

**直执路径 `enrichPersonal`（:1020）字段映射修订**：

| 口语命中 | 现状 | 修订后 |
|---|---|---|
| myDept（我部） | deptName | 不变 |
| myGroup（我组） | groupName + deptName | 不变（本就双注） |
| myApp（我的应用） | appName | appName + **deptName += ledger.depts()** |
| myProductLine（我的产品线） | productLine | productLine + **deptName += ledger.depts()** |
| myself（裸我） | perNo + perName | perNo + perName + **deptName += ledger.depts()**（查 Q1，ledger null/anonymous 时不注） |

- peer 三键：myself 不注入任何 peer（同级互斥、未指定都不带）——现状已如此，**固化**；
  我X per-type 自身值注入不变（拍板 A 仅恢复"部门连带"这一项）；
- 多命中并集："我的应用和我的产品线"双命中 → 两份 ledger.depts() 为同一人的部门，
  appendNew 去重后自然合并；
- 降级契约不变：anonymous / 台账查无 / 查询失败 → 不注入（裸我仍填 perNo=userId）；
- **LLM 回退路径同步（`DimensionStateMiddleware` :129-146）**：myApp/myProductLine 分支加
  `state.setDepartments(merge(...ledger.depts()))`；myself 分支加 departments 注入
  （peer 仍维持 setPeerIfAbsent 三选一）。

**与 L2 重锚的交互（自动成立，无需改 L2）**：

- myself/myApp/myProductLine 命中 → anyHit=true → L2 触发 → 本轮未重新提及的
  peer/人 继承值清空 → "裸我轮不带出 peer（含继承残留）"与"我的应用轮不带出
  继承的其他 peer"均由既有机制保证；deptName 不在 L2 抑制矩阵 → 刚连带注入的
  台账部门不会被误清；
- 裸我 + 显式部门（"我和杭州三部的对比"）→ deptName = 台账部门 ∪ 显式值，appendNew 保序。

### 2.4 修订后 plan() 全链路顺序

```
① extract(previewState)                          跨轮继承进入
② schema/required 加载                            【前移，需求1】
③ applyLedgerTruthScan                           真值校验+互斥裁决（不变）
④ applyPersonalDimensions                        我X enrich（需求3 全量连带）→ 人名扫描 → perRole
⑤ backfillDeptFromLedger(mapping, required)      Q8 反填（需求1 必输门控）
⑥ applyReanchorSuppression                       L2 原有分支（不变，需求2 暂缓）
⑦ 时间歧义反问 → 人名重名反问 → buildParams → 快照兜底补缺（不变）→ 必填缺失反问/回退
```

## 4. 测试要点（E2E，内网）

1. **需求 1**：脚本部门参数非必输，问"车贷组的缺陷数"（车贷=统计组）→ 参数仅 groupName，
   无 deptName；同脚本部门参数改必输 → Q8 反填部门照旧；台账停服 → 必输脚本走缺部门反问；
2. **需求 3**：裸"我的缺陷数" → deptName=我的部门 + perNo/perName，无组/应用/产品线参数；
   "我的应用缺陷数" → appName + deptName；"我部和二部比" → 两部门多值；
3. **回归**：全量单测基线（当前 793+）；enrich 签名变更涉及构造点全量过；
   仅提人追问轮（"张三的缺陷数呢"）行为与现状一致（继承部门照旧，不做回归断言变更）。
