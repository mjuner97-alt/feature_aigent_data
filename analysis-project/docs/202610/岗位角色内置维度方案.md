# 岗位角色内置维度方案（perRole）

> 关联：docs/202610/人员台账维度方案.md（perNo 内置键 §3.4、我X enrich §3.3）、
> docs/202610/我X按需注入与作用域重锚方案.md（R1/R2/L3）。2026-10-26 需求，先定逻辑再实施。

## 1. 需求

台账表 `developer_pl_person_info_t` 已有 **"岗位角色"** 列（业务侧维护，值域如
应用开发/应用测试/需求分析）。要求：**当通过 统一认证号（userId）或 人名→统一认证号
的方式获得 perNo 时，新内置维度「岗位角色」同步填充对应台账值**——即岗位角色是
"人的属性维度"，值永远跟随人解析产生，不从问句文本提取。

## 2. 数据源现状（零数据改动）

- 表列 `"岗位角色"` 已存在（nvarchar2，业务维护）；
- dev 库 2026/10/22 灌入的 421 行种子数据已带随机角色值（ROLES =
  应用开发/应用测试/需求分析，`tmp_test/ledger_seed_insert.py`），**无需补数**；
- 兼岗（同 perNo 多行）各行可有不同角色 → 与 部门/统计组 同口径 **distinct 多值合并**。

## 3. 语义设计

### 3.1 新内置键 `perRole`（第 11 内置键）

| 项 | 值 |
|---|---|
| key | `perRole` |
| label | 岗位角色 |
| 值来源 | **双源**：① 问句显式提取（§3.1b）② 随人填充（§3.2 台账）；显式值优先 |
| 值域 | 业务维护（应用开发/应用测试/项目经理/测试经理…），值域走台账角色字典（§3.1b），**不走静态词表** |
| 指纹 | **不参与**（同 perNo：执行期解析值，随人变化，跨轮不继承不进指纹） |
| 多值 | 兼岗多行 distinct 保序；多人（"张三和李四"）合并去重 |

不进静态词表的理由：值域随台账行变化，静态词表会腐化；问题侧提取用 **台账角色
字典（运行期 DISTINCT 查询）** 承载值域（§3.1b），字典即词表、永不腐化。
perRole 行**仍要建** dimension_key_config 行，但其 aliases 承载的是 **正则配置**
（MYSELF 变体 / 角色提取模式，见 §3.1c），不是值域同义词。

### 3.1b 问句显式角色提取（2026-10-26 补，指定具体岗位角色场景）

业务例句（显式说了角色，不再是"纯随人填充"）：

- **我担任项目经理**xxx指标数据 —— 期望 perNo=userId **且** perRole=[项目经理]
- **张三担任测试经理**的xxx指标数据 —— 期望 perNo=张三认证号 **且** perRole=[测试经理]

三个设计点（1/2 的正则均为**前端维度键配置可动态添加**，见 §3.1c）：

1. **"我担任" 触发 myself**：现有 MYSELF 正则 `(?<![一-龥])我(个人|本人)?(?![一-龥组们的])`
   对 "我担任" 不命中（"我"后跟中文）→ perNo 拿不到 → 台账行拿不到。扩展方式：
   **perNo 配置行追加 myself 变体正则条目**（§3.1c 统一规范；首版 seed
   `我担任|我现任|我所担任` → myself=true，语义=裸我+角色声明）；后续业务发现
   新场景（"我分管""我负责"…）在维度键页直接补条目，TTL 内生效、无需发版。
2. **角色值提取**：提取正则同样**放 perRole 配置行**（首版 seed
   `担任([一-龥]{2,10}?)(?=[的，。？?！!、\s]|$)`，取第一捕获组），再用
   **台账角色字典**（Q4：`SELECT DISTINCT "岗位角色"`，TTL 同姓名字典 30min）
   归一校验——捕获值在字典中有**包含关系命中**（字典值 `测试经理` ⊇ 捕获 `测试经理`
   或反向）才收，收字典标准值；字典不可用 → 捕获值原样收（fail-open，脚本侧自查）。
   字典即值域，无需静态词表。
3. **合并语义（显式优先，不并台账）**：问句显式提及角色 → `perRole = 显式值`
   （**覆盖**，不追加 ledger.roles）；未显式提及 → `perRole = ledger.roles`（随人填充）。
   理由：显式角色是**行过滤声明**（"张三担任测试经理的指标" = 只要张三角色行中
   测试经理那部分），并集会把 ledger 的其他角色（应用测试等）AND 进来造成过度过滤/扩
   集，语义错误。显式与台账冲突（台账=应用测试，问句=测试经理）→ 信问句 + log
   （台账可能滞后）。

### 3.1c 正则配置承载（2026-10-26 补：正则前端可动态添加）

统一规范见 **我X按需注入与作用域重锚方案.md §8**（全部我X正则动态配置化，
perRole 是其中一部分）：regex 型 alias 条目
`{"alias":"<正则串>","value":"<标签>","type":"regex"}`，**正则放它触发的目标键行**。
本方案涉及两行：

| 键行 | value 标签 | alias（正则串） | 语义 |
|---|---|---|---|
| perNo | `myself` | `我担任\|我现任\|我所担任` | 命中 → myself=true（补现有 MYSELF 正则缺口） |
| perRole | `extract` | `担任([一-龥]{2,10}?)(?=[的，。？?！!\s、]|$)` | 第一捕获组 = 显式角色值（§3.1b 归一） |

运行期语义：

- **加载**：`DimensionKeyConfigRepository.findAllEnabled()`（既有 TTL 缓存）取
  perNo/perRole 行 → 按 value 标签分组 → `Pattern.compile`；**TTL 内热生效，
  业务发现新场景随时补条目，不用发版**（用户拍板需求）；
- **标签未知/正则非法**：跳过该条目 + log（compile 失败不致命，其余条目照用）；
- **兜底**：行缺失 / aliases 空 → 代码内置默认 seed 同款正则（§4.2 seed 保证行
  存在，此为防御）；
- **seed 灌入**：随 §4.2 BUILTIN seed 落库（JSON 中 `\s` 等写成 `\\s`，与既有
  aliases seed 同序列化路径）；
- **同义词路径过滤**：regex 型条目对既有词表匹配不可见（`isSynonym()` 过滤，
  我X方案 §8.1 安全约束），只在 resolver 显式提取路径消费。



### 3.1d 无关键字角色识别（2026-10-26 补：字典扫描 + 人锚共存）

例句：**张三项目经理**的xxx指标 —— 无"担任"关键字，角色值直接跟在人名后。
§3.1b 的 extract 正则（担任…）对此不命中。识别逻辑改为**两路径并行，命中即收**：

- **路径A 关键字提取**（§3.1b 既有）：perRole 配置 `extract` 正则取捕获组
  → 字典归一；
- **路径B 字典扫描**：**Q4 台账角色字典值逐个在问句 `find()`**（最长优先：
  "测试经理"先于"经理"消歧；命中 span 屏蔽防重叠计数）→ 命中的字典值即候选。
  字典即值域，运行期 DISTINCT，**无关键字也能认出角色**，且值域自动跟随台账。

路径B 两道防误伤闸门：

1. **人锚共存**：仅当问句存在人锚（myself 命中 ∪ 人名扫描命中）才启用——
   "张三项目经理"有 张三 锚 → 收 [项目经理]；"应用开发人员的达标率"（无具体
   人，§7-4）不收，按角色全量查询边界不破；
2. **命中 span 屏蔽**：角色命中区间先屏蔽再做人名扫描/组名匹配（与粒度词屏蔽
   同机制）——防"张三项目"被人名 2~4 字窗口吞、"测试经理"被统计组词匹配吞。

其它：

- 字典空 / 查询失败 → 路径B 自然禁用（无值可扫，fail-safe）；
- 误收兜底：角色值是业务名词，人锚共存已把识别面收窄到"这个人的角色声明"；
  "张三的需求分析指标"型真歧义（指标名 vs 角色）→ 收角色 + log（fail-open
  同 §3.1b，脚本侧按 perNo 自查可纠）；
- **R2 联动**：显式角色提及判定 = 路径A ∪ 路径B 命中（§3.3 同口径）。



### 3.2 填充时机（随人填充与 perNo 产生点同构；显式提取见 §3.1b/§3.1d）

| 场景 | perNo 产生方式 | perRole 填充 |
|---|---|---|
| 我担任项目经理… | "我担任"→myself → perNo=userId | **显式值 [项目经理] 覆盖**（ledger 不追加） |
| 张三项目经理…（无关键字） | 扫描唯一 → byName | **路径B 字典扫描 [项目经理]**（人锚共存，§3.1d） |
| 张三担任测试经理… | 扫描唯一 → byName | **显式值 [测试经理] 覆盖** |
| 裸我（"我的达标率"） | myself → perNo=userId | Q1 byUserId → `ledger.roles` 追加 |
| 人名唯一命中（"张三的达标率"） | 扫描 → byName 唯一身份 | 该身份 `identity.roles` 追加 |
| 重名反问补参轮（回复序号/部门） | chosen identity | `withResolvedPerson`：本轮有显式值 → 保留显式；否则 chosen.roles |
| 人名重名未确认 | 无 perNo | 显式值仍收（角色提取独立于人确认）；ledger 不填 |
| 我部/我组/我的应用/我的产品线 | perNo 不产生 | 仅问句显式提角色时收显式值；ledger 不填（§7-1） |

要点：**随人填充的值与 perNo 同源同批**（Q1/Q2 一并带出角色列，不新增查库）；
**显式值独立于 perNo**（"我部担任项目经理的指标" 型无具体人也收角色——§7-4 的
按角色查询场景在直接执行轨顺带覆盖）。填充代码放既有 perNo 落点位。

### 3.3 与 R2 重锚抑制 / L3 补缺收窄的联动

- **R2**：重锚抑制的「人」行清空 `perName/perNo/persons` → 同步清 `perRole`
  （角色是人的派生值，人被清角色必清）；**显式角色提及独立判定**：
  问句提取/字典扫描命中（§3.1b 路径A / §3.1d 路径B，显式值在抑制前已落
  extraction）→ `perRole` 保留，与人维度判定解耦（"人名重名未确认"轮显式角色
  仍收，同口径）。完整判定：`perRole` 被清 ⟺ 人未提及 **且** 显式角色未提取。
- **L3**：`FINE_GRAINED_DIM_KEYS` 追加 `perRole` —— 快照补缺一律不补
  （角色跨轮补进来同样几乎总是错的：人都不在了角色无意义）。

### 3.4 LLM 回退轨

主场景仍是直接执行（param_mapping 绑 `perRole`）。LLM 轨首版**不注入**岗位角色
（与 perNo 同口径：LLM 轨只注入重名提示行，不承载参数契约）——见 §7-3。

## 4. 生效层（改动清单）

### 4.1 数据层 PersonLedgerRepository

- Q1/Q2 SQL 增列 `"岗位角色"`；`PersonLedgerRow` 增 `roles` 字段（distinct 多值），
  `PersonIdentity` 增 `roles` 字段（按 perNo 合并时 distinct 累积）；
- `mergeByUser` / `mergeIdentity` 同步合并 roles；缓存结构不变（TTL 30min 照旧）；
- Q3 姓名字典不变；
- **Q4 角色字典（新增）**：`SELECT DISTINCT "岗位角色"` → `Set<String>`，
  TTL 30min（同姓名字典）+ 失败关（返回 null，提取侧 fail-open）；
  承载问句侧角色提取的值域归一（§3.1b），不新增连接池（复用 Q1/Q2 同源）。

### 4.1b 问句显式提取（PersonalDimensionResolver）

正则全部来自 perRole 配置行（§3.1c），resolver 侧只做编译与应用：

- **加载**：注入 `DimensionKeyConfigRepository`，findAllEnabled TTL 快照中取
  `key=perNo`（myself 变体）与 `key=perRole`（extract 提取）两行 → aliases 按
  value 标签分组编译；compile 失败跳过 + log；行缺失 → 内置默认兜底；
- **myself 变体**：任一 `myself` 正则 `find()` 命中 → `myself=true`
  （**不并入**现有硬编码 MYSELF 模式——核心 裸我/我个人/我本人 保持不变，
  变体是配置层叠加，避免负向断言互相误伤）；
- **extractExplicitRoleByPattern(question)**（路径A）：逐条 `extract` 正则 find，
  取第一捕获组（多条命中 → 先到先得）→ Q4 字典包含关系归一（字典值 ⊇ 捕获 或
  捕获 ⊇ 字典值 → 收字典标准值）；字典不可用/无命中 → 捕获值原样收（fail-open）；
  无命中 → 空；
- **extractExplicitRoleByDictionary(question, anchors)**（路径B，§3.1d）：Q4
  字典值按长度降序逐个 find，命中 span 屏蔽防重叠；入参 `anchors` =
  人锚集合（myself ∪ 人名扫描产物），**anchors 为空直接返回空**（§7-4 边界闸门）；
  命中值已是字典标准值无需归一；字典空/查询失败 → 返回空（fail-safe）。

### 4.2 内置键注册（第 10 → 11 键）

- `DirectSkillExecutor.DIMENSION_KEYS` 加 `"perRole"`；
- `DimensionKeyConfigRepository.BUILTIN_KEYS` 加 seed 行（builtin=true），
  aliases seed = §3.1c `extract` 正则条目（JSON 内 `\s` 写 `\\s`）；
  **perNo 行 aliases seed = `myself` 变体条目**（我担任|我现任|我所担任）；
  perRole 与 perNo 一并 **加入** `VOCAB_EDITABLE_BUILTIN_KEYS`（正则配置需页面
  可编辑，总计数 3 → 8，见我X方案 §8.3）；
- `DimensionExtraction` 加第 14 字段 `perRole`（13 参 legacy 构造保留，补 14 参）；
- `valuesFor("perRole")` → `extraction.perRole()`；
- 测试计数对齐：activeKeys 14/17 → 15/18、BUILTIN_KEYS 10 → 11（seed/backfill 索引）。

### 4.3 plan 填充点（DirectSkillExecutor，注意顺序）

1. **路径A 关键字提取（最先，无需人锚）**：plan 内
   `resolver.extractExplicitRoleByPattern(question)` → 非空则 perRole 占位
   ——后续随人填充全部"显式值已存在则跳过"（覆盖语义实现方式）；
2. `enrichPersonal`：`personal.myself()` 分支 → `perRole += ledger.roles()`
   （显式值已占位则跳过）；
3. `applyPersonalDimensions` 人名扫描唯一命中分支 → `perRole += identity.roles()`
   （与 perNo 同点位追加；显式值已占位则跳过）；
4. **路径B 字典扫描（人名扫描后、重锚抑制前）**：人锚此时齐备
   （myself ∪ scannedNames）→ `resolver.extractExplicitRoleByDictionary(
   question, anchors)` → 命中则**覆盖**此前 perRole（显式 > ledger；与路径A
   并存时合并去重）——"张三项目经理"在此落值；
5. `applyReanchorSuppression`：显式角色提及判定 = 路径A ∪ 路径B；
6. `consumePersonPending` → `withResolvedPerson` → `perRole += chosen.roles()`
   （本轮有显式值 → 保留显式，否则 chosen.roles）。

均不新增查库（Q1/Q2 已带出角色列；Q4 字典仅路径A 归一 + 路径B 扫描用，TTL 缓存）。

### 4.4 R2/L3 联动点

- `applyReanchorSuppression`：人维度未提及 → 清单加 `perRole`；
- `FINE_GRAINED_DIM_KEYS` 加 `"perRole"`。

## 6. 兼容性/风险

- **指纹稳定**：perRole 不进指纹/继承（同 perNo 口径），存量会话无迁移问题。
- **兼岗多值**：同 perNo 多行角色 distinct——脚本收多值 List 过滤（schema type=array
  时恒传 List，direct-exec-param-type-plan §2.2 既有机制）。
- **多人配对丢失**："张三和李四" → perNo=[a,b]、perRole=合并去重，**人-角色配对不保证**
  （过滤型维度语义，脚本 `role IN (...)`；人少场景可接受，精确配对留给脚本按 perNo 自查）。
- **重名反问展示**：displaySuffix 可选带角色后缀"张三（杭州开发一部 / 应用开发）"辅助消歧
  —— 建议做（零成本），见 §7-2。
- **降级契约**：角色列 NULL / 台账查无 / 查询失败 → perRole 空，不阻塞（照抄 §3.5）。
- **skill 侧**：按角色过滤的脚本 param_mapping 绑 `perRole` + params_schema 声明
  （array 恒 List）；demo 观察可在 q2_1_dual_time_demo 加 perRole 回显（实施时顺手）。

## 7. 待拍板点

1. **我X 维度命中是否连带填 perRole**：我部/我组等也走 byUserId（同一 ledger 行有角色），
   但此时 perNo 并不作为查询参数传入。建议**不填**（严格"获得 perNo 才填"，避免
   "我部"带出一个无消费方的角色值）；若业务想要"我部+我的角色"语义再放开。
2. **重名反问 displaySuffix 是否带角色**：建议带（辅助消歧，改一处拼接）。
3. **LLM 回退轨是否注入**：建议首版不注入（主场景直接执行全覆盖，回退轨维持最小）。
