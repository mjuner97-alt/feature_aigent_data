Skill 一二三级关键词检索收窄：池级收窄 → 按 skill 自身配置层级的 AND + 双轨并存

Context

现状（docs/202610/skill-retrieval-logic.md §7.3/§8.4）：SkillCandidateSelector 阶段一是池级收窄——任一 skill 在某层命中，就淘汰"配置了该层却未命中"的其他
skill（narrowByLevels）；且阶段一一旦有层级命中，只配 domain+keywords 的存量 skill 全部出局（拍板⑥）。

两个问题（用户 2026/10/22 拍板）：
1. 层级命中是跨 skill 联动的，语义反直觉；应改为按 skill 自身：配了几层，每层都必须有词条命中问题（AND），不满足 → 完全出局（显式点名豁免）。
2. 存量 skill（仅领域标签+关键词，未配层级）被层级命中挤出 → 改双轨并存：层级 skill 按 AND 判定、存量 skill 按旧 domain+keywords 判定，两边各自命中都进目录，层级满足者排前。

关键发现：分组保底（FALLBACK_MARKER）机制与严格 AND 天然兼容（L2/L3 含「保底」且上层命中 → 注入命中 → AND 满足），SkillCandidateSelectorFallbackTest 9 个测试无需改动。

实现步骤

1. 重写 selectInternal 的分流与合并（删两阶段硬切，改单池合并）

现结构（SkillCandidateSelector.java:89-172）：explicitPool / levelPool / restPool 三池 → levelPool 非空走 narrowByLevels + 阶段一排序，否则走阶段二叶层回退。

新结构：

遍历 active metadata:
显式点名 → explicitPool（不变）
else 计算 l1Terms/l2Terms/l3Terms + injectFallbackHits（不变）
有层级配置（L1∨L2∨L3 任一数组非空）:
AND 判定: 每个非空层都必须有命中词（l1Terms/l2Terms/l3Terms 对应非空）
全命中 → levelQualified 池
任一配置层未命中 → 直接丢弃（完全出局, 不落叶层回退）
无层级配置（三层全空 = 存量轨）→ restPool（原 restPool 只收这类 skill）

合并打分（单一列表, 单一比较器）:
explicit: depth=4, rank=0, partial=false（不变）
levelQualified: depth = 命中层深度(1/2/3), rank = bestGlobalRank, partial = 配置了叶层 keywords 但零命中
restPool: 原 §8.4 阶段二逻辑原样保留（domain 互斥过滤 + domainScore+keywordScore 取负进 rank, depth=0, partial=false）
排序: explicit desc > depth desc > globalRank asc > name（depth 天然分层: 层级轨 1-3 排存量轨 0 前）
finish() 截断两档逻辑不变（hadFallback = 榜首 partial）

具体删改点：
- 删 narrowByLevels / narrowAtLevel（SkillCandidateSelector.java:227-245）；
- 删"levelPool 非空→阶段一 / 空→阶段二"的 if/else 硬切（:125-146 与 :146-171 合并为一个 scored 列表 + 一次 sort）；
- 阶段二循环体（:147-167 的 domain 过滤 + 打分）原样搬进合并循环，仅作用对象从 restPool 语义收窄为"三层全空的存量 skill"；
- partiallyMatched（:311-317）删前三个层级子句（AND 已在入池前强制，层级子句恒 false，保留会误导），只留叶层子句 !keywords.isEmpty() && keywordHits==0；
- 类 javadoc（:16-39）改写：两阶段描述 → AND 语义 + 双轨并存 + 保底注入不变；
- 保底注入 injectFallbackHits（:286-298）零改动。

2. AND 判定细节

- "该层已配置" = entry.levelXKeywords() 非空（含保底保留字的层也算配置，其命中由注入机制供给——与现状一致：纯保底层在旧逻辑同样无法靠文本命中入池）。
- L1/L3 配置、L2 留空 → 只要求 L1 与 L3 命中（未配置层不设要求）。
- 保底注入在 AND 判定之前执行（现顺序已是），L2=[保底]+L1 命中 → L2 视为命中。
