# 版本计划 / 季度互不换算方案

> 2026/10/21 · 背景：双时间键脚本（同时支持版本计划与季度维度）收到互相矛盾的取值。
> 规则一句话定稿：**已知其一，不换算其二**。

## 1. 问题与复现

问题原文：

```
使用 q2_1_script_then_download_demo skill查询 杭州三部 F-GCMS-PSN、F-ATP-INNER 12月版Q1完成率是多少
```

dimension_extract 面板输出（节选）：

```json
"extraction": { "versionPlan": ["2026年12月份版本"], "vestQuarter": [], ... },
"resolved": {
  "versionPlan": ["2026年12月份版本"],
  "vestQuarter": ["2026年4季度"],          ← 从版本换算出来的
  "versionPlan.start": ["2026-11-15"], "versionPlan.end": ["2026-12-13"],
  "vestQuarter.start": ["2026-09-20"], "vestQuarter.end": ["2026-12-13"]
}
```

用户显式说的是「12月版」（版本计划），季度 `2026年4季度` 是 Java 从版本值**换算**出来的。
当 skill 的 param_mapping 同时映射两个时间家族时（脚本同时支持版本/季度两种入参），
换算值会随显式值一起传给脚本，脚本若对两个时间入参取并集/交集，结果就错。

## 2. 规则定稿（拍板口径）

| # | 用户问题显式提及 | 脚本收到 |
|---|---|---|
| R1 | 版本计划（标准值「12月版」/ 变体「今年以来→YEAR_V」「当前·在建版本→THIS_V」「近半年→LAST:6V」「延后版→DELAYED」） | 只传版本计划值 |
| R2 | 季度（标准值「2026年4季度」「Q1」/ 变体「当季·在建季度→THIS_Q」） | 只传季度值 |
| R3 | 都未提及 | 默认在建版本计划，只传版本计划值 |
| R4（核心） | 提及其一时 | **不换算出另一值**，另一个时间参数不传 |
| R5 | 季度与版本计划**并存**（如「2026年4季度11月份版本」） | 默认仅传版本计划（2026年11月份版本），季度丢弃 |
| R6 | 问题含**需求项/需求子条目**且未显式提及时间 | 两个时间维度都不传默认在建版本，传给脚本的值为空（需求项脚本按需求项全历史口径自查）；显式提及时间则正常传该时间 |

即：换算（版本→季度）只允许发生在「用户显式提及版本、而脚本只认识季度」的**单侧时间键**
skill 上（skill 作者明确声明脚本只说季度语言）；一旦脚本两个时间家族都声明了，就按
显式提及二选一，谁都没说就走默认版本。

## 3. 换算点清单（代码现状）

换算是**单向的**：版本 → 季度（反向 quarter→version 不存在，versionPlan 取值只读
`extraction.versionPlan()` + 在建版本默认）。全部换算点都在 `DirectSkillExecutor`
params 层，提取层（DimensionStateManager）本身是 TimeDimension 二选一，不产双值：

| # | 位置 | 行为 |
|---|---|---|
| C1 | `valuesFor("vestQuarter")` | `vestQuarter` 为空时 `deriveQuarters(expandVersionValues(extraction.versionPlan()))` —— 从版本值换算季度 |
| C2 | `quarterEdge("vestQuarter.start"/".end")` | 季度列表为空时从展开后的版本值推算季度窗口 |
| C3 | `defaultTimeValues("vestQuarter")` | 都未提及时 `deriveQuarters(currentVersionsSafe())` —— 默认在建版本换算成季度 |
| C4 | `VersionPlanAnchorResolver` 的 THIS_V/YEAR_V/LAST:nV/DELAYED/THIS_Q 展开 | **不算换算**（用户显式提及的锚点按火车日历展开，R1/R2 的正当路径），不动 |

## 4. 方案选项

### 方案 A：双时间键 skill 抑制换算（已实施，2026/10/21）

`buildParams` 增加 `timeFamilyLoserKeys()`：仅当 param_mapping **同时**含
versionPlan 家族（`versionPlan` / `.start` / `.end`）与 vestQuarter 家族（`vestQuarter` /
`.start` / `.end`）时，按 R1–R3 定唯一胜者，败者家族（含后缀键）整体抑制：

- `extraction.vestQuarter()` 非空（R2，含 THIS_Q）→ 胜者季度，抑制 versionPlan 家族；
- 否则（R1/R3）→ 胜者版本，抑制 vestQuarter 家族（C1/C2/C3 对双家族 skill 不再生效）。

单侧时间键 skill（只映射 versionPlan 或只映射 vestQuarter）**不干预**：
`vestQuarterDerivedFromVersionValuesWhenQuarterMissing`（版本问题 → 季度专用脚本，
从版本换算季度）既有拍板口径保持不变。

- ✅ 修掉本 bug（冲突只可能发生在双时间键脚本上）
- ✅ 改动面最小（`buildParams` 一处，plan 与歧义补参轮共用自动生效）
- ⚠️ 规则不是全局的：换算仍然存在于单家族 skill —— 但单家族只传一个参数，**构不成冲突**

### 方案 B：全局禁换算

把 C1/C2/C3 全部删掉：任何时候已知版本就不换算季度，季度键无值即缺参（走反问/回退）。

- ✅ 规则最简、最可解释（「维度之间永不换算」）
- ❌ 回退既有拍板（口语值方案的「版本推算季度」口径），季度专用脚本遇到版本问题从
  「自动换算出答案」退化成「反问请补充季度」，UX 变差
- ❌ 改动面大（3 处换算点 + 既有单测改语义）

### 结论

**推荐方案 A（已实施）**。理由：冲突的必要条件是「两个时间参数同时传给脚本」，
方案 A 恰好只在该条件下禁换算，覆盖 R1–R4 的全部可观察行为；方案 B 的额外收益
（规则全局纯化）没有对应的实际问题，却要付出 UX 回退。若后续出现「单家族 skill
换算出错误季度」的实际案例，再升级 B（升级路径清晰：删 C1/C2/C3）。

## 5. 变体锚点覆盖说明（为何 R1/R2 天然覆盖词表变体）

二选一判定读的是 `extraction.versionPlan()` / `extraction.vestQuarter()` 字段，
而全部变体在提取层上游就已落入这两个字段（`DimensionStateManager.analyzeQuestionRuleBased`
词表合并，:627-644），与值的形态无关：

| 词表变体 | 锚点 | 落点 | 判定 |
|---|---|---|---|
| 今年以来 / 全年 / 各月度版本 / 每月 / 各版本 | YEAR_V | versionPlan | 版本胜 |
| 上半年 / 下半年 | HALF_V:1 / HALF_V:2（可带 @yyyy） | versionPlan | 版本胜 |
| 近半年 | LAST:6V（近 N 个版本正则同路） | versionPlan | 版本胜 |
| 目前 / 当前 / 现在 / 本月 / 当月 / 近期 / 在建版本 | THIS_V | versionPlan | 版本胜 |
| 延后版 | DELAYED | versionPlan | 版本胜 |
| 当季 / 在建季度 | THIS_Q | vestQuarter | 季度胜 |

版本与季度变体并存时（如「12月版Q1」「2026年4季度11月份版本」，R5），TimeDimension
二选一**版本优先**（:634），季度不进 extraction —— 双时间键 skill 自然只传版本。
锚点展开（C4）执行期照常发生，胜者的值是展开后的
具体版本/季度值（THIS_V → 在建版本列表，THIS_Q → 季度值）。

## 6. 已实施记录（方案 A，2026/10/21）

- `DirectSkillExecutor.java`：`buildParams` 循环前算 `timeFamilyLoserKeys(mapping, extraction)`，
  命中败者家族的 dimKey 直接 skip（抑制发生在 defaultTimeValues 兜底之前，C1/C2/C3 连带失效）；
  `plan` 与歧义补参轮（consumePending 复存 mapping+schema 重跑 buildParams）自动共用
- **R6 特例（同日补充）**：`buildParams` 另算 `requirementWithoutExplicitTime(extraction)` ——
  extraction 含 itemNo（需求项）/ subItemNo（需求子条目）且 versionPlan/vestQuarter 均空时，
  跳过 defaultTimeValues 兜底（C1/C2 因 versionPlan 空本就无源），时间参数整体不传。
  规则跟问题走不跟 skill 走：单家族版本 skill 同样不补默认（+3 单测，全量 593 过）
- `DirectSkillExecutorTest`：+5 用例 —— 双时间键提及版本只传版本（含 qStart/qEnd 抑制）、
  提及季度只传季度、都未提及默认在建版本、THIS_V 锚点版本胜（展开 2026年10月份版本）、
  THIS_Q 锚点季度胜（展开 2026年4季度）
- `DimensionStateManagerRuleTest`：+1 用例（R5 并存场景：「2026年4季度11月份版本」→
  VERSION 类型、仅 2026年11月份版本，季度丢弃 —— 行为本就正确，测试锁死）
- 全量 587/587 过（BUILD SUCCESS）；同日另一修复：应用维度多值收集（`F-A、F-B` 全收集，
  DimensionStateManagerAliasIntegrationTest +2）
- 两个修复均未提交，待内网 E2E 后一并提交

## 7. 测试要点（E2E，内网）

1. 双时间键 skill：问题只提「12月版」→ 脚本入参只有 version（无 quarter/qStart/qEnd）
2. 双时间键 skill：问题只提「当季」→ 入参只有 quarter（值 = THIS_Q 展开的季度值）
3. 双时间键 skill：问题不提时间 → 入参只有 version（全量在建版本）
4. 变体：「今年以来」「近半年」「延后版」→ 只传 version，值为锚点展开结果
5. 季度专用 skill（只映射 vestQuarter）：问题提「12月版」→ 仍自动换算 quarter（方案 A 不干预）
6. 单版本 skill（只映射 versionPlan）：行为与现状完全一致（回归面为零）
