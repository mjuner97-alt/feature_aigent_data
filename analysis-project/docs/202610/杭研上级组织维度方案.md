# 杭研上级组织维度方案

> 2026/10/22 · 背景：「使用 q2_1_script_then_download_demo skill查询 杭研7月的完成率」
> 报缺部门参数。杭研是部门的**上级组织**（不是具体部门）。
> 拍板（简化版，弃「deptName 组别名展开」方案）：**新增动态键 `orgName`（杭研维度），
> 词表页面可配；问题命中 orgName 时，缺部门不反问，直接执行**。

## 1. 拍板口径

- `dimension_key_config` 新增动态键（页面「新增维度键」即可，零代码 seed）：
  - 维度键 `orgName`，展示名「杭研维度」
  - 词表：`杭研→杭研`、`杭州研发部→杭研`、`研发部→杭研`、`基地→杭研`（后续变体页面随意加）
- 行为：问题命中 orgName 词表 → `extraction.extraDimensions["orgName"]` 非空
  （双轨动态键既有机制，仅当前问题提取）→ 直接执行缺参判定对 `deptName` 必填
  **跳过反问**，plan 直接执行；dept 参数不传，脚本按缺部门自行决定查询范围。
- 需要脚本拿杭研原值的，param_mapping 绑 `"参数名": "orgName"` 即可透传（动态键
  已并入 param_mapping 合法集，valuesFor 走 extraDimensions 默认分支）。

## 2. 实现记录（2026/10/22）

- `DirectSkillExecutor.java`：新增常量 `ORG_DIMENSION_KEY = "orgName"`；`plan()` 必填
  缺失循环中，`mapping.get(req) == "deptName"` 且 extraDimensions 的 orgName 非空时
  跳过反问（log 后 continue）。注意该检查在 `conversationId == null` 回退分支之前
  ——无会话键也照常放行（不反问本来就无需 pending）。
- `DirectSkillExecutorTest` +2：`orgKeyHitSkipsMissingDeptAsk`（杭研7月完成率 →
  missingAsk 空、dept 不传、org 透传「杭研」）、`noOrgKeyStillAsksForMissingDept`
  （对照：未命中词表仍反问 deptName）。全量 651 过。

## 3. 配置与脚本侧注意

- **页面配置**（管理员，维度键字典页新增）：
  ```
  维度键 orgName | 展示名 杭研维度
  词表: 基地→杭研, 研发部→杭研, 杭州研发部→杭研, 杭研→杭研
  启用 ✓
  ```
- **脚本 schema**：若 skill 的 params_schema 里 `dept` 仍标 `required=true`，
  script_exec 的必填校验（ScriptExecTool checkRequiredParams）会拦下缺 dept 的执行
  ——要把 dept 改为非必填，脚本内自行处理「无 dept = 查全部/按上级组织口径」。
- **快照兜底不受影响**：followup §3.5 的必填快照继承先于本判定，上轮带过 dept
  时仍会继承（继承后 params 含 dept，本判定根本不触发）。
