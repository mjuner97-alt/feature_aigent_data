# 版本/季度/部门口语值处理方案

> 状态：设计稿 v2（2026-10-19，未实施）。
> v2 修订：① 季度是独立维度，**不做季度→月度版本展开**；② "X月延后版"是**标准值**
> （与"X月份版本"同级，字面归一目标），不是特殊语义查询；③ 口语词表落到**维度键字典页面可维护**。
> 用途：补齐内置键（versionPlan / vestQuarter / deptName）的口语值覆盖，并把
> dimension-key-dynamic-dimension-plan.md §6.1 暂缓的 `LAST:{n}V/{n}Q` 落地。
> 上游底稿：`docs/202610/dimension-key-dynamic-dimension-plan.md`（§1 双轨模型、§4 拍板、§5 波及面清单）。
> 本文"§N"默认指该底稿章节。

## 1. 口语值三分类（设计总纲）

需求清单（2026-10-19 业务提供）里的口语值，按处理机制分三类，**不要混在一条链路里做**：

| 类别 | 特征 | 例子 | 处理机制 | 落点 |
|---|---|---|---|---|
| A 字面归一 | 结构固定（年/月/季度数字排列），可用正则穷举 | 十月版、202610版本、10月份版、X月延后、杭二 | 正则归一为标准值 | `DimensionStateManager`（已有模式扩展，代码） |
| B 词表别名 | 封闭小词表，业务可能增删 | 杭一、今年以来、当季、近期、延后版 | 词表消解（alias → 标准值或锚点） | **`dimension_key_config` 内置键 alias 行，字典页面可维护** |
| C 语义锚点 | 值随"今天"或日历变化，必须执行期算 | 今年以来(YEAR_V)、近3个版本(LAST:3V)、当季(THIS_Q)、在建版本(THIS_V) | 锚点 DSL + 日历解析 | 新 `VersionPlanAnchorResolver`（timeRange 同构） |

B 类词表存 `dimension_key_config` 内置键的 aliases 列（新增能力，见 §3.6），
其中指向锚点的行（C 类）执行期经 resolver 展开，指向标准值的行（纯 B 类）直接进状态。
**数字形态的变体（近N个版本、近N个月、X月延后、X季度）一律正则**，词表只收封闭短语。

## 2. 现状盘点（已有什么、缺什么）

### 2.1 部门（deptName）

已有：`EXPLICIT_DEPT` 正则 + `normalizeDepartment` switch（DimensionStateManager.java:283-302），
覆盖 `杭州一部/一部/服务支持/技术部/云计算/实验室` 等 14 个别名；
2026-10-27 补 `杭州产品赋能团队/产品赋能团队/赋能团队`（标准枚举同步进
`VersionPlanAnchorResolver.DEPT_STANDARD_NAMES` 词表校验白名单）。

**缺口**：`杭一/杭二/杭三…`（去"州"极简形）不在正则里。

### 2.2 版本计划（versionPlan）字面归一

已有正则（DimensionStateManager.java:273-280）：
- `EXPLICIT_VERSION`：`(?:(\d{4})年)?(\d{1,2})月份版本` — 吃 "10月份版本"
- `EXPLICIT_MONTH`：`(?:(\d{4})年)?(\d{1,2})月份?(?!版本)` — 吃 "10月"/"10月份"，归一为 "{y}年{m}月份版本"
- `EXPLICIT_QUARTER` / `EXPLICIT_QUARTER_ALIAS`：`X季度` / `一季度`（裸 `Q1`~`Q4` 已于 2026-10-22 移出季度解析，见 §2.4a）

**缺口**（正则没吃到的写法，均为 A 类）：
| 口语词 | 归一目标 |
|---|---|
| 十月版、十一月版、十二月版 | 中文数字月份无正则 |
| 202610版本、202610 | 紧凑 YYYYMM 无正则 |
| 10月份版、2026年10月版、2026年10月份、2026年10月版本 | "月份版"/"年10月版" 等半截后缀 |
| 10月延后、10月份延后 | "X月延后" → "2026年10月延后版"（**标准值**，日历里与月份版本同级的独立版本计划） |

### 2.3 版本计划语义锚点

§6.1 预留了 `LAST:{n}V/{n}Q` 锚点但**本期暂缓**（保存期校验直接拒绝）。
需求里的 今年以来 / 上半年 / 下半年 / 近x个版本 / 近半年 / 近X个月 / 在建版本 全部属于这一类，本文正式落地。

### 2.4 季度（vestQuarter，独立维度，不转版本）

已有：`X季度/一季度` → `{y}年{n}季度`；缺省"当前在建季度"由
`VersionPlanKnowledgeHook.deriveQuarters(currentVersions())` 推算并注入 prompt（仅 LLM 路径）。

**缺口**：`当季/在建季度` 无提取（→ `THIS_Q` 锚点）。

**§2.4a 裸 Q1~Q4 移出季度解析（拍板 2026-10-22）**：QI卡口 指标值本身就叫
Q1/Q2/Q3/Q4（Q1卡口 等），与季度口语值撞词。`EXPLICIT_QUARTER_ALIAS` 与
`TIME_MASK_SPAN` 均不再认裸 Q 形态，季度只认 `X季度`/`一季度`~`四季度`；
裸 Q1 交给词表按卡口（qGate）维度解析。
**拍板（2026-10-19）**：季度是独立维度，**季度值不展开为月度版本**；按季度取数的脚本
param_mapping 配 `vestQuarter`，按版本取数的脚本配 `versionPlan`，各取各的，无转换。

### 2.5 日历数据源

`rdc_train_calendar`（gauss）：`火车开始时间 TIMESTAMP / 版本计划 / 火车类型 / 常规投产日 DATE`。
`VersionPlanKnowledgeHook.VERSION_PLAN_SQL` 已有"在建窗口"rank 查询 + TTL 缓存（30min）+ 失败保陈旧值。
**每个版本的时间窗口 = 该版本所有火车的 `MIN(火车开始时间) ~ MAX(常规投产日)`**
（延后版在日历里同样有火车行，窗口口径相同）。

### 2.6 维度键字典页面

`DimensionKeyPage.vue` 现状：内置 8 键整行只读（label/词表都不可编辑），
仅非内置键可编辑 alias 行；`DimensionKeyConfigRepository.update` 带 `WHERE builtin=FALSE`。
timeRange 保留行（builtin=FALSE）已走通"词表页面维护 + 保存校验"模式。

**缺口**：内置键 versionPlan/vestQuarter/deptName 的口语词表无处维护（本期需求核心之一）。

## 3. 机制设计

### 3.1 锚点 DSL（扩展 timeRange 的白名单体系）

锚点挂在 `versionPlan` / `vestQuarter` 两个内置键上（**不新增动态键**，走内置轨）。
`TimeRangeResolver.CONFIG_ANCHOR` 白名单放开 `LAST:{n}V/{n}Q`（§6.1.2 暂缓项正式转正），
版本专用锚点归 `VersionPlanAnchorResolver` 校验：

| 锚点 | 语义 | 展开（执行期，日历驱动） |
|---|---|---|
| `THIS_V` | 在建版本 | `currentVersions()` 全量在建列表（同现有缺省拍板，多在建不漏查） |
| `THIS_Q` | 在建季度 | `deriveQuarters(THIS_V)`（vestQuarter 专用） |
| `YEAR_V` | 当前年 1月版~12月版 | 12 个 `{y}年M月份版本`（y=执行期当前年） |
| `HALF_V:{1\|2}` | 上/下半年 | 1-6 月版 / 7-12 月版 |
| `LAST:{n}V` | 在建版本的最后一个版本按**月序**往前推 n 个（拍板①终版） | 锚定在建最后一版按月回推 n 个标准月版名，**日历缺位月照常生成**（11月版近6个→6月~11月）；在建锚点缺失退化日历最新版 |

> 季度值（`X季度`/`THIS_Q`）**只进 vestQuarter，不展开月度版本**（§2.4 拍板）。
> `DELAYED_V` 锚点取消——延后版走 A 类正则 + B 类词表（§3.2）。

### 3.2 提取层（DimensionStateManager 扩展 + 字典词表合并）

**A 类（正则，直接出标准值，代码）**：

```
// 中文数字月份（新增 pattern）
CN_MONTH_VERSION = "(?:(\d{4})年)?([一二三四五六七八九十]{1,3})月(份)?(版本?|版)?"
   十月版→{y}年10月份版本；"十一月"优先于"十月"（最长匹配）
// 紧凑 YYYYMM（新增，词边界约束防误伤数字串）
COMPACT_VERSION = "(?<!\d)(20\d{2})(0[1-9]|1[0-2])(?=版本?|\D|$)"
   202610版本/202610 → 2026年10月份版本
// 半截后缀（扩展现有 EXPLICIT_VERSION 尾部）
10月份版 / 2026年10月份 / 2026年10月版本 → 2026年10月份版本
// 延后版（标准值，与月份版本同构）
DELAYED_VERSION = "(?:(\d{4})年)?(\d{1,2})月(份)?延后(版本?)?"
   10月延后/10月份延后 → {y}年{m}月延后版
   裸"延后版"（无月份前缀）→ B 类词表行（见下），默认指当前在建月份的延后版（拍板②）
```

**B/C 类（字典词表，页面维护，`dimension_key_config` 内置键 alias 行）**：

内置键 seed 词表行（随建表/补种灌入，页面可增删改启停）：

| 键 | alias → value | 类型 |
|---|---|---|
| deptName | 杭一→杭州开发一部、杭二→杭州开发二部…（杭X部五组） | B（标准值） |
| versionPlan | 今年以来→YEAR_V、全年→YEAR_V、今年→YEAR_V、各月度版本→YEAR_V、每个月度版本→YEAR_V、各个月度版本→YEAR_V、每月→YEAR_V、各月→YEAR_V、各版本→YEAR_V | C（锚点） |
| versionPlan | 上半年→HALF_V:1、下半年→HALF_V:2 | C（锚点） |
| versionPlan | 近半年→LAST:6V | C（锚点） |
| versionPlan | 目前→THIS_V、当前→THIS_V、现在→THIS_V、本月→THIS_V、当月→THIS_V、近期→THIS_V、在建版本→THIS_V | C（锚点） |
| vestQuarter | 当季→THIS_Q、在建季度→THIS_Q | C（锚点） |
| versionPlan | 延后版→DELAYED（裸词，执行期按在建月份定位） | C（锚点） |

> "近(\d+)个版本 / 近(\d+)个月"是数字形态，走**代码正则**产 `LAST:{n}V`，不进词表。

**合并规则**（关键）：`DimensionStateManager` 注入可选 `DimensionKeyConfigRepository`，
正则提取完成后，对 **versionPlan / vestQuarter / deptName 三个白名单内置键**扫其 alias 行
（contains 语义与动态键轨一致，命中值去重保序后并入 TimeDimension / departments）。
- 合并只发生在这三个键，其余内置键维持"字典零交互"（§4#6）；
- Repository 不可用/读失败 → 只跑正则（warn，对齐 §4#7 容错）；
- 与 timeRange 的 span 协调：timeRange L1 绝对区间（`10月1日到10月15日`）先跑并屏蔽 span，
  版本词表扫描跳过已屏蔽 span（防"10月1日"里的"1月"被词表误收）。
- 裸日期屏蔽（2026-10-27 E2E 补）：裸 "M月D日"（含可选年份前缀，`BARE_DATE_SPAN`）
  是截止日/事件日，不是版本——"杭州三部11月版、12月版10月26日到期"曾多出
  `2026年10月份版本`（EXPLICIT_VERSION/EXPLICIT_MONTH 从日期里吃出"10月"）。
  修复：`dateShieldSpans()` = absoluteDateSpans（区间/截至）∪ 裸日期 span，
  **版本正则提取（qTime 屏蔽链）与词表合并两条路径统一用它屏蔽**；裸日期不产出
  时间维度（到期日≠查询时间范围，不加 timeRange 锚点）。

**指纹与跨轮继承**：标准值（`2026年10月份版本`）与锚点原词（`YEAR_V`/`LAST:3V`）都进
`TimeDimension.values`。锚点词指纹稳定（同一说法同指纹，auto-synth 计数可累积）；
解析结果（日历展开的具体版本列表/日期）**执行期算、绝不进指纹**（同 timeRange 拍板②语义）。
跨轮继承继承的是锚点原词，第二轮日历变了按新日历解析——正确行为。

### 3.3 解析层（新组件 `VersionPlanAnchorResolver`）

新 `v2/dimension/VersionPlanAnchorResolver.java`（与 TimeRangeResolver 同构）：

```java
// 输入：锚点/标准值列表 + 当天日期
// 输出：LinkedHashMap<锚点, VersionResolution>
record VersionResolution(List<String> versions, String start, String end) {}
//   versions = 展开后的版本计划值（供裸键 versionPlan 传参）
//   start/end = 该版本集合的聚合时间窗口（供 .start/.end 后缀键）：
//               MIN(各版本 MIN(火车开始时间)) ~ MAX(各版本 MAX(常规投产日))
```

日历查询（新 `VersionCalendarRepository`，gauss JdbcTemplate，独立 TTL 缓存 30min + 失败保陈旧，
模式复用 VersionPlanKnowledgeHook）：

```sql
-- Q1: 指定版本集合的时间窗口（裸键值 / YEAR_V / HALF_V 展开产物；延后版同口径）
SELECT 版本计划, MIN(CAST(火车开始时间 AS DATE)) AS v_start, MAX(常规投产日) AS v_end
FROM rdc_train_calendar
WHERE 版本计划 IN (:versions) AND 火车类型 IN ('直接发布火车（四周）','非直接发布火车（四周）（4+4）')
GROUP BY 版本计划

-- Q2: 在建窗口前推 n 个 rank（LAST:{n}V；THIS_V 是 n=当前在建窗口的特例）
--     复用 VERSION_PLAN_SQL 的 rank 结构，窗口从 min_rank 向前扩 (n-1) 个 rank
```

裸"延后版"（词表值 `DELAYED`）定位：按当前在建月份构造 `{y}年{m}月延后版` 精确值，
进 Q1 查询；日历无该值 → 解析为空（降级契约，见下）。

**降级契约**（对齐 §4#7 容错）：日历查询失败/无数据 → 该锚点解析为空 → 参数不传 →
必填缺失回退 LLM（fail-safe，不抛错不阻塞）。`LAST:{n}V` 按月序回推生成，**日历缺位月照常展开**（版本名不依赖日历，仅 .start/.end 聚合窗口按日历命中的部分计算）。

### 3.4 传参绑定（DirectSkillExecutor.valuesFor 扩展）

后缀键模式对齐 timeRange（§6.1.6）：

| param_mapping | 语义 | 产出 |
|---|---|---|
| `{"versionPlan": "versionPlan"}` | 裸键：标准值/锚点展开后的**版本值列表** | `["2026年10月份版本",…]`（单值 String / 多值 List 由脚本 schema 决定） |
| `{"startDate":"versionPlan.start","endDate":"versionPlan.end"}` | 聚合时间窗口 | 第一个解析体的 start/end（ISO 日期） |
| `{"vestQuarter": "vestQuarter"}` | 季度值 | `["2026年4季度"]` / `THIS_Q` 解析产物 |
| `{"startDate":"vestQuarter.start",…}` | 季度时间窗口 | 季度版本集合的聚合窗口 |

**裸键 vs 锚点原词**：`valuesFor("versionPlan")` 现在直接返回 `extraction.versionPlan()`。
扩展语义：值是锚点（`THIS_V/YEAR_V/HALF_V:x/LAST:nV/DELAYED`）→ 经 resolver 展开成版本列表再传；
值已是标准值（`2026年10月份版本` / `2026年10月延后版`）→ 原样传。**锚点原词绝不透传给脚本**。

**多锚点**：`今年以来和上月比` → 两个锚点。裸键传 List（多值）；`.start/.end` 后缀键
只取第一个（同 timeRange §6.1.6"多范围对比不支持"边界，保持一致）。

**缺省逻辑不变**：`defaultTimeValues`（在建版本全量）继续服务"完全没提到时间维度"的场景；
锚点提取只覆盖"提到了口语词"的场景，两者互补不重叠。**季度不展开版本**，
versionPlan 缺省补在建版本的原有语义维持现状（§2.4 拍板撤回 v1 的展开补强）。

### 3.5 ResponseCache 绕过

锚点解析依赖"今天"+日历（同 timeRange 拍板②）：`ResponseCacheMiddleware.containsTimeRangePhrase`
扩展为同时扫描版本类锚点短语——**词表 seed 值集合（YEAR_V/HALF_V/LAST/THIS_V/THIS_Q/DELAYED
对应的全部 alias 原词）+ 正则形态（近\d+个版本/近\d+个月/\d+月延后）**，命中即不读不写。
短语集合放 `VersionPlanAnchorResolver` 公开静态（seed 常量同源），两处不各写一份。

> 字面归一（A 类，无锚点）**不绕过缓存**："10月版缺陷数"指纹与解析结果都是确定性的，可缓存。

### 3.6 维度键字典页面改造（前端 + 后端配置链路）

**页面 `DimensionKeyPage.vue`**：
- 内置键行新增"词表"编辑入口：versionPlan / vestQuarter / deptName 三键开放 alias 行
  的新增/编辑/启停/软删（key/label/builtin 标识仍只读）；其余内置键维持整行只读；
- alias 行 value 校验按键分型（前端提示 + 后端保存期双重校验）：
  - `versionPlan`：value 必须匹配 `^\d{4}年\d{1,2}月份版本$` / `^\d{4}年\d{1,2}月延后版$` /
    锚点白名单（`YEAR_V|HALF_V:[12]|LAST:[1-9]\d*V|THIS_V|DELAYED`）；
  - `vestQuarter`：value 匹配 `^\d{4}年[1-4]季度$` 或 `THIS_Q`；
  - `deptName`：value 必须在部门标准枚举内（杭州开发一~五部/杭州服务支持部/杭州技术部/云计算实验室/杭州产品赋能团队，2026-10-27 补）；
- 页面 hint 注明：锚点值（YEAR_V 等）执行期动态展开，具体版本以火车日历为准。

**后端 `DimensionKeyController` / `DimensionKeyConfigRepository`**：
- `update` 的 `WHERE builtin=FALSE` 放开为"白名单内置键允许改 aliases，不允许改 key/label/enabled"；
  非白名单内置键仍拒绝（`builtin=true` 保护不整体撤，防止误开 8 键全量编辑）；
- seed 扩充：`ensureTable`/`ensureReservedRow` 模式补内置三键的默认词表行（§3.2 表），
  存量表**仅补种缺失行、不覆盖已改配置**（同 timeRange 补种语义）；
- 保存期校验在 Controller 层（同 timeRange 锚点校验先例）；
- `DimensionKeyConfig` record 不变（aliases 结构复用），无表结构变更。

**前端配套**：`frontend/src/api/dimensionKey.ts` / `types/dimensionKey.ts` 补 value 校验
提示字段；`SkillRoutingConfigPage.vue` 下拉走 `activeKeys()` 动态加载，后缀键自动透出，
无需改动（`DIRECT_EXEC_DIMENSION_KEYS` fallback 枚举补 4 个后缀键，可选）。

## 7. 测试要点

1. **归一**：十月版/202610版本/10月份版 → 同一标准值同一指纹；"十一"不截断成"十"+"一"；
   `2026103` 这类非版本数字串不误命中（词边界）；`10月延后` → `2026年10月延后版`；
2. **词表合并**：杭一/今年以来/当季 命中 seed 行；词表新增行即时生效（reload 后）；
   Repository 挂掉只跑正则不报错；`10月1日到10月15日` 里"1月"不被词表误收（span 屏蔽）；
   裸日期屏蔽：`杭州三部11月版、12月版10月26日到期` → 只出 11月版/12月版（不出 10月版）；
   裸 `10月26日到期` / 区间 `10月1日到10月15日` 不产出版本维度；
3. **解析**：周一/版本切换日当天问 THIS_V / LAST:3V；日历缺历史版本时 LAST:{n}V 按 rank 实际值降级；
   延后版精确值查无 → 解析空 → 必填缺失回退 LLM；
4. **绑定**：锚点展开成版本列表传裸键；`.start/.end` 取聚合窗口；多锚点取第一个；
   锚点原词不出现在任何传参里；季度值原样传 vestQuarter 不展开；
5. **页面**：内置三键 alias 可编辑、value 分型校验拒绝非法值；非白名单内置键仍只读；
   其余内置键行编辑被后端拒绝（防绕过前端）；
6. **缓存**：锚点短语命中绕过 ResponseCache；字面归一命中可缓存；
7. **回归**：全量单测基线（2026-10-15 后为 438+）；`extraDimensions` 缺省行为不变；
   `defaultTimeValues` 缺省语义不变；LLM 路径 prompt 注入不受影响。

## 8. 维度值→部门反填（2026/10/27 拍板，已实施）

**问题**：车贷/房贷型纯组/纯产品线/纯应用问句（如「个贷汽车场景建设组和个贷住房场景建设组的达标率」）
不含部门词，extraction.deptName 为空 → skill 缺必填 dept 参数反问补参，体验断裂。

**拍板**：不退化脚本口径，Java 侧自动查人员台账表 `developer_pl_person_info_t` 看该维度值
对应的部门，自动填充 deptName。

**实现**（727 测试过）：
- `PersonLedgerRepository.deptsByDimension(column, value)`（Q8）：`SELECT DISTINCT "部门" WHERE
  "<维度列>" = ? AND 快照(max 统计月份)`；列白名单 {统计组, 产品线, 应用}（拼接前过闸，
  白名单外 IllegalArgumentException）；per column:value TTL 缓存（同 Q1 30min），失败负缓存
  fail-open 返回空列表（不反填，不反复打库）。
- `DirectSkillExecutor.backfillDeptFromLedger`：位置在 applyPersonalDimensions 之后
  （我X enrich 显式优先，只反填 deptName 仍为空的情况）、applyReanchorSuppression 之前
  （deptName 不在抑制矩阵，安全）。三键（统计组/产品线/应用，经互斥裁决后至多一键非空）
  逐值查部门并集注入 LinkedHashSet 保序去重；台账查无/失败 → 不填（fail-open）。
- 脚本侧兜底（q2_1_metrics_dual_time）：dept 改可选，未提及时跳过查询仅回显维度入参。
