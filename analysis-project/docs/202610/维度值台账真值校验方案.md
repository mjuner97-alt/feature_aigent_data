> 2026/10/26 立项。承接 我X按需注入与作用域重锚方案.md §9（block 屏蔽）之后的第二轮垃圾值治理。
> 触发：业务 E2E 「车贷、房贷两个组的风险」——配同义词前收垃圾值 `stat_group=["房贷两个组"]`，
> 配同义词（房贷→个贷住房场景建设组 / 车贷→个贷汽车场景建设组）后仍只收出一个值。
>
> **2026/10/27 v2 升级（业务拍板）**：机制 B 从「事后排除（负向校验）」升级为
> 「**事前匹配（正向字典扫描）为主 + 域外终局拒收兜底**」——统计组/产品线/应用的
> 标准值直接来自台账 distinct 集合的正向扫描，非标准说法走同义词，正则降为最后兜底。
> 同 perName 人员名识别的成熟模式（Q3 姓名字典扫描）。

## §1 E2E 实证与根因

### §1.1 现象

| 配置 | 提取结果 (stat_group) | 期望 |
|---|---|---|
| 未配同义词 | `["房贷两个组"]` | `["个贷住房场景建设组","个贷汽车场景建设组"]` |
| 配了同义词 | `["个贷汽车场景建设组"]`（房贷的值丢了） | 同上 |

### §1.2 根因一：组名修剪守卫误杀 alias 命中（配同义词后丢值）

`DimensionStateManager.suppressEmbeddedAliasHits`（alias 嵌入组名 token 的抑制守卫，
本意防「个贷数据开发组」里的「个贷」误绑到个人信贷产品线）：

- EXPLICIT_TEAM 正则把 **「房贷两个组」整段**抢成组名 token（span [3,8)）；
- alias 命中「房贷」span [3,5) 嵌在 token 内部，token 与标准名「个贷住房场景建设组」互不包含
  → 按「碰巧子串」抑制，**真值在源头被丢**；
- token 尾巴「两个组」是**数量粒度短语**（两个+组），不是组名的一部分——守卫的位置枚举
  （各/每/按 前导+尾缀）不含数量词，拦不住这一形态。
- 「车贷」span [0,2) 不在任何组名 token 内 → 保留。这就是只出一个值的原因。

### §1.3 根因二：regex 轨候选值没有终局校验（未配同义词时收垃圾）

- 「房贷两个组」被 EXPLICIT_TEAM 直接当组名收：首字「房」∉{各,每,按}、
  尾缀「两个」∉{各,每,按}、词表反哺无词干、block seed（裸我）不命中 → 垃圾值一路透传到脚本。
- 粒度词守卫已是第五层（位置枚举）+ 第六层（block 配置）+ 词表反哺，但**配置驱动永远追不出
  所有口语变体**（两个组/这几组/那三组/分两个组…），每类都要等 E2E 撞上再补。
- 根治：维度候选值对一个**封闭真值域**做终局校验——不在域内即垃圾，拒收。

## §2 方案总览（v2：A 修守卫 + B 正向扫描三段式提取）

统计组/产品线/应用的提取从「正则猜形状」升级为三段式，**真值域正向匹配优先**：

```
问题 → [B①] 台账字典正向扫描：问题文本 contains 台账真值（最长优先）→ 直接收标准值
     → [B②] 同义词词表：非标准说法 → 标准值（既有 alias / dimension_key_config 词表）
     → [B③] 正则兜底：EXPLICIT_TEAM 等形状猜值 → 逐值真值域校验，域外拒收
     → [A]  alias 抑制豁免数量粒度后缀（守卫层修复，独立于提取三段式）
     → 我X enrich → 人名扫描 → 重锚抑制 → 下钻展开 → buildParams
```

- **A 是修 bug**（守卫误杀），不引入新依赖；
- **B 是根治**（业务拍板方向）：`developer_pl_person_info_t` 的 统计组/产品线/应用
  distinct 集合既是**正向匹配源**（B①，标准说法不再依赖正则形状，整名直接命中），
  又是**终局校验域**（B③，正则兜底收上来的候选不在域内即拒收）；
- ①②接得住的值不再依赖正则，③只处理①②都没覆盖的残余——垃圾值即使被正则收上
  也进不了脚本，且治理日志暴露未适配说法，运营据此补词表。

## §3 机制 A：alias 抑制的数量粒度后缀豁免

**位置**：`DimensionStateManager.embeddedInTeamSpan`（suppressEmbeddedAliasHits 内部）。

**规则**：alias 命中 span 嵌在组名 token 内时，取 token 内 alias 之后的**剩余后缀**
（`q.substring(h.end, span[1])`），若后缀匹配数量粒度短语 → 该 token 是「alias + N个组」
的口语组合，**不抑制**（alias 命中照常进 resolved）：

```
数量粒度后缀 = ^[一二两三四五六七八九十\d]+个?组$   （两个组 / 3个组 / 几个组 / 两个组）
```

- 「车贷、房贷两个组的风险」：房贷后缀「两个组」命中 → 不抑制 → resolved 双值
  → buildAliasPeerDimension 同类型多命中去重全收（既有能力，"比较军队和票据"→双产品线）。
- **不碰 findTeamToken 路径**：裸「10月三组」是真组名（既有测试
  rawFallbackStillExtractsTeamWhenMaskedTooShort 锁定），数量词守卫若上提到正则提取层会误伤
  ——正则轨的垃圾留给机制 B 按真值域裁决，位置守卫不新增层。
- 后缀豁免只影响**已配 alias** 的场景，未配置时 token 照旧整段被收，交给 B。

## §4 机制 B：台账真值域（v2：正向扫描为主 + 终局校验兜底）

### §4.1 真值域数据源

`PersonLedgerRepository` 新增字典查询（复用 Q4 roleDictionary 模式：TTL 缓存 + 失败退避）：

| 查询 | 列 | TTL | 目标键 |
|---|---|---|---|
| Q5 | DISTINCT 统计组 | 30min | groupName |
| Q6 | DISTINCT 产品线 | 30min | productLine |
| Q7 | DISTINCT 应用 | 30min | appName |

- 中文列名带引号（Q1/Q2 同款）；一次 distinct 全表扫描，30min TTL 足够台账更新频率。
- **失败语义与 Q4 不同**（关键）：校验用途必须区分「查询失败」和「真没数据」——
  查询失败 → 返回 null（调用方**跳过**该键校验/扫描，fail-open 防误杀）；
  空集（成功但无行，环境未灌数）→ 同样跳过（空域校验会误杀一切）。

### §4.2 真值域 = 台账 ∪ 词表标准值 ∪ alias 标准值

台账表是**人员归属**口径，宽表是**项目数据**口径，两者可能存在历史组/新增组时间差。
为防误杀合法值，真值域取并集：

```
truthSet(groupName)  = ledger 统计组 distinct
                     ∪ dimension_key_config groupName 行同义词 value（isSynonym，管理员配的标准值）
                     ∪ dimension_alias 表 TEAM standardName（业务配的组名全称）
truthSet(productLine)= ledger 产品线 distinct ∪ 词表 value ∪ alias PRODUCT_LINE standardName
truthSet(appName)    = ledger 应用 distinct   ∪ 词表 value ∪ alias APPLICATION standardName
```

- 台账注入值（myGroup 等 R1 产物）天然在 ledger distinct 里，无需单列。
- 词表/alias 标准值并入：管理员/业务显式配置过的标准值视为合法，即使台账暂无该组人员。

### §4.3 B① 正向字典扫描（新增提取层）

**位置**：`DirectSkillExecutor.plan`，提取之后、我X enrich 之前（最先做）。

**算法**（同 PersonalDimensionResolver.scanNames 姓名扫描模式）：

- 扫描源 = §4.2 truthSet（台账 distinct ∪ 词表标准值 ∪ alias 标准值，按值长度**降序**）；
- **扫描目标 = 问题原文**（关键，见 §10 案例二）：**不做**部门/时间/应用 span 屏蔽——
  屏蔽是正则形状猜测的配套（防吞整段），字典扫描靠整名精确 contains，屏蔽反而会把
  「杭州二部FMBM资金交易组」切碎导致 miss；扫描只需要**真值域内部**的
  `boolean[]` span 消费防重叠（长值优先，短值是长值子串时自然被 span 挡掉，
  如「个贷」命中被「个贷汽车场景建设组」整名消费挡掉）；
- 最短长度 ≥2 字防单字误命中；产物去重保序；
- **三键互斥裁决**（业务规则：groupName/productLine/appName 每次仅一个维度有值）：
  按键独立扫描可能同时命中多键（组名里嵌产品线词等）——取**最长命中值所在键**，
  其余键丢弃；长度平手沿用 alias 轨既有兜底序 产品线 > 组 > 应用（AliasResolver
  FALLBACK_ORDER 同源）；
- **与同义词轨去重**：同义词命中产出的标准值若与扫描产物相同，只留一份；
- **与 R2 联动**：扫描产物计入「本轮显式提及」，重锚抑制不得误清
  （同 personScan 产物的豁免语义）。

效果：标准组名/产品线**整名直接命中**，不再依赖 `[一-龥]{2,}组` 的形状正则——
「个贷汽车场景建设组的风险」「数据产品线质量」这类标准说法 100% 接住，
**形状再不规则（嵌部门/嵌应用/不以"组"结尾）也能提取**（§10 案例二）。

### §4.4 B③ 终局校验（正则兜底残余的拒收）

B①② 都没接住时，正则轨（EXPLICIT_TEAM / EXPLICIT_PRODUCT_LINE）照旧提取候选，
对候选**逐值真值域校验**：

- 值 ∈ 真值域 → 保留（「10月三组」型真组名若在台账，照常通过）；
- 值 ∉ 真值域 → **丢弃 + 治理日志**（`Ledger truth-check dropped: key=groupName value=房贷两个组`，
  运营据此决定是否补同义词）；
- 全部丢弃 → 该键置空 → 走既有缺参反问流程（反问优于查空集）。
- **fail-open**：truthSet 为 null/空（§4.1 语义）→ 跳过校验，行为与现状一致。

### §4.5 plan 链路顺序

```
analyzeQuestionRuleBased → extraction
  → [B①] scanLedgerTruth(extraction, question)      ← 正向扫描，最先做
  → [B③] validateAgainstLedgerTruth(extraction)     ← 正则残余拒收
  → applyPersonalDimensions（我X enrich）
  → 人名扫描 → 重锚抑制 → 下钻展开 → buildParams
```

- 先扫描/校验再 enrich：R1 注入值在 ledger distinct 里必过；R2 重锚抑制的显式命中判定
  在干净值上做。
- 不扫描/不校验的键：deptName（值域固定枚举）、时间键、itemNo/subItemNo（格式正则自带校验）、
  perName/perNo（台账字典扫描本身即真值匹配）、perRole（Q4 角色字典归一）。

### §4.6 与既有层级的关系

| 层 | 机制 | 拦截形态 | 失效模式 |
|---|---|---|---|
| 五 | 粒度词守卫（位置+词表反哺） | 各/每/按/词干 | 位置枚举追不全 |
| 六 | block 配置（我X方案 §9） | 含「我」代词短语 | 只覆盖已配正则 |
| **七** | **台账真值域（本方案）**：正向扫描 = 真值直达；域外校验 = 终局拒收 | **标准说法整名命中；一切域外值进不了脚本** | 台账口径缺口（fail-open 兜底） |

七是终局：前六层是「尽量拦」，七是「标准值直达 + 拦不住的域外值也进不了脚本」。

## §5 边界与风险

1. **宽表与台账口径一致性（关键确认点，需业务拍板）**：脚本按 stat_group 查宽表，
   若宽表存在台账没有的组（历史归档组、外部组），严格校验会误删合法值。
   缓解：§4.2 并集 + 治理日志先观察（日志只记不删的灰度开关可选）+ 业务确认
   「宽表 stat_group 值域 ⊆ 台账统计组 ∪ 已配词表」。
2. **「10月三组」型真组名**：机制 A 不动 findTeamToken，这类值由 B 按真值域裁决——
   在台账里则保留，不在则拒收（业务语义：不在台账的组本来也不该查）。
3. **LLM 回退轨**：本期不做（主场景直接执行全覆盖）；DimensionStateMiddleware 轨
   如需同款校验，后续把 validator 挂 formatDimensionContext 前，接口同款。
4. **性能**：Q5-Q7 各 30min TTL + 失败 60s 退避，plan 链路零新增 DB 压力（命中缓存）。
5. **多租户**：真值域取全表 distinct（组名是全局组织概念，不分用户）；台账 Q1/Q2 的
   per-user 语义不变。

## §9 v2 升级记录（2026/10/27 业务拍板）

业务确认：统计组/产品线规则混乱，仅靠正则+同义词不彻底，垃圾值不好校验——
**根治靠 developer_pl_person_info_t 真值域本身**。机制 B 从 v1 的「事后排除（负向校验）」
升级为「**事前匹配（正向字典扫描）为主 + 域外终局拒收兜底**」（§4.3 B① + §4.4 B③）：

- 标准说法（台账里有的整名）→ B① 正向扫描直接命中，不依赖正则形状；
- 非标准说法 → B② 同义词词表映射（既有轨不变）；
- 都没接住 → B③ 正则兜底照旧收候选，再按真值域逐值拒收（v1 行为）。

v1 的「事后排除」没有丢：它降级为 B③ 兜底层，仍然是垃圾值进不了脚本的终局防线。
同 perName 人员名识别（Q3 姓名字典扫描）的成熟模式，实现可复用其最长优先 + span 消费算法。

## §10 复杂案例推演

### 案例一：「车贷、房贷两个组的风险」（§1 原始 E2E）

- 配词表前：正则轨收垃圾 `["房贷两个组"]` → B③ 域外拒收 → groupName 空 → 缺参反问；
- 配词表后：双 alias 命中，机制 A 豁免数量粒度后缀误杀 → 双值都出；B① 也会
  在真值域整名命中无贡献（问题原文只有口语词）。

### 案例二：「杭州二部FMBM资金交易组 需求项首次会签未完成」（2026/10/27 业务补充）

### 案例四：「团队」结尾值域批量存在（2026/10/27 业务补充）

  「杭州产品赋能团队领导」；deptName 键不参与本方案（值域固定枚举口径不变），无冲突。
