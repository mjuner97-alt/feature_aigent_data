# 报告流程复用设计

## 目标

新增独立的“报告流程”资源。报告流程由执行节点组合和报告输出大纲组成，可以被 Skill、长任务流程和独立任务引入。每个用户可以创建自己的报告流程，其他用户可以复制已启用的报告流程。引入后，使用方可以修改自己的副本；执行完成通知发送给实际触发人。

## 核心概念

报告流程不是单纯的大纲，而是一份可复用的报告执行组合：

- 基本信息：名称、唯一编码、描述、启用状态、创建人。
- 执行节点：Skill 或 Python 节点、节点参数、指标依赖、执行顺序和必填属性。
- 报告输出大纲：报告总标题、章节层级、编号样式，以及章节与节点的绑定关系。

Skill、长任务流程和独立任务都是报告流程的使用方。使用方选择报告流程后，将报告流程内容复制到自身配置中并保存来源信息与快照；使用方可以继续修改节点和大纲。

## 权限与复制

- 每个用户可以创建自己的报告流程。
- 报告流程名称全局唯一；名称用于展示，编码用于稳定引用。
- 只有创建人可以编辑、删除、启用和停用自己的报告流程。
- 其他用户可以查看已启用报告流程并复制。
- 复制会创建完全独立的新报告流程，创建人为当前复制者。
- 复制记录保留 `copied_from_id` 和源名称快照；源报告流程删除后，副本仍可使用。

## 引入与快照

配置 Skill、长任务流程或独立任务时，模板选择器暂时只展示当前用户创建的报告流程。引入后允许修改当前使用方的节点和大纲。

使用方保存以下信息：

- `report_process_id`：引入时的来源报告流程 ID。
- `report_process_version`：引入时的版本号。
- `report_process_snapshot`：引入时的完整节点和大纲 JSON。

执行时使用使用方保存的快照，不重新读取来源报告流程。来源报告流程更新只影响之后新引入的使用方。后续可增加“同步报告流程”操作，展示差异后再覆盖当前配置。

## 执行与通知

报告流程创建人、Skill 或任务创建人不决定完成通知对象。执行记录保存实际触发人的 `triggerUserId`，报告完成通知发送给该用户。

例如：用户 A 创建报告流程和 Skill，用户 B 使用该 Skill；执行使用 Skill 保存的报告流程快照，完成通知发送给用户 B。

## 与现有长任务入口的关系

现有 `script_exec` 保留 `flowTask:<长任务名称>` 入口。长任务执行时使用其保存的报告流程快照，提交仍然是异步的，完成结果继续走现有通知机制。

## 第一阶段范围

- 报告流程列表、创建、编辑、删除、启停。
- 报告流程复制。
- 报告流程节点和报告大纲编辑。
- Skill、长任务流程、独立任务选择当前用户自己的报告流程并保存快照。
- 执行完成通知发送给实际触发人。

暂不包含多人协作编辑、复杂版本历史、自动合并和跨用户直接编辑。

## 约束与校验

- 报告流程名称全局唯一，复制时必须解决名称冲突。
- 启用报告流程前校验节点、节点参数、指标依赖、大纲结构和节点绑定完整性。
- 使用方保存时校验快照完整性，避免来源流程被停用或删除后产生不可执行配置。
- 报告流程中的节点类型遵循现有 Skill/Python 节点规则，不引入第三种执行类型。
