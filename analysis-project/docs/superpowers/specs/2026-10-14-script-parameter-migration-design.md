# 最新脚本与参数迁移

> 后续用户已确认按字段名、明确规则自动转换、保留失败原值及异步检查/试跑/发布。实施以 [2026-10-15 异步迁移与发布计划](../plans/2026-10-15-async-script-parameter-migration.md) 为准，本文旧约定仅作背景。

## 目标

脚本作者可以修改自己的脚本，不因其他用户引用而失去修改权。长任务及流程模板继续通过 scriptId 使用最新代码，不引入源码版本或源码备份机制。

## 方案选择

采用保存参数定义时迁移引用配置，并在执行前校验参数。仅在执行时临时适配会导致编辑页面保留过期参数；自动按相似名称猜测改名会错误迁移业务值，因此不采用。

## 保存与迁移

参数定义编辑界面提供变更预览、明确的旧名称到新名称映射及新增参数默认值。预览展示受影响长任务和流程模板数量、可自动迁移及需人工调整数量；避免向脚本作者泄露其他用户的参数值。

同名参数保留原值。改名仅使用作者指定的映射，完整保留值对象，包括 $rule 引用。新增参数仅在原值缺失且存在有效默认值时补齐，不覆盖已有值。删除参数在变更预览中明确列出，提交变更时移除对应配置。类型变化不猜测转换：已有值符合新类型则保留，否则标记待调整。

迁移覆盖持久化长任务节点及流程模板节点，包括 ReportProcess.nodesJson 与 SkillFlowNode.scriptParamsJson；实施前核对其实际生命周期和所有写入入口。历史执行日志不修改，正在执行的节点不热改参数。已排队但未执行的节点在执行前按最新参数定义校验。

脚本参数定义与引用配置的迁移在同一数据库事务中完成。并发编辑使用现有配置比较或乐观锁检测冲突，不静默覆盖他人修改。跨用户配置迁移仅由服务端根据指定 scriptId 查找引用执行，不开放任意跨用户节点编辑权限。

## 无法适配的引用

缺少必填参数、类型不匹配、改名目标已有冲突值等问题不会禁止作者保存脚本。引用保留需用户处理的信息，编辑和执行入口展示具体节点、参数和原因。执行前重新校验；存在问题时不启动 Python，修正后自动恢复可运行状态。

参数规则标记在定义迁移时保留，在执行时解析后验证实际值。默认值必须通过新参数类型验证。迁移只保证参数结构兼容，不能证明脚本业务含义未变化。

## 源码与定义边界

单独编辑 Python 源码不能可靠推断参数接口变化。参数迁移由明确修改 paramsSchema 触发；源码编辑入口提醒同时维护参数定义。脚本文件写入与数据库事务不能保证天然原子性，实施时沿用现有保存边界并明确失败提示，不宣称二者原子发布。

## 验证

覆盖跨用户引用、改名规则对象保留、新增默认值、删除参数、必填缺失、类型不兼容、映射冲突、事务回滚和并发编辑；验证长任务与流程模板均使用最新脚本，历史日志保持不变。运行现有相关后端及前端检查。
