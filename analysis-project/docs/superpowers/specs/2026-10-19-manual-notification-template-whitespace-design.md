# 手动通知正文模板与空白格式修复

## 已确认的问题

- 手动通知弹窗仅加载已保存的 TO/CC 名单，没有展示正文模板，也没有提交临时正文的入口。
- 编辑页正文预览先 trim，再转换为普通 HTML，造成首尾空白删除、连续空格和行首缩进折叠。
- SkillFlowDefinitionRequest 使用 trimToNull 保存正文，会裁剪非空正文的首尾空白。

## 推荐方案

复用编辑页的正文模板输入、插入 {链接} 和预览组件。手动通知每次打开时加载流程编辑页最新保存的正文模板，允许修改本次发送正文；发送提交明确的模板值，临时修改不写回流程配置。加载失败显示错误并允许重试，禁止以空模板代替读取失败。沿用已有异步响应防护及发送中禁用规则。

正文只有在全部为空白时使用默认模板。包含有效文字时，完整保留连续空格、行首缩进、首尾空白及换行。预览与实际邮件采用一致的安全转义和保留空白的 HTML 表达，维持现有链接占位符替换和缺少占位符时追加报告链接的规则。实际发送路径需同时检查执行快照与本次覆盖值，兼容没有传正文的旧调用。

模板输入框内 Tab 在光标处插入一个制表符，预览与邮件将其显示为四个空格；Shift+Tab 保留移出输入框的行为。手动通知预览中的报告标题和日期使用执行记录对应值，与实际邮件一致。

用户追加要求：复制长任务的副本默认启用，包括源流程已禁用的情况。保留现有名称与触发词冲突校验，以及用户手动关闭副本的能力。

## 其他方案

- 单独为手动弹窗复制编辑控件：改动直观，但两处预览容易再次不一致。
- 手动弹窗只读展示：改动较少，但不能达到与编辑页一样的编辑体验。

## 验证

先添加并运行失败用例，再实现修复。覆盖已保存模板回显、本次正文传递且不修改保存配置、空模板与未传模板的区别、关闭重开及异步过期响应、连续空格、第二行缩进、首尾空白、换行、HTML 转义和链接替换。运行相关前后端测试及前端构建。无需发送真实邮件。
