# 长任务通知收件人设计

## 目标

支持长任务在创建和编辑时配置通知收件人；定时执行使用该配置；对话或手动执行产生独立执行记录，用户可针对已有报告重新选择人员并发送通知。

## 现有能力复用

- `notification_config` 与 `notification_recipient` 保存业务对象的收件人关系。
- `developer_pl_person_info` 是人员清单，后端已有批量存在性校验和姓名解析。
- `skill_job_notification` 保存长任务每次首发或补发的投递记录。
- `skill_flow_notification` 属于流程通知，不在本次范围内修改。

## 行为设计

### 创建和编辑

长任务表单增加人员搜索与多选收件人。创建或编辑成功后保存长任务对应的 `SKILL_JOB` 通知收件人配置。后端重新校验人员存在性、去重并限制最多 50 人；空名单保留现有兼容语义，即发送给创建人。

### 定时/自动执行

任务完成时读取长任务配置的收件人名单。每次投递在 `skill_job_notification` 新建一条 `INITIAL` 记录，记录收件人快照、发送器、状态和错误信息。收件人配置为空时沿用创建人兜底逻辑。

### 对话/手动执行

每次触发继续生成独立执行记录。执行详情中的通知区域展示该执行的投递历史，并提供“发送/通知”操作。操作弹出人员清单选择器；确认后调用已有补发入口，创建新的 `RESEND` 记录，仅发送已有报告，不重新执行任务。

## 校验与错误处理

- 前端校验收件人非空、去重和人数上限。
- 后端对收件人执行人员清单存在性校验，后端规则为最终权威。
- 补发校验执行记录归属、报告已生成、用户有权限且至少有一个有效收件人。
- 发送失败保留 `FAILED` 记录及原因；不会改变执行本身的成功/失败状态。
- 兼容既有通知配置、旧客户端请求及空名单兜底逻辑。

## 不在范围内

- 不新增通知表。
- 不修改流程通知表 `skill_flow_notification`。
- 不更换现有通知发送器或邮件协议。
