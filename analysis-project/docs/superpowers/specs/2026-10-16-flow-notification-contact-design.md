# 长任务通知联系人配置（已确认）

## 需求与现状

长任务编辑页面允许为每条流程配置通知联系人和手机号。现有邮件发送器从运行配置表的 `notification_contact_html` 读取整段联系人 HTML，在发送邮件时追加到正文。

## 推荐设计

- 在通知设置区域增加“联系人”“手机号”两个普通文本输入框，与流程一起保存；仅流程创建人可修改。
- 两项均为空时使用原有配置表 HTML；两项都填时用当前流程的联系人和手机号替换默认联系人段落，避免重复追加。
- 只填一项时提示补齐另一项，避免自定义联系人与默认手机号混用。清空两项即可恢复默认。
- 手机号去除首尾空格后仅检查长度为 11；不校验号段、运营商、实名或验证码，也不增加正则格式校验。前后端采用同一规则。联系人去除首尾空格，仅检查非空。
- 输入区域标题为“通知中的联系信息”，紧接说明：“展示在任务通知邮件中，方便收件人遇到问题时联系相关人员。手机号仅作为联系信息展示，不用于发送短信。”
- 字段标签为“联系人姓名”“联系电话（手机号）”；占位提示分别为“填写负责解答此任务相关问题的人”“填写 11 位手机号”。
- 输入框下方持续显示：“两项都留空时，使用系统默认联系信息；如需自定义，请同时填写联系人和手机号。”不把配置表 HTML 填入输入框。
- 两项均为空时显示状态“当前使用系统默认联系信息”；两项均填写且校验通过时显示“保存后，任务通知邮件将展示上述联系信息”。
- 只填联系人时提示“请填写联系电话，或清空联系人以使用系统默认联系信息”；只填手机号时提示“请填写联系人姓名，或清空手机号以使用系统默认联系信息”；手机号长度不符时提示“请输入 11 位手机号”。在保存时阻止不完整或长度错误的配置，不在尚未结束输入时反复弹窗。
- 自定义信息在创建执行时写入快照，本次执行完成通知及重发使用该快照；修改流程不影响已启动执行。旧执行及未配置的流程继续按发送时的原有配置表规则回退。
- 发送器负责选择自定义联系人段落或配置表 HTML；自定义文本进行 HTML 转义。其他独立任务调用保持原有默认逻辑。
- 自定义字段纳入编辑脏状态检测。复制流程时清空自定义联系人，避免沿用他人的联系方式。

## 备选方案

1. 推荐：联系人和手机号成对覆盖。保持现有 HTML 配置兼容，回退行为明确。
2. 每个字段独立回退：需要拆分或解析现有 HTML，容易出现联系人与手机号不属于同一人的情况。
3. 提供“使用系统默认”开关：规则明确，但对两个可选字段增加额外交互，本期不采用。

## 验证

覆盖新增/编辑往返、空值回退、单项缺失、11 位长度边界、仅联系人变更的脏状态、HTML 转义、执行快照及旧执行兼容；运行相关前端测试、后端测试与不清理静态资源的生产构建。数据库迁移新增流程字段及执行快照字段。
