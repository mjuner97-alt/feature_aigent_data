# Skill/Python 指标依赖选择设计（修订版）

## 1. 目标与当前实现边界

指标依赖需要在创建阶段可见，并在运行前展示最终生效集合。仓库当前已有 `skill_flow_node_metric` 关系表和 `metricIds` 数组接口，但流程节点仍被前后端限制为单指标；独立任务仍使用历史单值 `metricId`。本修订先消除流程节点的单指标限制，再分阶段引入 Skill/Python 默认依赖和独立任务多指标，避免把两个不同存储模型一次性混改。

## 2. 统一语义

- Skill/Python 默认集合：`defaultMetricIds`，可空数组。
- 节点/独立任务覆盖集合：`metricIds`，可空数组。
- 最终集合：`effectiveMetricIds`，只读返回。
- 来源：`DEFAULT`、`OVERRIDE`、`NONE`。
- 未配置必须与“显式清空”可区分。当前版本不把空数组当作覆盖空集合；新增 `metricOverrideConfigured`（默认 false）作为迁移期间的显式标记。旧记录无标记时按现有行为兼容：有历史指标视为覆盖，无指标视为未配置。

## 3. 分阶段实施

### 阶段 A：流程节点多指标（本次）

- 后端移除“最多一个指标”校验，保留逐项存在且启用校验。
- 前端节点选择器改为多选，保存时去重并保持选择顺序。
- 运行门控继续复用现有关系表，节点的全部指标必须 READY。
- 增加回归测试：多指标保存、读取、就绪预检和运行门控。

### 阶段 B：默认依赖数据模型

- 新增 `skill_default_metric`（`skill_id`, `metric_id`, `sort_order`）和 `script_default_metric`（`script_id`, `metric_id`, `sort_order`）关系表。
- Skill/Python 创建、编辑接口增加 `defaultMetricIds`；读取旧单值时归一化为单元素集合。
- 保存时去重、校验指标启用状态，并保留稳定顺序。

### 阶段 C：继承解析

- 节点请求增加可空 `metricOverrideConfigured`；未配置时继承绑定 Skill/Python 的默认集合。
- 服务层统一计算 `effectiveMetricIds` 与 `metricSource`，详情、运行前预检、执行快照全部复用同一解析器。
- 不允许通过字符串拆分推断多指标。

### 阶段 D：独立任务兼容升级

- 新增任务指标关系表，保留旧 `skill_job.metric_id` 读取兼容。
- 新保存统一写数组；历史单值按单元素集合读取。
- 详情和运行失败信息显示最终集合及来源。

## 4. 页面要求

Skill/Python 表单使用“默认指标依赖”多选；节点和独立任务使用“指标依赖（可选）”多选。节点未单独配置时显示继承结果，选择后显示覆盖来源；默认和覆盖均无指标时显示“未配置指标依赖”。

## 5. 验收标准

1. 流程节点可保存并运行多个指标，全部指标参与 READY 门控。
2. 历史单指标记录可读取、编辑并保存为多指标。
3. 默认变更只影响继承节点，覆盖节点保持不变。
4. 详情、运行前确认和实际门控使用同一 `effectiveMetricIds`。
5. 空集合不会被误显示为覆盖空集合。
