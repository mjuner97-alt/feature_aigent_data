# weekly_demo-1015 报告执行

## 适用请求

用户明确要求执行、生成或重新生成 `weekly_demo-1015` 报告。例如：

- 使用 weekly_demo-1015 模板生成报告。
- 执行 weekly_demo-1015 报告。
- 用 weekly_demo-1015 测试报告流程。

仅询问模板说明或执行原理时，解释流程即可，不提交任务。

## 固定模板与执行入口

模板名称为 `weekly_demo-1015`。通过 `script_exec` 按模板名称提交一次：

```json
{
  "scriptId": "report_template:weekly_demo-1015",
  "params": {}
}
```

- `report_template:` 后固定填写页面上看到的模板名称 `weekly_demo-1015`，无需查询或使用内部编码。
- 不查找或创建同名 Python 脚本，不把该 ID 当作 `script_registry` 中的脚本 ID。
- 不额外传递版本、年份、用户 ID 或会话 ID。节点参数沿用报告模板中保存的配置；身份与会话由执行上下文提供。
- 不手工拆分执行模板节点，不自行调用底层模拟脚本，不重复提交同一轮请求。
- 模板不存在、已停用或提交失败时，如实说明工具返回的原因，不换用其他模板。

## 返回处理

工具返回“已提交”或“正在执行”后，简短告知用户提交状态并结束本轮。不要调用 `wait_async_results`，不要轮询等待报告完成，也不要将提交成功表述为报告已经生成。

完成通知及报告产出由后台流程负责，用户可在“流程报告记录”查看进度和结果。
