# 自增序列巡检与导入后校准

脚本：`scripts/check_serial_sequences.sql`。

显式导入 ID 不会推进 SERIAL/BIGSERIAL 的序列。应用新增继续省略 ID，导入、迁移或恢复数据后运行本脚本检查。脚本作为维护工具手动执行，不放入应用启动或每次请求，也不修改已有 Flyway 迁移。

## 使用步骤

1. 用维护账号连接目标数据库，使用与应用相同的 `search_path`。业务表名不加 schema 前缀，例如 `skill_flow`。先执行 `SHOW search_path;` 确认范围。
2. 原样运行整个脚本。默认 `INSERT INTO serial_sequence_options VALUES (FALSE)`，只读取业务表和序列，不调用 `nextval` 或 `setval`。脚本会创建并删除会话临时表。
3. 检查报告。`BEHIND` 表示下一个序列值不大于表内最大 ID；`OK` 表示本次未发现落后；`SKIPPED`、`EXHAUSTED`、`ERROR` 需要人工处理，不能视为通过。
4. 修复前暂停应用、定时任务、导入程序等所有相关写入和直接取序列值的调用。断开并重新建立持有序列缓存的数据库连接，保持写入暂停。将脚本中上述 `FALSE` 改成 `TRUE`，在新维护会话中重新执行整个脚本。
5. `REPAIRED` 表示已将落后序列设为当前最大 ID，并标记为已使用。空表、领先序列不调整。重新以 `FALSE` 执行巡检，检查剩余异常，再恢复应用连接和写入。
6. 用实际创建接口验证长任务等受影响业务，确认不再出现主键冲突。

修复模式持有表写入锁直到脚本事务结束，但不能阻止其他连接独立调用 `nextval()`，所以仍然必须停写。`setval()` 的修改不会随事务回滚；如果部分表报错，报告中已标记 `REPAIRED` 的序列可能已经修改，不应依靠 `ROLLBACK` 恢复。

## 范围与兼容性

- 扫描当前 `search_path` 可见普通业务表的所有列，不限定表名或主键列名；同名表以当前搜索路径解析结果为准，不会跨 schema 修改被遮蔽的表。
- 自动发现数据库关联的 SERIAL/BIGSERIAL 及 IDENTITY 序列。无法通过无前缀名称解析的序列跳过。
- 检查序列所有权以及列默认值依赖；多个列或表共享一个序列时跳过。
- 未关联所有权的自定义 `nextval` 默认值、函数或触发器内取号、分区表及其特殊依赖需单独审核。报告 `OK` 不代表这些场景已经覆盖。
- 仅修复正向、非循环且未达到上限的序列；比较时考虑 `is_called` 和步长，最大 ID 包含软删除行。
- PostgreSQL 10+ 从 `pg_sequence` 读取参数；旧 PostgreSQL/openGauss 分支从序列关系读取。系统目录仍使用标准名称，业务表不写固定 schema。具体 openGauss 版本需先在测试库验证，兼容性或权限错误会显示为 `ERROR`。
- 巡检读取不是全库一致快照；在线结果用于发现候选异常，维护窗口内的修复会重新取值。大表的 `MAX` 查询耗时取决于索引。

## 测试库验收

在独立测试库中准备以下数据，先运行默认巡检，再在停写状态下运行修复，最后执行省略 ID 的 INSERT：

| 场景 | 巡检预期 | 修复预期 |
| --- | --- | --- |
| BIGSERIAL 表显式导入 id=100，序列未使用 | BEHIND | REPAIRED；下一次生成 101 |
| 序列值已经超过 MAX(id) | OK | 保持原序列值，不能回调 |
| 空表、未使用序列 | OK | 下一次仍返回序列起始值 |
| last_value=MAX(id)，is_called=false | BEHIND | 下一次大于 MAX(id) |
| last_value=MAX(id)，is_called=true，步长为 1 | OK | 无需调整 |
| 另一个表默认值引用相同序列 | SKIPPED | 不修改共享序列 |
| 降序或循环序列 | SKIPPED | 不修改 |
| 缺少表或序列读取权限 | ERROR | 其他表继续检查，单独处理权限 |

每次导入操作的完成条件应包含：报告无未处理异常，以及受影响业务的新增操作成功。数据库完整备份恢复应包含序列状态；仅导入表数据时仍要执行这项检查。
