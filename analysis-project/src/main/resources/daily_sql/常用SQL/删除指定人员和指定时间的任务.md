# 任务执行记录清理 SQL（GaussDB）

> 用途：按人员或完成时间清理历史任务明细，长期保留邮件通知及其统计关联记录。
>
> 说明：
> - 只删除终态记录，保留 `WAITING_METRICS`、`QUEUED`、`RUNNING` 等未完成任务。
> - 执行前先修改“参数区”中的用户 ID 和时间；先执行预览 SQL，确认数量后再执行对应删除 SQL。
> - 长任务清理会物理删除终态父执行、节点明细及原投递记录。独立历史表 `skill_flow_notification_history` 保留全部通知及统计字段。
> - **必须先部署并核对 `V20261112.1__flow_notification_history.sql`**。清理脚本检测归档保护是否已启用；通知尚在投递的长任务会被跳过。
> - 独立任务未接入这张历史表，有通知的独立任务执行和通知仍保留。
> - 不删除 `skill_flow`、`skill_flow_node`、`skill_job` 等任务定义。
> - 建议在暂停相关任务触发、通知发送和人工补发的维护窗口执行，避免清理期间并发写入。
> - 旧脚本已经删除的邮件记录不会通过本次修复恢复，需要从数据库备份恢复。

## 二、执行前预览（只读）

### 2.1 按人员预览长任务和独立任务

```sql
-- 替换：'用户ID'
SELECT '长任务' AS task_type, e.id, e.trigger_user_id AS user_id,
       e.status, e.created_at, e.completed_at,
       CASE WHEN EXISTS (
           SELECT 1 FROM skill_flow_notification n WHERE n.flow_execution_id = e.id
             AND n.status IN ('PENDING', 'SENDING')
       ) THEN '保留：通知仍在投递' ELSE '删除执行，保留独立通知历史' END AS cleanup_action
FROM skill_flow_execution e
WHERE e.trigger_user_id = '用户ID'
  AND e.status IN ('SUCCESS', 'PARTIAL_SUCCESS', 'FAILED', 'CANCELLED')
UNION ALL
SELECT '独立任务' AS task_type, e.id, j.created_by AS user_id,
       e.status, e.created_at, e.completed_at,
       CASE WHEN EXISTS (
           SELECT 1 FROM skill_job_notification n WHERE n.execution_id = e.id
       ) THEN '保留执行和通知' ELSE '删除执行' END AS cleanup_action
FROM skill_job_execution e
JOIN skill_job j ON j.id = e.job_id
WHERE j.created_by = '用户ID'
  AND e.status IN ('SUCCESS', 'FAILED', 'SKIPPED')
ORDER BY created_at;
```

### 2.2 按时间预览长任务和独立任务

`matched_execution_count` 是符合时间及状态条件的执行总数；`deletable_execution_count` 是可删除的执行数；`retained_execution_count` 是需保留的执行数（长任务通知仍在投递，或独立任务有通知记录）。

```sql
-- 替换：TIMESTAMP '2026-10-01 00:00:00'
SELECT '长任务' AS task_type, count(*) AS matched_execution_count,
       COUNT(CASE WHEN NOT EXISTS (
           SELECT 1 FROM skill_flow_notification n WHERE n.flow_execution_id = e.id
             AND n.status IN ('PENDING', 'SENDING')
       ) THEN 1 END) AS deletable_execution_count,
       COUNT(CASE WHEN EXISTS (
           SELECT 1 FROM skill_flow_notification n WHERE n.flow_execution_id = e.id
             AND n.status IN ('PENDING', 'SENDING')
       ) THEN 1 END) AS retained_execution_count
FROM skill_flow_execution e
WHERE e.status IN ('SUCCESS', 'PARTIAL_SUCCESS', 'FAILED', 'CANCELLED')
  AND e.completed_at < TIMESTAMP '2026-10-01 00:00:00'
UNION ALL
SELECT '独立任务' AS task_type, count(*) AS matched_execution_count,
       COUNT(CASE WHEN NOT EXISTS (
           SELECT 1 FROM skill_job_notification n WHERE n.execution_id = e.id
       ) THEN 1 END) AS deletable_execution_count,
       COUNT(CASE WHEN EXISTS (
           SELECT 1 FROM skill_job_notification n WHERE n.execution_id = e.id
       ) THEN 1 END) AS retained_execution_count
FROM skill_job_execution e
WHERE e.status IN ('SUCCESS', 'FAILED', 'SKIPPED')
  AND e.completed_at < TIMESTAMP '2026-10-01 00:00:00';
```

## 三、按人员删除长任务

```sql
BEGIN;
-- 维护窗口执行，防止选中清理目标后又写入通知。
LOCK TABLE skill_flow_execution, skill_flow_notification IN SHARE ROW EXCLUSIVE MODE;

DO $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM pg_trigger
        WHERE tgrelid = 'skill_flow_notification'::regclass
          AND tgname = 'trg_flow_notification_history_guard' AND tgenabled IN ('O', 'A')
    ) THEN
        RAISE EXCEPTION 'Apply V20261112.1__flow_notification_history.sql first';
    END IF;
END $$;

CREATE TEMP TABLE flow_cleanup_ids ON COMMIT DROP AS
SELECT e.id
FROM skill_flow_execution e
WHERE e.status IN ('SUCCESS', 'PARTIAL_SUCCESS', 'FAILED', 'CANCELLED')
  AND e.trigger_user_id = '用户ID'
  AND NOT EXISTS (
      SELECT 1 FROM skill_flow_notification n
      WHERE n.flow_execution_id = e.id AND n.status IN ('PENDING', 'SENDING')
  );
ALTER TABLE flow_cleanup_ids ADD PRIMARY KEY (id);

DELETE FROM skill_flow_node_attempt a
WHERE a.node_execution_id IN (
    SELECT n.id FROM skill_flow_node_execution n
    JOIN flow_cleanup_ids t ON t.id = n.flow_execution_id
);

DELETE FROM skill_flow_node_execution
WHERE flow_execution_id IN (SELECT id FROM flow_cleanup_ids);

-- 保护触发器验证每条投递记录已同步；失败则整次清理回滚。
DELETE FROM skill_flow_notification
WHERE flow_execution_id IN (SELECT id FROM flow_cleanup_ids);

DELETE FROM skill_flow_execution
WHERE id IN (SELECT id FROM flow_cleanup_ids);
COMMIT;
```

## 四、按人员删除独立任务

```sql
-- 替换：'用户ID'
-- 独立任务的执行记录没有 created_by，必须通过 skill_job.created_by 关联任务定义。
-- 保留全部通知；仅分批删除没有任何通知记录的独立任务执行记录
DO $$
DECLARE deleted_rows bigint;
BEGIN
  LOOP
    DELETE FROM skill_job_execution e
    WHERE e.id IN (
      SELECT e1.id
      FROM skill_job_execution e1
      JOIN skill_job j ON j.id = e1.job_id
      WHERE j.created_by = '用户ID'
        AND e1.status IN ('SUCCESS', 'FAILED', 'SKIPPED')
        AND NOT EXISTS (
          SELECT 1 FROM skill_job_notification n WHERE n.execution_id = e1.id
        )
      LIMIT 5000
    );
    GET DIAGNOSTICS deleted_rows = ROW_COUNT;
    RAISE NOTICE '独立任务执行删除 % 行', deleted_rows;
    EXIT WHEN deleted_rows = 0;
  END LOOP;
END $$;
```

## 六、按完成时间删除独立任务

```sql
-- 替换：TIMESTAMP '2026-10-01 00:00:00'
-- 保留全部通知及其关联执行记录
DO $$
DECLARE deleted_rows bigint;
BEGIN
  LOOP
    DELETE FROM skill_job_execution e
    WHERE e.id IN (
      SELECT e1.id FROM skill_job_execution e1
      WHERE e1.status IN ('SUCCESS', 'FAILED', 'SKIPPED')
        AND e1.completed_at < TIMESTAMP '2026-10-01 00:00:00'
        AND NOT EXISTS (
          SELECT 1 FROM skill_job_notification n WHERE n.execution_id = e1.id
        )
      LIMIT 5000
```
