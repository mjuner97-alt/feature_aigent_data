# 十、EvolutionOrchestratorImpl.trigger 完整框架

这是整个 MVP 的核心。

```java
@Service
public class EvolutionOrchestratorImpl
        implements EvolutionOrchestrator {

    private final SkillIndexRepository skillIndexRepository;
    private final SkillCandidateRepository candidateRepository;
    private final SkillJobRepository jobRepository;
    private final SkillFailureCaseRepository failureCaseRepository;

    private final SkillDistiller skillDistiller;
    private final SkillSaveTool skillSaveTool;

    private final SkillFormatValidator skillFormatValidator;
    private final GoldenEvaluationRunner goldenEvaluationRunner;

    private final GePaClient gePaClient;

    @Value("${harness.skills.evolution.strategy:llm}")
    private String defaultStrategy;

    @Override
    public String trigger(EvolutionTrigger trigger) {

        // 1. 获取当前 Skill
        SkillIndex skill =
                skillIndexRepository.findByName(trigger.skillName());

        if (skill == null) {
            throw new IllegalArgumentException(
                    "Skill not found: " + trigger.skillName());
        }

        // 2. GET_LOCK / concurrency control
        acquireEvolutionLock(trigger.skillName());

        try {

            // 3. 创建 Job
            String jobId = UUID.randomUUID().toString();

            SkillJob job = SkillJob.pending(
                    jobId,
                    trigger.skillName(),
                    resolveStrategy(trigger.strategy()),
                    trigger.triggerType(),
                    trigger.traceId(),
                    trigger.failureType(),
                    skill.getVersion()
            );

            jobRepository.insert(job);

            // 4. 持久化 failure exemplar
            persistFailureCase(trigger);

            // 5. 异步执行
            evolutionExecutor.submit(() ->
                    executeJob(jobId, trigger, skill));

            return jobId;

        } catch (Exception e) {
            releaseEvolutionLock(trigger.skillName());
            throw e;
        }
    }
}
```

# 十一、真正执行 Job：executeJob

```java
private void executeJob(
        String jobId,
        EvolutionTrigger trigger,
        SkillIndex skill) {

    try {

        jobRepository.markRunning(jobId);

        String strategy = resolveStrategy(trigger.strategy());

        SkillCandidate candidate;

        if ("llm".equals(strategy)) {

            candidate = executeLlmEvolution(
                    jobId,
                    trigger,
                    skill
            );

        } else if ("gepa".equals(strategy)) {

            candidate = executeGepaEvolution(
                    jobId,
                    trigger,
                    skill
            );

        } else {

            throw new IllegalArgumentException(
                    "Unsupported strategy: " + strategy);
        }

        // Candidate 已生成
        jobRepository.markEvaluating(jobId);

        evaluateCandidate(candidate, skill);

        jobRepository.markWaitingApproval(jobId);

    } catch (Exception e) {

        jobRepository.markFailed(
                jobId,
                truncate(e.getMessage())
        );

    } finally {

        releaseEvolutionLock(trigger.skillName());
    }
}
```

```java
private SkillCandidate executeGepaEvolution(
        String jobId,
        EvolutionTrigger trigger,
        SkillIndex skill) {

    candidateRepository.markPreparing(jobId);

    String oldBody = loadSkillBody(skill);

    GepaEvolutionRequest request =
            new GepaEvolutionRequest(
                    skill.getName(),
                    skill.getVersion(),
                    oldBody,
                    trigger.exemplarQuestion(),
                    trigger.failedTraceSnippet(),
                    trigger.failureType(),
                    "gepa"
            );

    candidateRepository.markOptimizing(jobId);

    GepaEvolutionResponse response =
            gePaClient.evolve(request);

    validateGepaResponse(response);

    SkillCandidate candidate =
            candidateRepository.createFromPatch(
                    jobId,
                    skill,
                    response.bodyPatch(),
                    response.baseVersion(),
                    response.mutationRegion(),
                    "gepa"
            );

    return candidate;
}
```

```java
public SkillSaveResult applyPatch(
        String skillName,
        int baseVersion,

    );

    // 6. saveSkill

            skillName,
            patchedBody,
            source,
            operator
    );
}
```

# 十八、applyBodyPatch 必须做什么

```java
private String applyBodyPatch(
        String body,
        SkillBodyPatch patch) {

    return switch (patch.operation()) {

        case REPLACE ->
            replaceExact(
                body,
                patch.oldText(),
                patch.newText()
            );

        case INSERT_AFTER ->
            insertAfter(
                body,
                patch.oldText(),
                patch.newText()
            );

        case DELETE ->
            deleteExact(
                body,
                patch.oldText()
            );
    };
}
```

如果：

```text
oldText
```

```text
0 次
```

或者：

```text
>1 次
```

都应该：


不能模糊替换。

```java
    EvaluationResult result =
            goldenEvaluationRunner.evaluateCandidate(
                    baselineSkill.getName(),
                    baselineSkill.getVersion(),
                    candidateBody
            );

    // 4. 保存分数
    candidateRepository.saveEvaluation(
            candidate.getCandidateId(),
            result
    );

    // 5. 判断是否进入人工审批
    if (isImproved(result)) {

        candidateRepository.markReviewRequired(
                candidate.getCandidateId());

    } else {

        candidateRepository.markRejected(
                candidate.getCandidateId(),
                "candidate score does not improve"
        );
    }
}
```

这里的 `evaluateCandidate(...)` 是你需要下一轮源码核对的另一个重点：如果当前 `GoldenEvaluationRunner` 没有这个签名，就做最小扩展，而不是重新造一套 evaluator。

# 二十四、MVP 的 improvement 判定

不再使用：

```text
+5%
```

而是：

```java
private boolean isImproved(EvaluationResult result) {

    return result.candidateScore()
            >= result.baselineMaxScore() + 1;
}
```

但是这里有一个数学表达上的细节：

如果 score 是：

```text
3 / 5
4 / 5
5 / 5
```

那么应该比较：

```text
candidatePassedCount
    >=
baselineMaxPassedCount + 1
```

而不是：

```text
0.8 >= 0.6 + 1
```

因此推荐实际字段：

```java
int baselinePassedCount;
int candidatePassedCount;
int baselineMaxPassedCount;
```

判定：

```java
candidatePassedCount >= baselineMaxPassedCount + 1
```

# 二十七、publishCandidate

```java
private void publishCandidate(
        SkillCandidate candidate) {

    SkillIndex current =
            skillIndexRepository.findByName(
                    candidate.getSkillName());

    // 二次乐观锁检查
    if (current.getVersion()
            != candidate.getBaseVersion()) {

        candidateRepository.markRejected(
                candidate.getCandidateId(),
                "skill version changed"
        );

        throw new ConcurrentSkillModificationException(...);
    }

    skillSaveTool.applyPatch(
            candidate.getSkillName(),
            candidate.getBaseVersion(),
            candidate.getBodyPatch(),
            SkillEntry.SOURCE_AUTO_SYNTHESIZED,
            "GEPA"
    );

    candidateRepository.markPublished(
            candidate.getCandidateId()
    );
}
```

这里实际上有两层保护：

```text
Candidate 创建
    ↓
base_version=3

评估期间
    ↓
有人把 Skill 改到 version=4

approve
    ↓
拒绝 publish
```

防止 GEPA 覆盖人工修改。

## 最后锁定一条非常关键的原则

这次 PoC **不要把 GEPA 理解成“让 Python 重新生成 SKILL.md”**。

真正的实现应该是：

```text
                 Java
                  │
       ┌──────────┴──────────┐
       │                     │
  Current Skill         Golden / Failure
       │                     │
       └──────────┬──────────┘
                  │
                  ▼
            Python GEPA
                  │
                  │ 只回答：
                  │ “哪一小段 body 应该怎么改？”
                  ▼
             body_patch
                  │
                  ▼
       Java SkillFormatValidator
                  │
                  ▼
       GoldenEvaluationRunner
                  │
                  ▼
             人工审批
                  │
                  ▼
        SkillSaveTool.applyPatch
                  │
           base_version 校验
                  │
                  ▼
          SkillSaveTool.saveSkill
                  │
             version + 1
                  │
             resetCounts
```

**Python 是 Evolution Engine，Java 才是 Skill 的 Source of Truth。**

对于你现在这个 `q2_1_by_dept_version_metrics`，GEPA 实际优化的对象就是 **R1/R2/R3/R4 四块 SKILL.md body**；`script_id + params_schema + Python script + frontmatter` 构成不可变边界。这样第一轮 PoC 的实验变量非常干净，也最容易在代码层验证“GEPA candidate 到底有没有比现有 LLM evolution 更好”。

下一轮代码核对时，最值得优先确认的是 **`GoldenEvaluationRunner` 当前如何启动 AgentScope runtime，以及 `SkillSaveTool` 当前是否能安全支持“只改 body、保留原 frontmatter、version 乐观锁”**；这两个点一旦对上，整个 MVP 基本就可以进入实际编码阶段。
