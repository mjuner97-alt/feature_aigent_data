# 优化 Supervisor 与 analyze_data 提示词 (双路径并列)

## Context

当前两个提示词文件结构混乱:
- **AGENTS.md**(Supervisor, 112 行)用「路由决策树 + 数值计算硬规则表(8 行触发词) + 注意事项 + 数据传递纪律」四处重复讲「何时派单 vs 直跑」。
- **analyze_data.md**(子 agent, 191 行)用「职责定位(2026/07/26 调整) + 必须执行计算 + 宽表指标加工通用流程 + 工作流程」四处重复讲「5 步流程」,且只详细讲了宽表路径,接口查询路径散落在「数据处理决策树」表里。
- 两个文档里的「触发词表」大量重叠,改一处要同步改另一处,容易漂移。

业务实际有 4 种场景(2 角色 × 2 路径):
- Supervisor 直跑宽表直查 / Supervisor 直跑接口查询
- analyze_data 走宽表直查做下钻 / analyze_data 走接口查询做下钻

目标:以「**宽表直查 / 接口查询**」两条路径并列为主轴重写两个文档,让每个角色一眼看明白「做什么决策 -> 走哪条路径 -> 用什么工具链」,去掉重复段落,顺便修两个 skill 与代码不一致的描述。

## 算术硬规则 (Supervisor 精简版)

- 任何加减乘除/百分比 -> 走 arith (哪怕两个数相减)
- 显而易见的比较 ("23.1 > 13.1") -> 自己判断 (不是算术)
- 均值/标准差/分位数/同比/环比/排名/相关/分组聚合 等统计计算 -> 派 analyze_data
- 详细统计触发词表见 analyze_data 提示词

## 数据传递纪律
- 数字必须与工具返回完全一致, 不得编造
- N 条数据要全部涵盖
- CSV 路径只能从 wide_table_query/clickhouse_query 返回的 📦 CSV 路径: 行复制
  (带 <userId>/<taskId> 前缀, 改写会被 ArtifactAccessMiddleware 越权拦截)

## 注意事项
- 简单查数由 Supervisor 直跑, 不派 analyze_data
- 复杂分析派 analyze_data, 不要先派单取数再算 (analyze_data 内部会自行查询+计算)
- 闲聊直接回答, 不需要工具
- 中文回复, 当前年份 2026, 质量分越高表示质量越差
