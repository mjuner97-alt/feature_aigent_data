# 宽表指标加工方案

> 业务人员通过写 skill 文件,让 agent 自动查询 GaussDB 宽表并加工 Q2-1 打分指标。
> 本文档面向业务人员与运维,描述整体架构、关键文件、工作流和验证方法。

## 1. 背景与目标

### 业务需求

业务人员希望用对话方式查询宽表 `productsgaussdb.dsqa_dwd_req_item_app_portrait_wide_inf` 的 Q2-1 打分指标:

- **4 个公共指标**:
  1. Q2-1 完成数 = `score_status_2_1 = '已完成'` 的行数
  2. Q2-1 达标数 = `standard_is_2_1 = '已达标'` 的行数
  3. 完成率 = 完成数 / 全量
  4. 达标率 = 达标数 / 完成数 (分母是完成数,不是全量)

- **3 个查询维度**:
  - 部门维度(`dev_dept`): 例 "杭州二部8月版Q2-1的完成率是多少?"
  - 产品线维度(`product_line`): 例 "个贷产品线8月版Q2-1的完成率是多少?"
  - 统计组维度(`stat_group`): 例 "信贷应用开发组8月版Q2-1的完成率是多少?"

### 设计目标

1. **业务自治**:业务人员通过写 skill .md 文件就能新增/修改指标,不需要改 Java 代码
2. **复用现有 agent**:走现有 `analyze_data` 子 agent + `router_tool` + `python_exec` + `arith` 工具链
3. **真实 DB 查询**:连真实 GaussDB,不走 mock 数据
4. **计算可验证**:python_exec 算一遍,arith 工具用 BigDecimal 复算一遍,两路径结果一致才回复用户

## 2. 架构总览

```
用户问"杭州二部8月版Q2-1完成率是多少?"
    ↓
Supervisor (AGENTS.md 路由) -> agent_spawn(analyze_data)
    ↓
analyze_data 读 skill: wide_table_q2_1_metrics
    (skill 提供: 表名 + 字段映射 + 4 个公式 + 完整 python_exec 代码模板)
    ↓
Step 1: analyze_data 调 router_tool({toolId:"wide_table_query",
                                      table:"productsgaussdb.dsqa_dwd_req_item_app_portrait_wide_inf",
                                      fields:[8 个字段],
                                      filters:{"dev_dept":"杭州开发二部",
                                               "version_plan":"2026年8月份版本"}})
        -> 工具返回 CSV artifact 路径 + 前 10 行预览 (不计算任何指标)
    ↓
Step 2: analyze_data 调 python_exec(pandas 代码)
        - pd.read_csv(<CSV 路径>)
        - 算 4 个指标: completion_count / standard_count / total / rates
        -> 返回数字
    ↓
Step 3: analyze_data 调 arith(op="pct", numbers=[完成数, 全量]) 复算 (BigDecimal 双保险)
    ↓
Step 4: 回复用户 (中文 + 4 个数字 + 业务解读)
```

### 三层职责划分

| 层 | 职责 | 实现位置 |
|---|---|---|
| **Java 工具层** | 通用 SELECT 查询,落 CSV artifact | `WideTableMetricsTool.java` |
| **Skill 层** | 每张表一个 skill,定义字段映射+公式+python_exec 模板 | `workspace/skills/wide_table_q2_1_metrics/SKILL.md` |
| **Agent 层** | 读 skill,组合 wide_table_query + python_exec + arith | `analyze_data` 子 agent(已有,不改) |

**核心原则**:Java 工具只做通用 SELECT,不写任何业务指标公式。所有业务逻辑(字段映射、公式、计算模板)都在 skill 里,业务人员改 skill 不需要重新编译 Java。

## 3. 关键设计决策

### 3.1 WideTableMetricsTool 是通用 SELECT,不算指标

工具只做一件事:`SELECT <fields> FROM <table> WHERE <filters> LIMIT <n>` -> CSV artifact + 预览。

- 不在 Java 里写任何业务指标公式
- 不在 SQL 里做 GROUP BY / COUNT / SUM(这些走 python_exec)
- 表名/字段名/筛选字段都由调用方(skill 模板填充)传入

工具签名:

```
wide_table_query(
  table: "productsgaussdb.dsqa_dwd_req_item_app_portrait_wide_inf",  # schema.table 全限定
  fields: ["projectzh_no","dev_dept","score_status_2_1",...],         # SELECT 字段列表
  filters: '{"dev_dept":"杭州开发二部","version_plan":"2026年8月份版本"}',  # WHERE 等值条件 JSON
  limit: 10000                                                         # 行数上限
)
```

### 3.2 SQL 注入防护(两层校验)

| 校验项 | 方式 |
|---|---|
| 表名 | 正则 `^[a-zA-Z_][a-zA-Z0-9_]*\.[a-zA-Z_][a-zA-Z0-9_]*$` (schema.table 格式) |
| 字段名 | 查 `information_schema.columns` 拿真实列名集合,只接受集合内的字段 |
| filter 列名 | 同上,从 information_schema 校验 |
| filter 值 | `PreparedStatement.setXxx()` 参数化绑定 |
| LIMIT | Java 端 clamp 到 [1, 10000] |
| 只读 | Connection 默认只读,不调用任何 DDL/DML |

### 3.3 CSV artifact 输出

- 路径:`<workspace_root>/artifacts/<userId>/<taskId>/wtq-<uuid>.csv`
- 走现有 `ArtifactRoot` / `ArtifactAccessMiddleware` 的越权防护
- 返回内容:markdown 表(前 10 行预览)+ `📦 CSV 路径: <path>` 行

### 3.4 业务 skill = 一张表一个 skill

Skill 不只是"映射说明",而是包含**可执行的 python_exec 代码模板**。Agent 读 skill 后:
- 知道调 wide_table_query 传什么 table/fields/filters
- 知道拿到 CSV 后跑哪段 pandas 代码算指标
- 知道最后调 arith 复算

**后续加新表(比如另一张宽表的 Q3 指标)= 加新 skill 文件,不改 Java**。

### 3.5 python_exec 优先,arith 复算

- 主计算路径:`python_exec` + pandas(`df['col']=='已完成').sum()` 等向量化操作)
- 复算路径:`arith(op="pct", numbers=[completion_count, total])` 用 BigDecimal 算百分比
- 两条路径结果应该一致,agent 在回复里用 arith 的结果(BigDecimal 精度)

## 7. 风险与注意事项

### 7.1 OpenGauss 认证协议

opengauss-jdbc 5.1.0 已验证可连(Java 测试通过)。E2E 校验脚本用 JPype + JDBC 需要 JVM,部署环境得有 JDK 21。

### 7.2 currentSchema 参数

OpenGauss 5.0 是否支持 `currentSchema=productsgaussdb` URL 参数需验证。不支持的话改成 SQL 里全限定 `productsgaussdb.dsqa_dwd_req_item_app_portrait_wide_inf`。

### 7.3 CSV artifact 跨用户隔离

工具落 CSV 时要带 `<userId>/<taskId>` 前缀,走 `ArtifactAccessMiddleware` 已有的越权防护。

### 7.4 LLM 越权直连 DB

`analyze_data` spec 要硬约束 Q2-1 类问题只能走 `wide_table_query + python_exec`。容器内没装 psycopg2/py-opengauss,LLM 即使想直连也会失败,但 spec 仍要明确禁止。

### 7.5 information_schema 查询权限

`remote_app` 用户需要:
- 对 `information_schema.columns` 有 SELECT 权限
- 对 `productsgaussdb` schema 有 USAGE 权限

如权限缺失,DBA 执行:
```sql
GRANT USAGE ON SCHEMA productsgaussdb TO remote_app;
GRANT SELECT ON productsgaussdb.dsqa_dwd_req_item_app_portrait_wide_inf TO remote_app;
-- information_schema 默认 PUBLIC 可读,通常不需要额外授权
```

### 7.6 宽表字段含 SQL 保留字

DDL 里 `"app"` 是 SQL 保留字,被双引号包了。拼 SELECT 时所有字段名都要双引号包裹,与 DDL 一致。
