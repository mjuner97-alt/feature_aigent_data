# 检索关键词与维度值冲突治理方案

> 2026/10/27 · 关联文档：docs/202610/skill-retrieval-logic.md（检索侧现状 §2.2/§7/§8/§9）、
> docs/202610/维度值台账真值校验方案.md（维度侧真值机制）、
> docs/202610/版本季度部门口语值处理方案.md（嵌入 alias 抑制机制A 先例）

## 1. 背景与问题

skill 检索（`skill_routing_metadata` 四层词条 + 旁路词）与维度提取（`dimension_alias`
口语别名 + 台账真值字典）是**两套互不感知的词表，跑在同一段问题文本上**。
当同一个词既是 skill 检索词条、又是 产品线/统计组/应用 的口语值（或其子串）时，双向串扰：

- **检索侧误路由（主害，本文要解的 bug）**：问题里只是把口语词当**维度修饰语**
  （"车贷的达标率"里"车贷"指个贷汽车场景建设组），却因该词命中某 skill 词条，
  把不该入围的 skill 拉进候选池甚至置顶 —— 选错 skill，或本该走通用 metrics skill
  的走了专项 skill。
- **contains 语义加剧**：`SkillTermMatcher.matches` = 正则 `find()` / 字面 contains
  （skill-retrieval-logic.md §7.4），短词条会在长维度值内部误中：
  词条"财政"命中"代理财政业务开发组"、词条"交易"命中"交易报价组"、词条"同业"命中"同业客户组"。
- **维度提取侧基本免疫**：嵌入 alias 抑制（机制A，2026-10-26 E2E 实证）、span 屏蔽剥离
  （§13.4）、BARE_APP 裸码让位 aliasHit（2026-10-27 修复）已经解决"检索词被维度误收"
  的反向问题，**本文不动维度侧**。

词条由管理员随时可配（PUT /api/skill-routing），当前 active 的 15 个 skill 词条
（问题/缺陷/Q1/达标率/卡口/准入/遗留/告警/质量/指标…）暂无撞车，但**任何新 skill 配了
GBC/同业/财政/社保 这类词即触发**，属于配置即爆的系统性缺口，需要机制化治理而非个案修补。

## 2. 现状机制回顾（两侧行为）

### 2.1 检索侧（skill-retrieval-logic.md §9 现行语义）

| 环节 | 行为 | 对碰撞的敏感度 |
|---|---|---|
| 显式点名 | `containsName`（skill 名 contains）| 低（skill 名是长串，撞不上口语词）|
| 层级轨 | AND：每个配置层都须有命中 | **天然缓解**：碰撞词只是一层，其他层不中即出局 |
| 存量轨（三层全空） | 叶层词条 1 词命中即入围（2000/词 cap 4000）| **最大受害面**：单个碰撞词即入池 |
| 排序 | depth → bestGlobalRank（碰撞词位次参与）| 碰撞词会把假候选排到真候选前 |
| 截断两档 | 榜首 partial 与否决定 maxVisible / fallback | 碰撞词命中让 `partiallyMatched=false`，截断收紧，挤掉真候选 |
| 旁路词 | 任一命中 → skill 检索整体置空 | 碰撞词配进 `skill_bypass_keyword` → 整轮误杀 |

### 2.2 维度侧（现成机制，本方案只读不改）

- `dimension_alias`：alias（口语）→ standardName，按类型 TEAM/PRODUCT_LINE/APPLICATION/…
- 台账真值字典：`PersonLedgerRepository.dimensionTruthDictionary(统计组/产品线/应用)`
- 嵌入抑制：alias 命中 span 与组名 token 互不包含才抑制（机制A）；alias 精确命中
  压过启发式正则（BARE_APP 让位）。
- 消费方 `DirectSkillExecutor.plan()`：selector 选池在先、维度提取在后，两者目前
  只共享问题文本，不共享任何命中信息。

## 3. 冲突矩阵（本机 DB 实测 2026/10/27）

维度口语词中"高频、超短、易被选作词条"的存量（dimension_alias，enabled 行）：

| 口语词 | 维度归属 | 撞车后果示例（若配为词条）|
|---|---|---|
| GBC | TEAM→杭州服务支持部GBC场景创新组 **且** PL→民生政务 | 问"GBC的缺陷密度"被拉去 GBC 专项 skill |
| 军队 | TEAM→特种业务组 **且** PL→企业资金管理系统 | 一词双维，检索再劫持即三方混战 |
| 财政 | TEAM→代理财政业务开发组 **且** PL→代理财政 | contains："代理财政业务开发组"内也误中 |
| 同业 / 分行 / 平台组 / 渠道组 / 中台组 / 量化组 | TEAM 口语 | 超短词，任何含该字面的问题全误中 |
| 个贷前端 | TEAM→个贷对客渠道组 **且** APP→F-WAPB-LOAN | — |
| 国库 / 社保 / 银商 / 银期 / 银证 / 银银 | APP 口语 | "社保的达标率"撞上社保类 skill 词条 |
| 车贷 / 房贷 / 汽车贷 / 个贷消费组 | TEAM 口语 | 本 session E2E 主角的词，最易被配成词条 |
| 交易下单 / 交易管理 / 对客 / 询价 | PL 口语 | contains："交易报价组"内误中"交易" |

**范围拍板（§6-P1）**：碰撞词表取 **alias 口语列**（不含 standardName）——
问题提到标准组名（"个贷汽车场景建设组的达标率"）把组专项 skill 路由进来是**合理行为**，
不算撞车；口语才是歧义源。

## 4. 方案候选

### 方案A：配置期冲突审计（治理面，无运行期行为变化）

扩展 Skill↔Skill/Skill↔Tool 重叠审计的既有哲学（**先审计可见，再谈阻断**）：

- 新增 `SkillDimensionCollisionService`：碰撞集 = dimension_alias 口语列（enabled）
  ∪ 台账真值字典三列 distinct 值（仅口语判断用 alias 列，真值字典仅供审计展示对照）。
- 等级：**HIGH** = 词条 normalize 后**完全等于**某口语词；**MED** = 词条是某口语词的
  子串（contains 误中面）；正则型词条（可编译为正则，§6 已知限制）标 **SKIP**
  （无法静态判定撞了哪个词）。
- 产出：① 启动审计日志（复用 SkillRoutingStartupAudit 挂点，只告警不阻断）；
  ② PUT /api/skill-routing 保存时实时计算，响应体带 `dimensionCollisions` 字段；
  ③ skill 配置页徽标提示（可后置）。
- fail-open：词表读失败 → 跳过审计，不阻塞保存/启动。

### 方案B：运行期检索守卫 —— 碰撞词无佐证不入围（推荐与 A 组合）

对齐 Skill↔Tool 重叠 S1"无佐证不出记录"的换轴哲学，在 selector 匹配层加守卫：

- `SkillCandidateSelector` 注入碰撞词快照（Supplier，TTL 30s，同 AliasResolver 风格）。
- 词条命中后加一道判定：**该 skill 的全部命中词都是碰撞词 → 视为未命中**
  - 存量轨：keywordHits 归零 → 出局（1 词碰撞即入围的受害面被完全封死）；
  - 层级轨：该层命中词全为碰撞词 → 该层按未命中计，AND 自然出局；
  - 混合命中（碰撞词 + 至少 1 个非碰撞词）：放行，碰撞词照常计分 —— **有佐证不误杀**。
- 正则型词条不参与碰撞判定（无法判定命中文本来源），行为与现状一致（§6 限制延续）。
- **显式点名不受守卫影响**（containsName skillName 在守卫之前，保持恒置顶）。

### 方案C：span 消费互斥（暂不推荐）

维度提取把 alias 命中 span 传给 selector，词条命中位置落在维度 span 内不计。
语义最精确，但要打通两套系统的时序与数据结构（selector 在 LLM 前跑、维度提取在
DirectSkillExecutor.plan 里跑，存在跨阶段依赖），改动大、耦合重。留作后续演进。

### 方案D：维度提取豁免检索词（否决）

反向让位（被检索消费的词不做维度解释）会破坏机制A/台账真值校验已验证的优先级链，
且"车贷的达标率"里车贷**必须**进维度 —— 不做。

## 5. 推荐组合与预期效果

**A + B**：A 让管理员配词条时当场看见"这词是维度口语，撞了谁"，把冲突消在源头；
B 兜底存量/漏配场景，语义是保守的（只有"全部命中词皆碰撞"才出局，混合命中放行），
fail-open（词表读失败守卫自动失效）。

预期：
- "车贷的达标率"（skill 词条含"车贷"）：守卫后该 skill 出局，回落到按"达标率"入围的
  通用 metrics skill，维度提取照常出 groupName=个贷汽车场景建设组 + Q8 部门反填；
- "车贷、房贷的准入达标率"：若 skill 词条是"准入/达标率"（非碰撞词），照常入围，
  行为不变。

## 6. 拍板点

| # | 问题 | 建议 |
|---|---|---|
| P1 | 碰撞词表范围：仅 alias 口语列，还是含 standardName/台账真值？ | **仅口语列**；标准名命中属合理路由 |
| P2 | 维度类型范围：PRODUCT_LINE/TEAM/APPLICATION 三类，还是全类型？ | **三类**（本文 bug 面）+ 部门/杭研可后扩 |
| P3 | 守卫力度：全部命中词皆碰撞才出局（保守），还是碰撞词不计分但其余词可独立入围？ | **全部碰撞才出局**（混合放行），误杀面最小 |
| P4 | 层级轨是否同受守卫约束？ | 是：碰撞层按未命中计，AND 自然出局 |
| P5 | 旁路词撞口语词是否豁免旁路？ | 是（F4）：旁路命中词为碰撞词 → 不旁路 |
| P6 | 配置端是否硬禁保存？ | 否，仅告警 + 响应 warning 字段；硬禁待运行证据 |
| P7 | 真值字典（台账 distinct 值）是否参与运行期守卫？ | 否，仅审计展示（真值是标准名，撞上属合理路由，同 P1）|

## 7. 改动清单（拍板后实施）

1. **新增** `SkillDimensionCollisionService`（v2/skills）：
   Supplier 拼装 collisionSet（dimension_alias enabled 口语列 × 三类 + 归一化去重），
   TTL 30s 缓存 + 失败 fail-open（空集 = 守卫自动关闭）；`collides(normalizedTerm)`
   判定含子串方向（P3 语义在 selector 层实现，本服务只供词表）。
2. **SkillCandidateSelector**：构造器加 collisionSupplier（可空 = 关闭，兼容既有单测）；
   `collectMatched` 后按 P3/P4 语义过滤；日志补碰撞出局原因。
3. **SkillBypassKeywordService**：bypassed() 命中词逐个过碰撞判定（P5）。
4. **SkillRoutingMetadataAdminService / Controller**：保存响应附 `dimensionCollisions`
   （方案A ②）；启动审计挂日志（方案A ①）。
5. **V2SkillConfig 装配**：bean 注入（alias 仓储 + PersonLedgerRepository 来源）。
6. 前端 skill 配置页徽标（可拆二期）。

## 8. 测试要点

- **Selector 单测**：① 存量轨单碰撞词命中 → 出局；② 碰撞词 + 非碰撞词混合 → 入围且计分；
  ③ 层级轨 L2 全碰撞 → AND 出局；④ 显式点名 + 碰撞 → 恒置顶不守卫；⑤ collisionSupplier
  抛异常/空集 → 行为与现状完全一致（fail-open）；⑥ 正则词条不判碰撞。
- **Bypass 单测**：碰撞词旁路命中 + 无显式点名 → 不旁路；非碰撞词照常旁路。
- **审计/保存单测**：HIGH/MED/SKIP 三级划分；保存响应 warning 字段。
- **E2E（内网）**：临时给某测试 skill 配词条"车贷" → "车贷的达标率"回落通用 skill 且
  维度 groupName 正常；换"个贷汽车场景建设组"（标准名）→ 专项 skill 照常入围。
- 回归：skill-retrieval-logic.md §9 全部既有语义（AND/双轨/保底注入/两档截断）单测
  全绿（现 572+ 用例不破）。

## 9. 兼容性与回滚

- 碰撞词快照为空（alias 表空/读失败）= 守卫天然关闭，等价现状，无开关也能滚；
- 预留 `skill.collision-guard.enabled`（默认 true）便于生产一键回退；
- 不改 SQL 表结构、不改维度侧任何代码，回滚 = 关开关。
