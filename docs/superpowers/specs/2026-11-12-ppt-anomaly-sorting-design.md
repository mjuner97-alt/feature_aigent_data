# PPT 异常数据分拣工具设计文档

**文档日期**：2026-11-12  
**文档状态**：需求设计阶段  
**适用范围**：固定模板的多页 PPT，处理文字框和表格内容

## 1. 项目背景

业务人员提供一份多页 PPT，希望系统识别其中的异常数据，并按照关键词与部门的对应关系，把异常内容分拣给对应部门。

PPT 中的页面和区域用途并不完全相同。有些区域可以判断是否存在异常，有些区域只能提供部门信息，有些区域属于说明或汇总内容，不能参与异常判断。因此，系统需要同时区分页面用途和区域用途。

## 2. 项目目标

系统需要完成以下工作：

1. 读取固定模板 PPT 中的文字框和表格。
2. 按页面和区域配置，确定哪些内容可以参与异常判断，哪些内容可以用于部门分拣。
3. 将有效内容切分成句子、段落、项目条目或表格行。
4. 根据异常触发词识别异常内容。
5. 根据否定词、消除词和前置字符窗口处理语义反转。
6. 对双重否定、规则冲突和无法确定的内容标记为待人工确认。
7. 使用已有的关键词与部门映射表完成部门分拣。
8. 一条内容涉及多个部门时，同时分发给多个部门。
9. 生成总结果、部门结果、人工确认清单和处理日志。
10. 保留页码、区域、表格行号和原文，保证结果可追溯。

## 3. 已确定的前提

1. PPT 模板固定，页面结构相对稳定。
2. 关键词与部门对应关系已经提供，不在本工具中重新推断。
3. 多部门命中时采用复制分发方式。
4. 当前只处理文字框和表格。
5. 当前不识别图片、图标和图片中的文字。
6. 规则使用确定性代码执行，不依赖大模型语义推理。
7. 业务规则放在外部配置中，规则调整不需要修改程序。

## 4. 业务人员需要提供的内容

业务人员首次提供一份 PPT 时，需要同时补充以下信息。后续同类 PPT 可以复用已经确认的规则。

### 4.1 原始文件和目标

- 原始 `.pptx` 文件
- 本次要找出的异常类型
- 需要分拣的结果范围
- 结果对应的部门范围

### 4.2 页面和区域用途

逐页标明以下内容：

- 页面能否用于判断异常
- 页面能否用于部门分拣
- 页面是否完全跳过
- 页面中哪些文本框、表格或表格行有效
- 哪些区域属于说明、备注或汇总

如果同一页的不同区域用途不同，需要标出具体区域。区域可以按文本框、表格、行、列或固定位置描述。

### 4.3 异常判断说明

- 什么情况算异常
- 哪些词表示异常
- 哪些词表示异常已经消除
- 哪些内容虽然包含异常词，但实际不需要分拣
- 哪些情况无法确定，需要人工确认

### 4.4 内容切分方式

- 文本框按句子、段落还是项目符号切分
- 表格按行还是按单元格切分
- 标题是否参与判断
- 备注是否参与判断
- 合计行是否参与判断

### 4.5 输出要求

- 是否生成一份总汇总表
- 是否生成每个部门的单独文件
- 是否生成待人工确认清单
- 每条结果需要保留哪些字段
- 是否需要保留原文和来源位置

## 5. 页面和区域模型

### 5.1 页面级属性

每一页至少配置三个属性：

| 属性 | 含义 |
|---|---|
| `judgment_enabled` | 页面内容是否可以用于判断异常 |
| `routing_enabled` | 页面内容是否可以用于部门分拣 |
| `excluded` | 页面是否完全跳过 |

页面级属性解决整页用途明确的情况。页面中存在混合用途时，使用区域级配置覆盖页面默认值。

### 5.2 区域级划分

固定模板建议将页面拆分为以下区域块：

| 区域块 | 典型内容 | 异常判断 | 部门分拣 | 默认处理 |
|---|---|---:|---:|---|
| 页面识别区 | 页面标题、页眉、页面编号 | 否 | 否 | 只用于识别页面类型 |
| 异常判断区 | 指标、问题描述、结论、状态 | 是 | 视情况 | 进入异常判断 |
| 部门分拣区 | 部门名称、部门编号、关键词 | 否 | 是 | 进入部门匹配 |
| 关联信息区 | 项目名、指标名、编号 | 否 | 否 | 用于对应异常内容和部门 |
| 说明备注区 | 口径说明、备注、解释文字 | 通常否 | 通常否 | 默认跳过 |
| 合计汇总区 | 合计、总计、整体情况 | 视规则 | 视规则 | 单独配置 |
| 待确认区 | 格式特殊或含义不清的内容 | 否 | 否 | 进入人工确认 |

### 5.3 区域之间的关联

优先使用以下顺序关联异常内容和部门信息：

1. 同一表格行
2. 同一文本条目
3. 同一页面内的固定关联区域
4. 通过固定编号、项目名称或指标名称关联

没有明确关联依据时，不自动把不同页面的信息拼接在一起。该内容进入待人工确认清单。

## 6. 页面类型识别方案

由于模板固定，第一版不需要建立复杂的通用页面分类模型。页面类型通过固定规则识别。

识别依据包括：

- 页码范围
- 页面标题
- 固定页眉或页脚
- 表格表头
- 文本框位置
- 表格位置和大小
- 页面中是否存在特定字段

每种页面类型在配置中维护以下内容：

- 页面类型名称
- 识别条件
- 异常判断区域
- 部门分拣区域
- 排除区域
- 区域读取顺序
- 匹配优先级

多个页面类型同时匹配时，使用优先级最高的配置。没有匹配到页面类型时，整页进入待人工确认，不直接参与自动分拣。

## 7. 内容提取和切分

### 7.1 文字框

按照业务确认的粒度提取：

- 段落
- 项目符号
- 换行内容
- 句子

每条内容保留原文，不合并来自不同区域的文字。

### 7.2 表格

默认以表格行为一个判断单元。每一行保留：

- 页码
- 表格编号
- 行号
- 各列原文
- 拼接后的判断文本

如果某些列只用于部门分拣，某些列只用于异常判断，需要在区域配置中明确列的用途。

### 7.3 图片和图标

图片和图标不参与自动判断。系统只记录：

- 所在页码
- 所在位置
- 对象类型
- 未解析状态

如果业务认为图片中的文字很重要，需要人工补充文字内容，或者后续增加 OCR 能力。

## 8. 异常判断规则

### 8.1 触发词

触发词用于标记潜在异常，例如“不达标”“超标”“逾期”“负增长”“异常”。

触发词需要支持：

- 启用或停用
- 优先级
- 完整词组
- 备注说明

较长、更具体的词优先于较短的词。例如配置了“连续下降”和“下降”时，优先匹配“连续下降”。

### 8.2 否定和消除词

否定或消除词用于取消异常判断，例如“无新增”“未发现”“没有”“已消除”“不再”。

每个否定词需要明确：

- 作用范围
- 是否直接取消异常
- 是否直接进入人工确认
- 是否有特殊例外

### 8.3 前置窗口

对每个触发词，检查其前方固定数量的字符。窗口长度放在配置中，默认值建议为 8，可根据业务规则调整。

例如：

```text
无新增不达标
      触发词
```

“无新增”出现在触发词前方窗口内时，该条内容可以判定为非异常。

### 8.4 双重否定和冲突

以下情况默认进入人工确认：

- 同一窗口出现两个或以上否定词
- 同一条目同时出现相互冲突的判定
- 触发词和否定词存在重叠
- 规则无法确定否定词作用范围
- 句子中出现业务未定义的转折表达

完整触发词优先于单独的否定词。例如业务需要识别“未达标”，应直接把“未达标”配置为一个完整触发词。

## 9. 部门分拣规则

部门关键词与部门的映射表作为外部配置读取。

分拣规则如下：

1. 只有判定为异常的内容进入部门匹配。
2. 关键词采用配置表中的对应关系。
3. 一个关键词对应多个部门时，全部保留。
4. 一条内容命中多个部门时，复制到多个部门结果中。
5. 同一部门命中多个关键词时，合并关键词记录，不重复生成同一条结果。
6. 没有命中部门的异常进入未归属异常清单。

## 10. 输出设计

建议生成以下结果：

1. 异常汇总表
2. 各部门异常结果文件
3. 待人工确认清单
4. 未归属异常清单
5. 页面排除记录
6. 解析异常记录
7. 本次运行信息

每条异常至少保留以下字段：

| 字段 | 含义 |
|---|---|
| 来源文件 | 原始 PPT 文件名 |
| 来源页码 | PPT 页码 |
| 页面类型 | 页面所属模板类型 |
| 区域名称 | 异常内容所在区域 |
| 表格编号 | 来源表格 |
| 表格行号 | 来源行号 |
| 原文 | 原始条目内容 |
| 异常词 | 命中的触发词 |
| 否定词 | 命中的否定或消除词 |
| 判定结果 | 异常、非异常或人工确认 |
| 部门 | 分拣目标部门 |
| 部门关键词 | 命中的关键词 |
| 复核原因 | 需要人工确认时填写 |
| 规则版本 | 使用的规则版本 |

## 11. 人工确认机制

人工确认只处理自动规则无法安全判断的内容，主要包括：

- 未识别的页面类型
- 未识别的区域结构
- 双重否定
- 触发词和否定词冲突
- 未归属部门
- 图片或图标中的文字
- 表格结构异常
- 文字与部门信息无法关联

人工确认后的结果需要沉淀为以下内容之一：

- 新的页面类型配置
- 新的区域配置
- 新的异常词
- 新的否定词
- 新的部门关键词
- 新的特殊处理规则

这样同类问题下次可以自动处理。

## 12. 配置和版本管理

业务规则全部放在外部配置中，包括：

- 页面类型
- 页面区域
- 排除页面
- 异常词
- 否定词
- 否定窗口
- 关键词与部门映射
- 输出设置

每次运行记录：

- PPT 文件哈希
- 规则文件版本
- 配置文件哈希
- 运行时间
- 处理页数
- 异常条数
- 人工确认条数
- 解析异常条数

同一个 PPT 使用同一版本配置时，应得到相同结果。

## 13. 实施阶段

### 阶段一，分析样本 PPT

- 逐页建立页面清单
- 划分页面区域
- 确认异常判断区
- 确认部门分拣区
- 确认跳过区域
- 确认内容切分方式

### 阶段二，建立第一版规则

- 固定页面类型
- 固定区域位置
- 配置页面排除规则
- 配置异常词和否定词
- 配置否定窗口
- 接入部门映射表
- 固定输出格式

### 阶段三，样本验证

验证以下内容：

- 应该分拣的异常是否全部识别
- 不应该分拣的内容是否被排除
- 只用于部门分拣的区域是否没有参与异常判断
- 多部门内容是否同时分发
- 备注和合计内容是否按规则处理
- 来源页码和原文是否准确

### 阶段四，固定为自动化流程

沉淀以下内容：

- 页面模板配置
- 区域配置
- 异常判断规则
- 部门映射配置
- 待人工确认规则
- 回归测试样本
- 固定输出模板

## 14. 验收标准

系统达到以下条件后，才适合进入日常使用：

1. 固定模板页面能够稳定识别。
2. 异常判断区域和部门分拣区域不会混用。
3. 页面排除规则能够稳定执行。
4. 表格行能够按照业务要求切分。
5. 否定语境能够按照配置处理。
6. 双重否定和无法判断内容能够进入人工确认。
7. 多部门内容能够同时分拣。
8. 每条结果都能追溯到原始页码和原文。
9. 规则修改只需要修改配置文件。
10. 同一输入和同一规则版本能够重复得到相同结果。

## 15. 当前仍需确认的内容

在进入实现前，还需要从样本 PPT 中确认以下细节：

1. 每种页面类型的实际页码、标题和区域位置。
2. 哪些表格列参与异常判断，哪些列只用于部门分拣。
3. 合计行、备注行和汇总行的具体处理方式。
4. 异常词、否定词和否定窗口的最终清单。
5. 没有命中部门的异常如何处理。
6. 异常信息和部门信息不在同一行时的固定关联方式。
7. 最终输出采用一个总文件、多个部门文件，还是两种都生成。
